# 安全加固

使用此技能开展务实的应用安全工作，产出按优先级排序的修复项和剩余风险说明。不要将其变成流于形式的合规演练。

## 工作流程

1. **梳理攻击面**
   - 识别身份验证/会话模型、角色/权限、API 路由、webhook、文件上传/下载、提供商调用、数据库访问、后台任务、管理工具、客户端存储和部署配置。
   - 定位密钥、环境变量、令牌存储、日志记录、依赖项入口点和网络出口。

2. **制定按风险排序的计划**
   - 优先处理可利用的攻击路径，而非理论性问题。
   - 将风险分为发布前必须修复、应尽快修复以及已接受/延期处理。
   - 除非漏洞修复需要改变行为，否则应保持产品行为不变。

3. **加固最高风险路径**
   - 在服务器/操作边界添加或收紧授权检查。
   - 在外部/API/提供商边界验证不可信输入。
   - 保护密钥并对敏感日志进行脱敏。
   - 在适当位置添加速率限制、来源控制、CSRF/CORS 策略、SSRF 防护、上传约束和安全标头。
   - 审计依赖项和软件包脚本，检查已知风险及升级路径。

4. **验证修复**
   - 针对权限绕过、输入拒绝、危险 URL/文件场景、身份验证/会话边界情况以及安全的错误/日志载荷添加针对性测试。
   - 运行仓库生态系统中可用的依赖项/安全工具。
   - 记录无法验证的内容。

5. **报告剩余风险**
   - 列出已修复的问题及相关证据。
   - 列出剩余风险，包括严重程度、利用方式概述和建议的后续措施。
   - 避免声称应用是“安全的”；应说明已审查的范围。

## 质量标准

- 每个重要的服务器端变更操作都有明确的授权机制。
- 密钥不会暴露在日志、客户端包、测试夹具或生成的产物中。
- 外部输入在产生副作用之前经过验证。
- 危险的网络/文件操作具备允许列表、大小限制和协议检查。
- 安全测试至少能够验证最主要的绕过/失败场景。
