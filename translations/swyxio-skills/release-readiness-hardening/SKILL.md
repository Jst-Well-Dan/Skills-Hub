# 发布就绪加固

使用此技能回答：能否安全发布，以及我们如何确认？它将发布风险转化为明确的门禁、证据和回滚路径。

## 工作流程

1. **盘点发布涉及的各个方面**
   - 部署平台、构建命令、运行时配置、环境变量、迁移、存储、队列、服务提供商、功能开关、健康检查、监控和回滚机制。
   - 当前的 CI/CD、手动部署步骤、分支/标签/版本策略，以及生产环境冒烟测试路径。

2. **定义发布门禁**
   - 必需的本地检查：类型检查/代码检查/单元测试/构建。
   - 针对受影响用户流程所必需的集成/端到端/视觉检查。
   - 必需的迁移/数据检查。
   - 必需的类生产环境冒烟测试。
   - 必需的部署后验证和日志审查。

3. **加固部署路径**
   - 添加启动/环境验证，以检查缺失或格式错误的配置。
   - 添加健康/就绪端点或等效检查。
   - 添加使用临时记录并在完成后清理的冒烟测试脚本。
   - 为有风险的新行为添加功能开关或紧急停用开关。
   - 为代码、配置和数据变更添加回滚说明。

4. **进行发布演练**
   - 执行本地门禁并记录结果。
   - 根据需要部署到预览/预发布/生产环境。
   - 验证路由、身份验证、持久化、关键工作流程、日志和指标。
   - 清理冒烟测试数据，并确认无任何残留。

5. **发布报告**
   - 说明已发布的版本/提交/部署 URL。
   - 列出已通过、已跳过或被阻塞的门禁。
   - 列出已知风险、回滚步骤以及接下来需要监控的内容。

## 质量标准

- 缺少必需的环境变量时，应尽早失败并给出清晰的消息。
- 部署验证使用类生产环境路径，而不只使用本地模拟。
- 回滚方案必须具体，并经过测试或至少进行过演练。
- 冒烟测试不得留下永久性测试数据。
- 最终回答应区分已通过的门禁和已接受的风险。

有关审计检查清单，请阅读 [checklist.md](references/checklist.md)。
