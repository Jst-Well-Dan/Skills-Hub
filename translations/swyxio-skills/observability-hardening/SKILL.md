# 可观测性强化

当产品能够运行但故障难以洞察时，使用此技能。输出应当使生产环境中的行为可以得到解释，同时避免泄露隐私数据。

## 工作流程

1. **梳理必须了解的内容**
   - 识别关键用户旅程、API 路由、后台任务、提供商调用、长时间运行的操作、部署/启动故障以及高成本路径。
   - 列出当前的日志、错误报告、分析、指标、追踪、请求 ID 和仪表板。

2. **定义遥测契约**
   - 选择事件名称、日志级别、错误类、跨度名称、路由标签、操作 ID 和脱敏策略。
   - 将产品分析与工程诊断分开。
   - 除非明确允许，否则将用户/提示词/内容密集型载荷保留在本地或进行脱敏。

3. **检测高价值路径**
   - 在入口点添加请求 ID/关联 ID。
   - 为关键操作的开始/成功/失败添加结构化日志。
   - 添加类型化错误类或安全错误封装。
   - 在相关情况下，为延迟、失败率、重试、队列时间、令牌/成本、缓存以及提供商/模型行为添加指标。
   - 为长时间运行或可重试的工作流添加用户可见的操作状态。

4. **使其易于使用**
   - 添加能够回答实际问题的仪表板、日志查询或开发者/管理员视图。
   - 仅为可采取行动的故障定义告警阈值。
   - 记录如何调试最常见的事件。

5. **验证**
   - 运行本地和模拟生产环境的冒烟测试。
   - 验证日志/事件已发出、已关联、已脱敏且未重复。
   - 测试具有代表性的失败路径。

## 质量标准

- 可以从用户操作追踪故障至路由/任务/提供商，并追踪返回。
- 日志是结构化的，并在需要时保持低基数。
- 默认对敏感内容进行脱敏。
- 告警对应具体行动，而非噪声。
- 长时间运行的操作会如实显示进度、已用时间和失败状态。
