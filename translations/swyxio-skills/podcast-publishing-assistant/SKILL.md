# 播客发布助手

将此技能用于播客或访谈发布工作流。

## 核心规则

- 优先使用源音频，而不是平台字幕。
- 除非用户明确要求以最快速度完成粗略版本，否则不要依赖 YouTube 字幕。
- 对于 Whisper 或 API 转录，应如实说明不确定性。除非工具确实生成了真正的说话人区分结果，否则不要声称实现了真正的说话人区分。
- 如果用户有格式偏好，请在后续轮次中原样保留。
- 对于 swyx，默认章节输出仅使用 YouTube 时间戳格式，只包含开始时间，后接一个 2 到 10 个词的标题。

## 工作流

1. 首先获取源音频。
   - 对于 YouTube URL，使用 `yt-dlp` 提取音频。
   - 为保证兼容性，优先输出 MP3。

2. 按后备方案阶梯进行转录。
   - 当 `OPENAI_API_KEY` 可用时，首先尝试 OpenAI Whisper API。
   - OpenAI 音频转录的上传上限约为 25 MB。长节目通常会超过此限制。
   - 如果文件过大，请先压缩再重试，例如压缩为单声道 16 kHz、约 32 kbps 的 MP3。
   - 如果 API 转录仍然失败，则改用本地 Whisper。
   - 如果脚本存在但不可执行，请使用 `bash` 调用，而不是因权限问题直接失败。

3. 在耗时较长的任务期间向用户同步进度。
   - 简短的进度说明即可：下载中、压缩中、转录中、打包中。
   - 如果启用了后备方案，用一行说明失败原因，然后继续。

4. 制作发布素材包。
   - 面向正在决定是否观看或收听的人撰写摘要。
   - 提炼关键要点或核心论点。
   - 用户要求时提供 5 个标题创意。
   - 用户要求时提供 5 个简介创意。
   - 提供章节时间戳。
   - 可选：推文串、节目笔记、精彩引语、新闻简报短文。

5. 正确整理时间戳。
   - 如果转录来源提供了分段信息，优先使用真实时间戳。
   - 如果转录稿只是单个纯文本块，请保守估算粗略的章节时间，并在需要时标注为近似时间。
   - 对于 swyx，默认使用以下精确样式：
     - `0:00` 开场与起源故事
     - `3:30` 品牌如何发展壮大

## 转录质量说明

- 除非在其他地方请求包含丰富分段信息的响应格式，否则 OpenAI Whisper API 通常返回纯文本。
- 纯文本转录稿适合制作摘要和粗略章节，但不适合精确区分说话人。
- 如果需要说话人标签但没有真正的说话人区分结果，请根据轮流发言情况进行启发式重建，并明确说明这只是近似结果。

## 发布模板

当用户需要发布方面的帮助时，默认提供可复用的发布素材包。

### 标准发布素材包

1. YouTube 标题
   - 提供 3 到 4 个选项。
   - 优先将核心论点放在前面，嘉宾放在后面。
   - 标题应具体，避免泛泛而谈。

2. YouTube 简介
   - 提供 3 到 4 个选项。
   - 每个选项都应包含：
     - 一段简短的背景介绍
     - 3 到 6 个具体要点，说明观众将学到什么
     - 如果可用，提供 YouTube 时间戳格式的章节标记

3. X 主帖
   - 提供 3 到 4 个选项。
   - 结构：
     - 吸引人的开头或核心论点
     - 介绍嘉宾资历的一行文字
     - 3 到 6 个具体要点
     - 链接占位符或实际链接

4. X 后续回复
   - 除非用户要求更多内容，否则提供 1 条仅含时间戳的简洁回复。
   - 仅使用 YouTube 时间戳格式，只包含开始时间，标题长度为 2 到 10 个词。

5. 原生短视频创意
   - 提供 3 到 4 个选项。
   - 每个短视频创意应包含：
     - 短视频主题
     - 它适合作为推广内容的原因
     - 如果已知，提供大致时间戳范围

6. 引语卡片创意
   - 提供 3 到 4 个选项。
   - 优先选择简洁、有论点且脱离上下文仍有明确含义的句子。

### 素材整理指南

- 区分：
  - 本期节目讲什么
  - 为什么它在当下很重要
- 优先使用具体要点，而不是抽象的主题标签。
- 对于 X，应同时优化好奇心和实用价值，而不只是采用公告式语气。
- 对于 YouTube，应同时优化可搜索的核心论点和嘉宾可信度。
- 如果受众是技术人员，具体性胜过炒作。

## 输出格式

默认输出顺序：
1. 简短摘要
2. 关键要点
3. 章节时间戳
4. 3 到 4 个标题选项
5. 3 到 4 个简介选项
6. 3 到 4 个 X 帖子选项
7. 3 到 4 个短视频创意
8. 3 到 4 个引语卡片创意

## 脚本

- `scripts/transcribe_youtube.sh`：从 YouTube 下载音频，压缩超过 Whisper API 大小限制的音频，并顺畅切换到后备方案。

## 说明

- 优先追求速度，但不要伪装确定性。
- 如果转录路径失效，请说明失败原因，然后继续尝试下一个后备方案。
- 对于长节目，请在最终整理发布素材之前向用户同步一次进度。
- 如果用户提出“始终使用 YouTube 时间戳格式”之类的格式要求，请在任务剩余过程中将其视为持续生效的偏好。
