# 将 URL 与导航和筛选状态同步

## 用户偏好

**始终将有意义的 UI 导航和筛选状态保存在 URL 中**（查询参数）。重新加载、共享或打开链接时，应恢复到相同的页面状态，而不仅仅是顶层路由。

除非用户另有说明，否则用户期望 Web 应用默认采用此行为。

## URL 中应包含的内容

| 状态 | 包含条件 |
|-------|----------------|
| 当前视图 / 标签页 / 模式 | 用户可以在不同页面之间切换 |
| 子导航（侧边栏表格、嵌套标签页） | 存在二级导航 |
| 搜索 / 筛选文本 | 用户可以筛选列表或表格 |
| 结构化筛选器（下拉菜单） | 每个筛选器都会实质性地改变显示内容 |
| 分页游标（可选） | 仅当为页面添加书签很重要时；最好省略 page=1 |
| 选中项 / 编辑器（可选） | 仅用于可共享的深层链接（`?focus=type:id`） |

从 URL 中**省略默认值**（例如默认标签页 id、空的 `q`），以保持链接简洁。

## 实现模式

1. **单一的路由模块** — `readRouteState(search)` + `writeRouteState(state)`（或等效实现）。在一处解析并验证所有参数。
2. **加载时从 URL 初始化存储** — 信号的初始值来自 `readRouteState()`，而不是仅使用硬编码的默认值。
3. **设置函数** — 例如 `setDataTableId`、`setListFilter`：更新信号，然后调用 `writeRouteState`。UI 在改变筛选器时，绝不能不与 URL 同步。
4. 对应用内更改使用 **`history.replaceState`**（符合现有偏好：URL 可共享，同时避免每次按键都产生一条历史记录）。仅当用户明确希望每次筛选更改都形成完整的历史记录栈时，才使用 `pushState`。
5. **`popstate` 监听器** — `hydrateRouteFromUrl()` 在浏览器后退/前进时重新读取参数。
6. **视图作用域参数** — 切换顶层视图时，移除仅适用于其他视图的参数（避免陈旧的 `q` 表示不同含义）。
7. **传入的深层链接** — 支持可映射到表格和筛选器的稳定别名（`focus=assignment:asn_…`）；用户手动更改导航后清除别名。
8. **测试** — 为解析/读取编写纯函数测试（无效 id、focus 格式、视图特定的 `q`）。

## 参数命名（约定）

- 使用简短、稳定的名称：`view`、`day`、`table`、`q`、`area`、`status`
- 除非有文档说明，否则避免在不同视图中复用一个键来表达不同语义
- 当 UI 显示 “Day 1” 时，URL 中优先使用序号（`day=3`）；同时接受原始 id，以保持向前兼容
- 添加新页面时，在 PR 或 README 中用一个简短的表格记录参数

## 新页面检查清单

- [ ] 每个导航控件都通过设置函数更新 URL
- [ ] 加载流程能从 URL 恢复状态
- [ ] 无效参数值能安全回退（不会崩溃）
- [ ] 后退/前进功能正常（`popstate`）
- [ ] 已记录示例 URL，或已通过测试覆盖

## 参考实现

AI Engineer World's Fair 2026 日程管理应用在以下文件中实现了此模式：

- `src/frontend/routing.ts` — 解析/写入查询参数
- `src/frontend/store.ts` — `setViewMode`、`setDataTableId`、`setDataFilter`、`setListFilter`、`hydrateRouteFromUrl`
- `tests/routing.test.ts` — focus 链接和视图特定的筛选器

在其他仓库中工作时，请复制此模式，不必照搬具体的参数名称。

## 反模式

- 筛选器仅保存在组件的 `useState` / 信号中，不与 URL 同步
- 仅在初始加载时同步 URL，但用户更改筛选器时不同步
- 将机密信息或个人身份信息放入查询参数
- 同一概念在不同视图中使用不同的参数名，且切换视图时不清除这些参数
