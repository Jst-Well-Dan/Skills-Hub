# 保留账号名策略

使用此技能保护公共账号名命名空间，同时避免将宽泛的列表变成缺乏解释的永久禁用名单。

## 从策略模型开始

区分两类限制：

1. `hard_reserved`：平台路由、权威性术语、安全身份和服务名称，用户绝不能申领。
2. `manual_claim_required`：稀缺或容易引发冒充的名称，管理员可在完成身份审核后进行分配。

不要将两者都简单报告为 `taken`。调用方需要区分现有账号、平台永久保留项，以及可以审核的申领请求。

在更改分级或来源群组之前，请阅读 [rationale.md](references/rationale.md)。仅在实施、审计或检查具体列表时加载 [reserved-handles.toml](references/reserved-handles.toml)；该文件包含数千个名称，因此有意不放入默认上下文。

## 实施工作流

1. 找到规范的账号名验证器、注册命令、改名命令、可用性端点、数据库唯一性约束，以及管理员变更边界。
2. 保留产品现有的规范化规则。比较规范化的小写账号名；如果允许使用分隔符，还需比较移除分隔符后的骨架形式。
3. 按以下顺序应用限制更严格的结果：
   - 与硬保留项完全匹配或构成易混淆匹配；
   - 已签发的当前或历史账号名；
   - 骨架长度不超过三个字符；
   - 与需人工申领项完全匹配或构成易混淆匹配；
   - 否则可用。
4. 在开放注册和自助改名流程中拒绝受保护的名称。不要为这些公共命令添加基于角色的绕过机制。
5. 如果范围包含人工分配，请创建独立的管理员命令，并记录申领人证据、原因、操作人、时间戳和审计记录。引导管理员申领可以作为范围严格且有明确文档说明的例外。
6. 如果旧的个人资料或内容 URL 会通过账号名历史记录重定向，则历史账号名应永久保持不可用。
7. 返回明确且机器可读的原因，例如 `manual_claim_required`，并在 UI 中向用户提供如实说明。
8. 为硬保留项、短账号名、分隔符、每个来源群组中的一个示例、现有/历史账号名、引导流程行为及经审计的分配添加聚焦测试。

## 使用捆绑的注册表

针对一个或多个候选项运行分类器：

```bash
python3 reserved-handle-policy/scripts/check_handle.py admin swyx a_i available-name
```

编辑注册表后对其进行验证：

```bash
python3 reserved-handle-policy/scripts/validate.py
```

TOML 资源是唯一事实来源。它为每个账号名使用一个紧凑的内联表，同时保留排名、karma、来源拼写、群组元数据和策略规则。CSV 是扁平化的便捷导出，每个精确账号名占一行，并包含所有匹配的群组。捆绑的读取器需要 Python 3.11 或更高版本，以使用标准库中的 `tomllib` 解析器，且不会安装任何依赖项。

## 更新来源群组

请阅读 [refresh.md](references/refresh.md)，了解特定来源的获取说明和准确的 Hacker News 查询。

- 将排名视为带日期的证据，而非永恒不变的身份事实。
- 在可用时保留来源顺序和排名元数据。
- 按照产品的账号名语法规则筛选候选项，但要记录被排除的来源行数。
- 不要将未经处理的 Reddit karma 排行榜作为权威来源导入。官方并不存在全局排名，而第三方列表中混杂着大量机器人、转载账号、已删除用户和不安全身份，噪声很大。除非出现更具合理依据的数据集，否则应继续对 Reddit 数据进行人工甄选。
- 新增受保护名称不能收回已签发的账号名。在更改线上策略前生成冲突报告。
- 将来源 URL、采集日期、群组依据和策略版本与数据保存在一起。

## 交接

报告：

- 各分级和群组的数量；
- 规范化和易混淆匹配规则；
- 与现有或历史账号的冲突；
- 哪些面向用户和管理员的流程发生了变化；
- 已运行的测试；
- 来源采集日期，以及任何被有意排除的群组。
