# media-use

HyperFrames 的媒体 OS：解析 · 生成 · 操作 · 记忆——所有媒体类型，一个技能，零上下文噪音。

首次运行：安装并登录 `heygen` CLI（免费使用路径），然后通过 `node <SKILL_DIR>/scripts/resolve.mjs --doctor` 验证。设置与提供商：`references/setup-providers.md`。

## 解析——唯一的动词

```bash
node <SKILL_DIR>/scripts/resolve.mjs --type <type> --intent "<description>" --project <dir>
```

返回一行：`resolved <id> → <path> (<type>, <metadata>)`。所有搜索噪音都会保留在磁盘上。

| 类型    | 单行意图                                                                            |
| ------- | ----------------------------------------------------------------------------------- |
| `bgm`   | 背景音乐（HeyGen 目录，10k+ 曲目）                                                  |
| `sfx`   | 音效（内置 19 文件库 + 目录）                                                       |
| `image` | 照片、背景（HeyGen 资产搜索，75k+ 矢量资源）                                        |
| `icon`  | 图标、符号（透明背景）                                                              |
| `logo`  | 官方品牌标识（svgl → simple-icons → GitHub 头像 → favicon；绝不重绘）               |
| `voice` | TTS 旁白（HeyGen 免费使用路径；可选本地 Kokoro）                                    |
| `grade` | 经过测量的校正候选项；广泛润色/风格化请遵循 Media Treatments                        |
| `lut`   | 用户提供或明确选择的、可复用且经过验证的 `.cube` 文件                              |

在重新解析前，使用 `--candidates` 列出可复用候选项，并自行判断适配性——复用规则、所有标志、摄取（`--from`）和采用方式见 `references/resolve.md`。

## 将广泛的视觉反馈视为媒体意图

当用户明确要求修复、润色、风格化、模糊、强调或揭示摄影媒体时，即使他们没有提及调色或效果，也请阅读 `references/media-treatments.md`。检查真实的 `<img>`/`<video>`，选择一个主要意图，然后使用确定性的持久化和验证。将匹配的配方作为可选的已测试起点，或者检查 `hyperframes media-treatment --capabilities --json`，然后使用 `--capability <id>` 请求一个相关系列/效果，并从规范控制项组装自定义处理。普通创作时绝不加载 `--all`。一项处理可以组合校正、预设、收尾、兼容的着色器效果、受支持的关键帧以及可选的 Registry 覆盖层。仅添加有源依据且范围受限的微调与兼容组件，绝不只是为了让结果显得更复杂而添加效果。使用 `hyperframes media-treatment` 持久化最终的组合载荷。

采用一个逐步升级的工作流。对于视频，检查一张带标签的早期/中期/后期联系表，而不是分别读取帧。对于普通校正或润色，应用一个候选项并检查一张处理后的联系表。仅当结果存在歧义、涉及时间维度、风格化、基于 LUT、对 HDR/LOG 敏感、隐私敏感或品牌关键时，才升级到单独帧或动态草稿证据。

对于普通校正或润色，持久化最终处理的预设/调整 JSON。
不要仅为了编码曝光、阴影、对比度或暖色调而生成 `.cube` LUT。仅当用户提供 LUT，或所选处理明确拥有 LUT 时才使用 LUT。`resolve --type grade --for ... --analyze` 是测量证据，不是用生成的 LUT 替换所选处理的许可。不要用 CSS/SVG 覆盖层重建受支持的暗角、颗粒、模糊、像素化、颜色或处理效果；这会绕过 Studio 控制项以及规范的预览/渲染着色器路径。

## 主动出击——执行媒体机会扫描

人类通常无法判断哪些媒体可以提升作品。你可以。当你构建或审阅一个构图时，进行**一次**有依据的扫描，然后**询问一次**——不要静默添加，也不要针对每个资产反复催促。

仅在存在具体信号时提出机会：

| 检测到的信号                                              | 提议                                                                                                   |
| -------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| 屏幕文本 / 有脚本但没有旁白                              | TTS 旁白（音频引擎）                                                                                   |
| Emoji 或样式化为图标的 `<div>`                           | 解析真实的 `icon`                                                                                      |
| 图像是占位符、很小或看起来被放大                          | 更好的 `image`（和/或放大——参见 `references/operations.md`）                                          |
| 硬场景切换 / 转场没有声音                                | 转场 `sfx`                                                                                             |
| 超过约 10 秒的作品没有音乐底                                | `bgm`                                                                                                  |
| 素材看起来曝光不足/过度或存在色偏                         | 校正性调色（使用 `hyperframes media-treatment --selector '#hero' --analyze --json` 检查）              |
| 摄影媒体视觉上平淡或偏离主题                              | 一个具体且与源素材相称的预设或自定义处理，并明确说明预期目标                                           |
| 有意义的媒体入场/揭示效果显得静态                         | 一个受支持且可安全定位的处理动画；除非请求同时证明预设合理性，否则保留色彩                             |

确保这是帮助而非催促软件的规则：**有依据，而非泛泛而谈**（没有信号 → 不建议）；**有主见且具体**（提出使用已选默认值的具体修复方案——人类批准**全部 / 部分 / 不批准**）；**每个项目一次**（一次汇总询问；尊重“保持原样”）；**仅提出，绝不静默修改**（尤其是调色：提出并预览——灰度世界“校正”会毁掉刻意的日落或霓虹外观）。
