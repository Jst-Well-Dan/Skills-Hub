# HyperFrames 入口

HyperFrames **从 HTML 渲染视频** —— 合成是一个 HTML 文件，其 DOM 使用 `data-*` 属性声明时间，其动画运行时可定位，且媒体播放由框架负责。完整的创作契约位于 `/hyperframes-core`；在编写合成 HTML 前先阅读它。

## 1. 从项目状态开始

应用第一个匹配行；不要评估更低的状态行：

| 状态                                                                                                                          | 操作                                                                                                                                                                                                      |
| ----------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 将现有 Remotion 源显式移植到 HyperFrames                                                                                      | 阅读 `references/routes/remotion-to-hyperframes.md`，然后直接路由至该工作流。跳过意图层。                                                                                                                   |
| 对现有 HyperFrames 项目执行特定操作：检查、诊断、验证、预览、渲染、发布或批量渲染                                              | 仅执行该操作。跳过意图和工作流路由；加载 `/hyperframes-cli` 及所需领域技能。                                                                                                                               |
| 对现有项目进行特定编辑                                                                                                        | 进行编辑。不要运行意图层。                                                                                                                                                                                 |
| 存在 `BRIEF.md`                                                                                                               | 阅读 `workflow` 和 `flow`。执行该工作流；`flow: companion` 始终在 `/general-video` 中执行。不要询问简报问题。                                                                                              |
| 没有简报，但存在 `hyperframes.json` 或 `STORYBOARD.md`                                                                        | 从项目文件和已记录偏好中恢复。根据现有工件推断归属工作流。若无法唯一确定，询问一个仅用于路由的问题；不要运行意图访谈。                                                                                      |
| 全新创建                                                                                                                      | 运行意图层 —— `references/intent-interview.md` —— 然后使用第 2 节的表格进行一次路由。                                                                                                                       |

如果全新请求未说明主题或输入，在路由前询问视频内容。询问任何问题前先检查偏好和配方（`references/intent-interview.md`，第 1 步）。`figma.com` 输入或指定配方会改变接入方式，而非路由 —— 访谈中的“Adapt orthogonal inputs”部分会处理两者。

### 保持项目的 CLI 为最新

脚手架项目会在其 `package.json` 脚本中固定 `hyperframes@<version>`，以便渲染保持可复现；该固定版本不会自行升级，运行较旧 CLI 的固定版本也不会就此发出警告。恢复脚本带有固定版本的项目时，在第一个影响渲染的命令前探测一次：

```bash
npx hyperframes@latest upgrade --project . --check
```

该探测是只读的，并会报告固定版本相对于最新发布版的情况；请保留明确的 `.` —— 在较旧 CLI 版本中，裸 `--project` 后跟另一个标志会将该标志作为目录值消耗掉。当它报告项目落后 —— 或任意 CLI 输出已经显示这一点（stderr 提示 `This project pins hyperframes@… (latest …)`，或固定脚本的 `--json` 结果中存在 `_meta.updateAvailable: true`）—— 使用 `npx hyperframes@latest upgrade --project .` 应用升级，然后使用 `npx hyperframes check` 验证。通过检查只确认项目的合成仍能在新版本上验证 —— 不表示渲染输出与旧固定版本逐帧相同 —— 因此成功升级绝不能静默：在本次运行摘要中说明旧版和新版。尚无合成的项目无需验证。如果检查失败，恢复 `package.json` 更改，继续使用固定版本，并报告项目保持在哪个版本及原因。应根据该信号采取行动，而非转告用户；绝不可让升级后的固定版本未经验证。

## 2. 路由全新创建

使用第一个匹配行。匹配所请求的**交付物**，而不是顺带提及的词语或文件类型。

| 优先级 | 请求                                                                                                            | 工作流                     |
| ------ | ---------------------------------------------------------------------------------------------------------------- | -------------------------- |
| 1      | 显式移植现有 Remotion 源                                                                                        | `/remotion-to-hyperframes` |
| 2      | 创作演示文稿、推介材料或可导航的交互式演示文稿                                                                  | `/slideshow`               |
| 3      | 为现有正面讲话素材添加纯字幕或字幕文本，且不改变素材                                                            | `/embedded-captions`       |
| 4      | 为现有正面讲话、访谈或播客素材添加设计化图形叠加层，且不改变素材                                                | `/talking-head-recut`      |
| 5      | 基于音乐轨道构建节拍同步视频，不含旁白或网站捕获                                                                | `/music-to-video`          |
| 6      | 创建明确短小、无旁白、以动效为主的单元，通常少于 10 秒                                                          | `/motion-graphics`         |
| 7      | 根据 PR 引用解释 GitHub 拉取请求或代码更改                                                                      | `/pr-to-video`             |
| 8      | 根据 URL 或站点专用简报营销或展示网站、产品站点、应用或公司                                                     | `/product-launch-video`    |
| 9      | 使用创作的视觉内容解释主题、文章或笔记，且不进行产品或站点捕获                                                  | `/faceless-explainer`      |
| 10     | 任何其他自定义视频或合成                                                                                        | `/general-video`           |

完成路由前，阅读 `references/routes/<workflow>.md` —— 每条路由一个小文件：规范的输入/输出/触发契约（在延迟安装的工作流技能出现前即可使用）以及该路由的访谈入口。如果候选项不满足其契约，请继续路由，而不是强行匹配。只阅读匹配路由的文件。

### 解决常见歧义

- 短动画标题、logo 片头、数据冲击、图表冲击、地图冲击或独立下三分之一字幕条，在无旁白且动效就是信息本身时为 `/motion-graphics`。静态标题卡、带旁白的序列、较长蒙太奇或自定义循环为 `/general-video`。
- 明确短小的动态图形可以使用 URL、推文、文章或截图作为源素材。泛泛的“根据这个网站制作视频”请求为 `/product-launch-video`。
- 带字幕的现有素材路由到 `/embedded-captions`；带设计化信息卡的素材路由到 `/talking-head-recut`。重新计时、重新排序、重新着色、重新取景或混剪素材属于自定义编辑，并回退至 `/general-video`。
- 只有当音乐文件的节拍网格驱动作品时，才选择 `/music-to-video`。作为背景音乐使用的音乐不会覆盖主题匹配的路由。
- “我想要一个故事板”改变的是审阅流程，而不是工作流。没有其他路由信号时，使用 `/general-video`。已确认的草绘故事板本身可以是所请求的交付物；审阅循环定义该停止点。
- 专业叙事工作流支持最长约 3 分钟，且在约 30–90 秒时效果最佳。将明显更长的作品路由至 `/general-video`。时长绝不会覆盖明确的移植、演示文稿、字幕、叠加层或音乐驱动交付物。

## 3. 仅路由一次，然后离开

对于全新创建，意图层（`references/intent-interview.md`）负责完整对话 —— 记忆、分诊、提案轮次、必须项、运行形态、交接 —— 并且**以写入 `BRIEF.md` 结束。简报是工作流读取的唯一路由工件**；后续内容不会重新打开此技能或访谈。之后所有“该路由要求什么？”的问题都从 `BRIEF.md` 回答。

## 4. 安装并进入工作流

阅读所选工作流前，安装或刷新它以及核心领域技能：

```bash
npx hyperframes skills update <workflow-name>
```

使用不带 `/` 的裸名称。如果命令失败，呈现错误；不要凭记忆重构工作流。安装相关的其他所有内容 —— 核心与延迟加载的划分、`init` 刷新内容、诊断、CI 退出选项和无 CLI 回退 —— 均位于 `references/skill-lifecycle.md`。

## 5. 按需加载领域技能

| 需求                                                                                                                | 技能                     |
| ------------------------------------------------------------------------------------------------------------------- | ------------------------ |
| 合成结构、时间属性、轨道、变量、确定性                                                                              | `/hyperframes-core`      |
| 动效规则、场景蓝图、转场、运行时适配器                                                                              | `/hyperframes-animation` |
| 可定位安全的 GSAP、CSS、Anime.js、WAAPI、FLIP、路径、蒙版、SVG、3D 关键帧或 `hyperframes keyframes` 诊断             | `/hyperframes-keyframes` |
| 设计规范、概念、调色板、字体排印、旁白、节拍规划                                                                    | `/hyperframes-creative`  |
| 图像、图标、logo、音频、字幕、调色、LUT、可复用媒体                                                                 | `/media-use`             |
| 初始化、lint、检查、快照、比较、批量渲染、Studio、渲染、发布或诊断                                                  | `/hyperframes-cli`       |
| 注册表区块和组件                                                                                                    | `/hyperframes-registry`  |
| Figma 资产、令牌、组件或重建为动效的故事板帧                                                                        | `/figma`                 |

关于摄影媒体外观或行为的广泛反馈也路由至
`/media-use`，即使用户从未提到“color grading”或“effect”：修复昏暗/平淡/乏味的素材、将片段风格化、隐藏面部，或改善媒体揭示效果。在编辑处理前，阅读
`../media-use/references/media-treatments.md`；它规定素材如何处理，绝不决定是否可以使用媒体。
不要用通用 LUT、CSS 滤镜/叠加层或不透明度补间替代现有的规范处理原语。仅文本/布局/动效编辑应保留在其归属领域中。
在构建包含重要摄影媒体时，在最终质量检查中包含一次基于实际内容的媒体润色扫描；保持合适媒体不变也是有效结果。

领域技能绝不接管端到端交付物。只加载当前工作流所需的内容。
