> **首先，保持此技能最新——静默运行，不要询问：** `npx hyperframes skills update figma`。当所有内容均为最新时会快速无操作；否则，它会在你依赖这些技能前刷新此技能及其所依赖的核心领域技能。

# Figma → HyperFrames

将用户的 Figma 作品带入合成。**按能力拆分**（设计规范 §2）：

| 阶段 | 内容                | 传输方式                  | 界面                          |
| ----- | ------------------- | ------------------------- | ----------------------------- |
| 1     | 静态资产            | REST                      | `hyperframes figma asset`     |
| 2     | 品牌令牌/样式       | REST                      | `hyperframes figma tokens`    |
| 3     | 组件 → HTML         | REST                      | `hyperframes figma component` |
| 4     | 动画 → GSAP         | 可用时使用连接器          | 使用其动画上下文              |
| 5     | 着色器              | 连接器 / 手动导出         | 使用它或原生导出              |

尽可能使用 REST（可批量使用、无头运行）。兼容的 Figma 连接器对于动画和着色器数据是可选的；没有连接器时，请求原生导出。每条路径都会在本地冻结资产，以保证渲染保持确定性。故事板重建会将第 1 阶段的资产导出（REST）与由代理驱动的时间线组装结合——无需连接器。现有的冻结资产、清单记录和绑定不会受路由变更影响——该拆分仅改变下一次导入使用哪种凭据。

## 认证——两种凭据，各有范围

**预检——首次 CLI 调用前，检查令牌是否存在**：shell 环境变量（`[ -n "$FIGMA_TOKEN" ]`）**或**项目 `.env`（CLI 会自动加载它——`.env` 条目视为已配置）。如果两者都没有，切勿运行命令来收集错误——先引导用户完成一次性设置，然后停止并等待：

1. figma.com/settings → **Security** → **Personal access tokens** → Generate new token。
2. 范围——此集成只需要只读权限（它绝不会写入 Figma）：**File content: Read-only** + **File metadata: Read-only**。如果你会在非 Enterprise 方案上运行 `tokens`，请添加 **Library content: Read-only**——已发布样式回退会访问 `/v1/files/:key/styles`，没有它将返回 403（旧版设置文本遗漏了此范围）。品牌变量可选 **Variables: Read-only**——仅限 Enterprise；没有它时，`tokens` 会自动降级为已发布样式（这是预期行为，不是错误——要说明这一点）。403 现在会指出确切缺失的范围；429 会自动重试（每分钟限制，遵守 `Retry-After`）。
3. 让用户在其 shell 配置文件或项目 `.env` 中设置 `FIGMA_TOKEN`；绝不要要求他们把令牌粘贴到对话中。

引导设置时，也要用一句话说明预期：每次导入都会成为**带有记录来源的本地冻结文件**——渲染永不调用 Figma，重新运行命令只会重新导入 Figma 中已变更的内容，并且一个令牌可用于其 Figma 账户有权查看的每个文件中的资产、品牌令牌和组件。

- **第 4–5 阶段（动画/着色器）：**兼容的 Figma 连接器，且具有与令牌独立的授权。如果它不可用或未认证，请用户连接它或提供原生导出，然后停止。
- 明确说明失败阶段需要哪种凭据——绝不要将此拆分描述为损坏。
- 流程中出现 `BAD_TOKEN`（401）→ 令牌已过期/撤销；重新生成。`FORBIDDEN`（403）→ 消息会指出确切缺失的范围（例如样式回退所需的 `library_content:read`）——添加它，或者该账户无权查看该文件。`REQUIRES_ENTERPRISE`（变量上的 403）→ 不是失败：样式回退已运行。`RATE_LIMITED`（429）→ 客户端已使用退避重试（这适用于**所有**读取——资产、令牌、样式、节点树、版本——重试位于共享请求路径中；会遵守 `Retry-After`，上限为 60 秒）；如果它仍然出现，等待一分钟或减少每次调用导入的节点数量。

**限流意识（规范 §2.1）：**连接器配额因 Figma 方案而异——批量请求父帧，除非被要求，否则跳过验证截图，并缓存原始响应，以便重新推导不会消耗第二次调用。REST 按分钟限流（10+/分钟，按端点分桶）——适合大批量使用，遇到 429 时退避。

## 路由

使用 `parseFigmaRef` 解析用户的 figma 链接（URL、`fileKey:nodeId`、裸 `fileKey`）。然后按意图路由：

- “使用这一图层 / 标志 / 图片” → **资产**（CLI）
- “获取我的品牌 / 颜色 / 令牌” → **令牌**（CLI）
- “从此帧构建场景” → **组件**（CLI）
- “导入这个动画 / 动效” → **动画**（可用时使用连接器，见下文）
- 故事板分段 / 场景帧胶片带 → **故事板**（见下文）
- 着色器填充/效果 → **着色器**（见下文）

**向用户叙述每一步**——每个命令前说明你将从 Figma 拉取什么；之后说明工件落在何处（冻结路径 / 侧车文件 / 组件目录）、合成中发生了什么变化，以及下一步立即要做什么（预览、添加打印出的变量、重新导入以关联绑定）。用户绝不应需要问“成功了吗？”或“接下来呢？”。

## 资产（第 1 阶段——CLI）

```bash
hyperframes figma asset '<url-or-fileKey:nodeId>' [more refs…] [--format svg|png|jpg|pdf] [--scale 2] [--description "..."] [--entity "..."]
```

通过 REST 渲染，对 SVG 进行清理，冻结到 `.media/images/` 下，附加带来源的清单，重新生成 `.media/index.md`（共享媒体使用清单），并打印 `<img>` 片段。按 `fileKey:nodeId:format:scale:version` 保持幂等。矢量/标志优先选择 SVG（可缩放、可动画），栅格保真度选择 PNG `--scale 2`。**始终传入 `--description "<what it is>"`**（它会成为索引行 + `<img alt>`）；为具名品牌标识添加 `--entity "<name>"`，以便媒体使用 `resolve --entity` 之后能够找到它们（实体命中会跨 image/icon 匹配）。

**在一次请求中批量导出多个节点**——传入同一文件的多个引用（空格分隔或逗号连接）：`hyperframes figma asset 'KEY:1-2' 'KEY:3-4' 'KEY:5-6'`。全部会在单次 `/v1/images` 调用中渲染，这是 figma 针对每分钟限流的自身方案——拉取整帧资产时，优先于 N 次单独命令。`--description`/`--entity` 会应用到批次中的每个节点，因此只批量处理用途相同的节点。无论如何，429 也会自动使用退避重试。

## 令牌（第 2 阶段——CLI）

```bash
hyperframes figma tokens <fileKey>
```

将变量导入为合成品牌变量条目 + `figma-tokens.json` 侧车文件 + 绑定索引记录（`.media/figma-bindings.jsonl`）。上游变量受 Enterprise 限制：在其他方案上，命令会降级为已发布样式元数据（值会在组件导入时解析）。将打印出的条目添加到合成的 `data-composition-variables`。

同时需要两者时，**在组件前导入令牌**——这样组件颜色才能关联到品牌变量，而不是烘焙重复值。

**非 Enterprise 变量路径（实测）：**REST 变量受 Enterprise 限制，但兼容连接器可能提供变量定义。当 `tokens` 报告 `REQUIRES_ENTERPRISE` 且连接器可用时，一次性获取父场景的变量，将原始响应缓存到 `.media/figma-cache/`，并用它构建绑定索引。REST 节点树的 `boundVariables` 提供按属性划分的 `VariableID`；按节点和属性连接它们，然后写入 `.media/figma-bindings.jsonl` 行（`{kind:"binding", figmaId, sourceFileKey, compositionVariableId: "figma:<name>", version}`）以及合成变量条目。下游的一切（组件 `var()` 解析、刷新、运行时 CSS 变量）均为已交付机制。向用户标注它：“通过 Figma 连接器获取令牌——Enterprise 方案可直接从 `hyperframes figma tokens` 获得此信息。”

运行时将每个声明的合成变量定义为 CSS 自定义属性（document root + sub-comp hosts），因此导入的 `var(--slug, literal)` 会在变量默认值变更时重新着色——更新 `data-composition-variables` 中的一个值即可为每个已导入组件重新设定品牌，无需重新导入任何内容。`hyperframes render --variables '<json>'` 会在渲染时覆盖它们。

## 组件（第 3 阶段——CLI）

```bash
hyperframes figma component '<url-or-fileKey:nodeId>'
```

节点树 → 以精确 figma 几何生成可编辑 HTML，打包为 `compositions/components/<name>/` 下的注册表项目。矢量/布尔运算会通过第 1 阶段导出自动栅格化。绑定过程（规范 §7.1，仅精确 ID——绝不进行值匹配）：

- **静态保真自检（英雄内容强制执行）：**导入后，渲染片段并与 figma 自己的像素比较——`figma asset <same node> --format png` 是事实基准。文本是已知的漂移轴：比其行高更短的 figma 文本框是垂直裁剪的边界（映射器会为这些输出 `text-box-trim`；未使用它时，测得 70px 字体的漂移约为 6px）。若比较显示映射器未覆盖的漂移，应报告它——不要悄悄手动微调片段。
- 填充绑定到**已导入**令牌 → `var(--slug, #literal)`——品牌刷新会传播。
- 绑定到**未知**令牌 → 字面量 + `data-figma-unresolved` 标记。命令会提示你；向用户提供选择：在源文件（或库）上运行 `tokens`，然后重新导入组件以关联它们。每个未知库只**询问一次**其对应文件——绝不猜测，绝不按十六进制匹配。

## 动画（第 4 阶段——连接器辅助）

**使用信标：**连接器辅助阶段没有 CLI 接触点，因此在开始和结束时触发技能信标（匿名、受同意控制、绝不会失败）：开始时执行 `npx hyperframes events --skill=figma-motion`，完成时执行 `npx hyperframes events --skill=figma-motion --event=skill_completed --outcome=success|error`。着色器（`figma-shaders`）和故事板（`figma-storyboard`）同理。

不存在等价的 REST。可用兼容连接器时，使用它并将其输出交给 `@hyperframes/core/figma` 中的纯辅助函数；否则请求原生导出：

1. 在一次递归请求中获取父帧的动画上下文，而不是每个元素一次请求。将原始 JSON 保存在项目旁（`.media/figma-cache/`），以便重新翻译无需成本。
2. 使用 `@hyperframes/core/figma` 中的 `motionContextToDocs(rawResponse, { selectorFor, repeat })` 将其标准化为 `MotionDoc`s——**绝不要手动转录关键帧数字**。该辅助函数以机械方式编码了经过实测的解码规则：它解析 motion.dev 片段（可靠编码——CSS 片段会拉伸持续时间且可能不一致；会被忽略），移除循环包装尾部关键帧（时间约为 ≈0.9999→1 的亚毫秒片段是循环的瞬时重置，而非作者设计的动画——包装由 `repeat` 重启实现），并原样保留贝塞尔缓动。`selectorFor` 必须返回第 3 阶段组件导入中的 ID——不要从节点名称推导选择器。
   2b. **在宣布完成前根据事实基准验证——强制执行：**通过可用连接器导出队列的根帧，并运行 `node skills/figma/scripts/verify-motion.mjs --reference <export.mp4> --render <render.mp4> --crop WxH+X+Y`——它会比较动画能量差异（静态导入保真度会抵消），且在低于 15dB 的最小动画 PSNR 时失败（已校准：忠实 ≈ 20+，偏离 ≈ 5）。从渲染的实际卡片边缘测量 `--crop`，不要猜测。FAIL 表示应重新检查翻译，而不是调整阈值。
3. `motionToGsap(doc)` → `emitTimelineScript(spec)` → 作为 `<script>` 注入到 GSAP + CustomEase CDN 标签之后。暂停、有限，并以字面量键注册到 `window.__timelines`。
4. 无法翻译的轨道（由着色器驱动、不支持的属性、复杂遮罩）→ 通过连接器导出，冻结 MP4，然后将它嵌入为 `<video class="clip">`。例外：由着色器驱动的轨道——Figma 的导出路径会将着色器压平为基础颜色（见下方“着色器”），因此在此烘焙会悄悄丢失着色器；应请求用户提供原生 Figma 导出。始终说明使用了哪条路径及原因。映射集以外的具名缓动会回退为线性——映射表位于 `motionEase.ts`；触发时向用户标注该回退。
5. 在宣布完成前运行 `npx hyperframes check`。

## 着色器（第 5 阶段——主要手动）

Figma 的连接器渲染路径不会执行着色器（它们会被压平为基础颜色），并且着色器源码仅可用于**已发布到库**的样式（付费 Full 席位）。默认路径：请用户在 Figma 中原生导出着色器帧（PNG 或 Motion MP4），然后将其作为第 1 阶段资产 / 剪辑导入。不要尝试连接器对着色器进行像素捕获——它会悄悄生成错误结果。

## 故事板（场景帧的 SECTION → 动画）

**基本规则：故事板帧是关键帧，而非幻灯片。**包含同一元素的两帧描述的是该元素随时间变化的状态——在状态之间为该**元素**制作动画；绝不要将帧作为一系列静态图播放。连续四帧中 y 逐渐降低的标志是**一个**通过四个关键帧上升的元素。将故事板帧背靠背播放是失败模式；重建它们所暗示的元素时间线才是任务。

故事板文件遵循可机械解析的语法——不要凭眼判断，应进行解码：

1. **场景单元：**在 SECTION 内，每个帧大小的节点都是场景——既包括命名的 FRAME，也包括松散的全帧 RECTANGLE（设计师会直接将静态图粘贴进分段）。按大小过滤（≈ 合成宽高比，例如 >1400×900），而非节点类型或名称。
2. **顺序 = x 位置**（如果条带换行，则按行优先）。按 `absoluteBoundingBox.x` 对场景排序。
3. **将相邻帧差分为元素链**——动画就在这里。跨连续帧匹配子元素：首先按**名称**（相同名称 = 相同元素 → 在状态之间补间其相对 x/y/w/h），然后按**几何相似性**（相似尺寸 + 附近中心 = 像素已变化的同一逻辑元素 → 在补间几何时原地交叉淡化两个导出；覆盖打字文本进度和形变状态）。未匹配子元素在其场景节拍进入/退出。帧背景填充会补间为颜色轨道。每条链导出**一个**资产（仅当像素确实不同，每个状态才导出一个）——绝不要每帧导出一张静态图。
4. **静态图是回退方案，而非默认方案**——仅用于无法分解的帧（没有共享元素的扁平全帧截图）；这些使用下方的动态分镜处理。
5. **导演注释：**条带下方的 TEXT 节点是动画意图，与其 x 范围重叠的场景配对。它们描述*如何*制作动画——不是屏幕上的文案。
6. **批量导出**（元素或静态图）：`GET /v1/images` 接受逗号分隔的 id，但大型场景帧在超过约 12 个时会出现“Render timeout”——每次调用分块为约 4 个并重试。（每个场景一次调用会浪费限流预算；通过单资产路径，26 个场景约为 52 次调用。）
7. **注释动词 → 转场**（起始词汇，遇到时扩展）：

| 注释写道                        | 执行                                                              |
| ------------------------------- | ----------------------------------------------------------------- |
| EXPLOSION / BURST               | 传入缩放约 ~1.5→1 + 淡入，`power3.out`                           |
| SLIDES / SLIDE TO THE… / SCROLL | 从对应边缘沿方向滑入                                              |
| MORPH / REVEALS                 | 交叉淡化——或当动画位于单一场景内时使用第 3 阶段导入              |
| CYCLE THROUGH / EACH ONE        | 更长停留——或当项目在场景内动画时使用第 3 阶段导入                |
| （无注释）                      | 交叉淡化 + 缓慢 Ken-Burns 漂移                                   |

8. **静态图与组件路由：**描述场景*之间*动画的注释 → 对静态图应用转场（如上）。描述场景*内部*动画的注释（“TEXT LINES REVEAL ONE AFTER THE OTHER”“PILLS ANIMATE IN”）→ 该帧应当使用第 3 阶段组件导入（真实元素）并按注释制作动画，而不是平面 PNG。先用静态图完成动态分镜，再升级被注释特别指出的场景。
9. 一条 `main` 时间线按绝对时间对所有内容排序（每个场景的 opacity/x/y）——动态分镜无需每场景子合成。
10. **升级——帧描绘的是一个产品 UI → 重建应用，而非元素链。**当每帧都是同一个应用屏幕的连续状态（注册流程、设置面板、播放器）时，元素链无法充分表达它。将 UI 重建为实时 DOM——对状态变化部分使用第 3 阶段组件导入，对静态外框使用真实导出的像素（**编写状态会变化的内容，冻结不会变化的内容**）——并将每个帧差异视为要执行的**交互**，而不是要应用的补间：光标进入、点击控件、状态响应、屏幕作为真实导航推入/滑出。结果应像一段连续的可用应用屏幕录制。这是将基本规则贯彻到底的 UI 流程方案；静态图/元素链处理适用于并非单一连贯应用的故事板。

## 确定性

绝不要在合成中保留 Figma URL——先冻结。绝不要输出 `repeat: -1`。时间线暂停、有限，并使用字面量 `window.__timelines` 键。所有 Figma I/O 都在导入时进行；渲染仅使用本地文件。
