# Stitch 设计品味——语义化设计系统技能

## 概述
此技能可生成针对 Google Stitch 屏幕生成进行优化的 `DESIGN.md` 文件。它将经过实战检验的反粗制滥造前端工程指令，转化为 Stitch 原生的语义化设计语言——将描述性的自然语言规则与精确数值相结合，使 Stitch 的 AI 智能体能够理解并生成高端、非通用化的界面。

生成的 `DESIGN.md` 是提示 Stitch 生成新屏幕的**唯一事实来源**，确保这些屏幕符合精心策划、具有高度设计自主性的设计语言。Stitch 通过由特定颜色值、字体排印规范和组件行为支持的**“视觉描述”**来理解设计。

## 前置条件
- 可通过 [labs.google/stitch](https://labs.google/stitch) 访问 Google Stitch
- 可选：使用 Stitch MCP Server，以便与 Cursor、Antigravity 或 Gemini CLI 进行程序化集成

## 目标
生成一个编码了以下内容的 `DESIGN.md` 文件：
1. **视觉氛围**——情绪、密度和设计理念
2. **色彩校准**——中性色、强调色以及带十六进制代码的禁用模式
3. **字体排印架构**——字体栈、比例层级和反模式
4. **组件行为**——按钮、卡片和输入框及其交互状态
5. **布局原则**——网格系统、间距理念和响应式策略
6. **动效理念**——动画引擎规范、弹簧物理和持续微交互
7. **反模式**——明确列出的禁用 AI 设计陈词滥调

## 分析与综合说明

### 1. 定义氛围
评估目标项目的意图。使用品味光谱中富有感染力的形容词：
- **密度：**“艺术画廊般疏朗”（1–3）→“日常应用般均衡”（4–7）→“驾驶舱般紧凑”（8–10）
- **变化度：**“可预测的对称”（1–3）→“错位的非对称”（4–7）→“艺术化的混沌”（8–10）
- **动效：**“静态克制”（1–3）→“流畅 CSS”（4–7）→“电影级编排”（8–10）

默认基线：变化度 8、动效 6、密度 4。根据用户对氛围的描述动态调整。

### 2. 映射调色板
为每种颜色提供：**描述性名称** + **十六进制代码** + **功能角色**。

**强制约束：**
- 最多使用 1 种强调色。饱和度低于 80%
- 严格禁用“AI 紫色/蓝色霓虹”美学——不得使用紫色按钮辉光，不得使用霓虹渐变
- 使用纯粹的中性色基底（Zinc/Slate），并搭配单一的高对比度强调色
- 整个输出仅使用一套调色板——不得在暖灰与冷灰之间摇摆
- 绝不使用纯黑色（`#000000`）——使用灰黑色、Zinc-950 或炭黑色

### 3. 建立字体排印规则
- **展示文字/标题：**紧凑字距、克制的字号比例。不要喧宾夺主。通过字重和颜色建立层级，而不是仅靠巨大的字号
- **正文：**宽松行距，每行最多 65 个字符
- **字体选择：**在高端/创意场景中禁用 `Inter`。必须呈现独特个性：使用 `Geist`、`Outfit`、`Cabinet Grotesk` 或 `Satoshi`
- **衬线字体禁令：**禁用通用衬线字体（`Times New Roman`、`Georgia`、`Garamond`、`Palatino`）。如果编辑或创意场景需要衬线字体，只能使用具有辨识度的现代衬线字体：`Fraunces`、`Gambarino`、`Editorial New` 或 `Instrument Serif`。仪表盘或软件 UI 中始终禁用衬线字体
- **仪表盘约束：**仅使用无衬线字体组合（`Geist` + `Geist Mono` 或 `Satoshi` + `JetBrains Mono`）
- **高密度覆盖规则：**当密度超过 7 时，所有数字必须使用等宽字体

### 4. 定义首屏区域
首屏决定第一印象，必须富有创意、引人注目且绝不通用：
- **行内图像字体排印：**在标题的单词或字母之间直接嵌入小型、与语境相关的照片或视觉元素。图像以文字高度行内放置，并采用圆角，作为视觉标点。这是标志性的创意手法
- **禁止重叠：**文字绝不能与图像或其他文字重叠。每个元素都占据自己清晰、独立的空间区域
- **禁止填充文本：**禁用“滚动探索”“向下滑动”、滚动箭头图标和弹跳箭头。内容本身应自然吸引用户
- **非对称结构：**当变化度超过 4 时，禁用居中的首屏布局
- **克制使用 CTA：**最多使用一个主要 CTA。不得添加次要的“了解更多”链接

### 5. 描述组件样式
针对每种组件类型，描述其形状、颜色、阴影深度和交互行为：
- **按钮：**激活状态提供有触感的按压反馈。不得使用霓虹外发光。不得使用自定义鼠标光标
- **卡片：**仅在抬升效果能够表达层级时使用。阴影色调应与背景色相协调。对于高密度布局，使用顶部边框分隔线或留白替代卡片
- **输入框/表单：**标签位于输入框上方，辅助文本可选，错误文本位于下方。使用标准间距
- **加载状态：**使用尺寸与布局匹配的骨架加载器——不得使用通用圆形加载动画
- **空状态：**使用经过构图设计的视觉组合，说明如何填充数据
- **错误状态：**提供清晰的行内错误报告

### 6. 定义布局原则
- 元素不得重叠——每个元素都占据自己清晰的空间区域。不得使用绝对定位堆叠内容
- 当变化度超过 4 时，禁用居中的首屏区域——强制使用分屏、左对齐或非对称留白
- 禁用通用的“3 张等宽卡片横向排列”功能区——使用双列之字形布局、非对称网格或水平滚动
- 使用 CSS Grid，而不是 Flexbox 数学计算——绝不使用 `calc()` 百分比技巧
- 使用最大宽度约束限制布局（例如居中的 1400px）
- 全高区域必须使用 `min-h-[100dvh]`——绝不使用 `h-screen`（会导致 iOS Safari 出现灾难性的跳动）

### 7. 定义响应式规则
每个设计都必须适配所有视口：
- **移动优先折叠（< 768px）：**所有多列布局都折叠为单列，无一例外
- **禁止水平滚动：**移动端出现水平溢出属于严重故障
- **字体排印缩放：**标题通过 `clamp()` 缩放。正文字号最小为 `1rem`/`14px`
- **触控目标：**所有交互元素的最小点击区域为 `44px`
- **图像行为：**行内字体排印图像（单词之间的照片）在移动端堆叠到标题下方
- **导航：**桌面端水平导航折叠为简洁的移动端菜单
- **间距：**垂直区域间距按比例缩小（`clamp(3rem, 8vw, 6rem)`）

### 8. 编码动效理念
- **默认弹簧物理：**`stiffness: 100, damping: 20`——呈现高端、稳重的质感。不得使用线性缓动
- **持续微交互：**每个活动组件都应具备无限循环状态（脉冲、打字机、浮动、微光）
- **交错编排：**绝不瞬间挂载列表——使用级联延迟实现瀑布式显现
- **性能：**仅通过 `transform` 和 `opacity` 制作动画。绝不对 `top`、`left`、`width`、`height` 制作动画。颗粒/噪点滤镜只能用于固定定位的伪元素

### 9. 列出反模式（AI 痕迹）
在 DESIGN.md 中将以下内容编码为明确的“绝对不要”规则：
- 任何地方都不得使用表情符号
- 不得使用 `Inter` 字体
- 不得使用通用衬线字体（`Times New Roman`、`Georgia`、`Garamond`）——仅在需要时使用具有辨识度的现代衬线字体
- 不得使用纯黑色（`#000000`）
- 不得使用霓虹/外发光阴影
- 不得使用饱和度过高的强调色
- 不得在大标题中过度使用渐变文字
- 不得使用自定义鼠标光标
- 元素不得重叠——始终保持清晰的空间分隔
- 不得使用三列等宽卡片布局
- 不得使用通用名称（“John Doe”“Acme”“Nexus”）
- 不得使用虚假的整数值（`99.99%`、`50%`）
- 不得使用 AI 文案陈词滥调（“Elevate”“Seamless”“Unleash”“Next-Gen”）
- 不得使用填充性 UI 文本：“滚动探索”“向下滑动”、滚动箭头、弹跳箭头
- 不得使用失效的 Unsplash 链接——使用 `picsum.photos` 或 SVG 头像
- 不得使用居中的首屏区域（针对高变化度项目）

## 输出格式（DESIGN.md 结构）

```markdown
# 设计系统：[项目标题]

## 1. 视觉主题与氛围
（生动描述情绪、密度、变化度和动效强度。
示例：“一个克制、如画廊般疏朗的界面，采用自信的非对称布局
和流畅的弹簧物理动效。整体氛围理性而温暖——如同一间
光线充足的建筑工作室。”）

## 2. 调色板与角色
- **画布白** (#F9FAFB) — 主要背景表面
- **纯净表面** (#FFFFFF) — 卡片和容器填充色
- **炭黑墨色** (#18181B) — 主要文字，具有 Zinc-950 的深度
- **柔和钢灰** (#71717A) — 次要文字、描述、元数据
- **轻柔边框** (rgba(226,232,240,0.5)) — 卡片边框、1px 结构线
- **[强调色名称]** (#XXXXXX) — 用于 CTA、活动状态和焦点环的单一强调色
（最多 1 种强调色。饱和度 < 80%。不得使用紫色/霓虹色。）

## 3. 字体排印规则
- **展示文字：**[字体名称] — 紧凑字距、克制比例、由字重驱动的层级
- **正文：**[字体名称] — 宽松行距、最大宽度 65ch、中性的次要颜色
- **等宽字体：**[字体名称] — 用于代码、元数据、时间戳和高密度数字
- **禁用：**Inter，以及高端场景中的通用系统字体。仪表盘中禁用衬线字体。

## 4. 组件样式
* **按钮：**扁平、无外发光。激活时提供 -1px 位移的触感反馈。主要按钮使用强调色填充，次要按钮使用幽灵/轮廓样式。
* **卡片：**宽大的圆角（2.5rem）。柔和扩散的轻盈阴影。仅在抬升效果有助于表达层级时使用。高密度场景：使用顶部边框分隔线替代。
* **输入框：**标签在上，错误信息在下。焦点环使用强调色。不得使用浮动标签。
* **加载器：**使用与布局精确尺寸匹配的微光骨架屏。不得使用圆形加载动画。
* **空状态：**采用经过构图和插画设计的视觉组合——而不仅仅是“无数据”文本。

## 5. 布局原则
（以网格优先的响应式架构。首屏区域采用非对称分割。
在 768px 以下严格折叠为单列。使用最大宽度限制。
不得使用 Flexbox 百分比数学计算。采用宽裕的内部留白。）

## 6. 动效与交互
（所有交互元素均使用弹簧物理。采用交错级联显现。
活动的仪表盘组件使用持续微循环。仅使用硬件加速的
变换。对于 CPU 密集型动画，使用隔离的客户端组件。）

## 7. 反模式（禁用）
（明确列出禁用模式：不得使用表情符号、Inter、纯黑色、
霓虹辉光、三列等宽网格、AI 文案陈词滥调、
通用占位名称或失效的图像链接。）
```

## 最佳实践
- **具有描述性：**使用“深炭黑墨色（#18181B）”——而不仅仅是“深色文字”
- **具有功能性：**说明每个元素的用途
- **保持一致：**整份文档使用相同术语
- **保持精确：**包含准确的十六进制代码、rem 值和括号内的像素值
- **立场鲜明：**这不是中性模板——它强制执行一种明确的高端美学

## 成功秘诀
1. 从氛围入手——在细化令牌之前先理解整体感觉
2. 寻找模式——识别一致的间距、尺寸和样式
3. 进行语义化思考——按照用途而非仅按外观命名颜色
4. 考虑层级——记录视觉重量如何传达重要性
5. 编码禁令——反模式与规则本身同样重要

## 应避免的常见陷阱
- 使用未经解释的技术术语（使用“宽大的圆角”，而不是“rounded-xl”）
- 遗漏十六进制代码，或只使用描述性名称
- 忘记设计元素的功能角色
- 氛围描述过于模糊
- 忽视反模式列表——正是这些规则让输出显得高端
- 默认采用通用的“安全”设计，而不是强制执行精心策划的美学
