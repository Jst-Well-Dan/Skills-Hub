# 重新设计技能

## 工作方式

应用于现有项目时，请遵循以下顺序：

1. **扫描** — 阅读代码库。识别框架、样式方案（Tailwind、原生 CSS、styled-components 等）和当前的设计模式。
2. **诊断** — 按照下方清单进行审查。列出发现的所有常见模式、薄弱环节和缺失状态。
3. **修复** — 使用现有技术栈进行有针对性的升级。不要从头重写。改进已有内容。

## 设计审查

### 字体排印

检查并修复以下问题：

- **到处使用浏览器默认字体或 Inter。** 替换为更具个性的字体。不错的选择包括：`Geist`、`Outfit`、`Cabinet Grotesk`、`Satoshi`。对于编辑型或创意型项目，可将衬线标题字体与无衬线正文字体搭配使用。
- **标题缺乏存在感。** 增大展示文字的字号，收紧字间距，减小行高。标题应显得厚重且经过精心设计。
- **正文过宽。** 将段落宽度限制在大约 65 个字符。增加行高以提升可读性。
- **只使用 Regular (400) 和 Bold (700) 字重。** 引入 Medium (500) 和 SemiBold (600)，建立更细腻的层级。
- **数字使用比例字体。** 对数据密集型界面使用等宽字体，或启用等宽数字（`font-variant-numeric: tabular-nums`）。
- **缺少字间距调整。** 大标题使用负字距，小型大写文字或标签使用正字距。
- **到处都是全大写副标题。** 尝试改用小写斜体、句首字母大写或小型大写字母。
- **孤行单词。** 单个单词独占最后一行。使用 `text-wrap: balance` 或 `text-wrap: pretty` 修复。

### 颜色与表面

- **纯 `#000000` 背景。** 替换为近黑色、深炭灰或带色调的深色（`#0a0a0a`、`#121212` 或深海军蓝）。
- **强调色饱和度过高。** 将饱和度保持在 80% 以下。降低强调色的饱和度，使其与中性色融合，而不是显得刺眼。
- **使用多个强调色。** 只选一个，移除其余颜色。一致性胜过多样性。
- **混用暖灰色与冷灰色。** 坚持使用同一灰色系。为所有灰色赋予一致的色调（暖色或冷色，不要两者混用）。
- **紫色/蓝色的“AI 渐变”美学。** 这是最常见的 AI 设计特征。替换为中性色基底和一个经过慎重选择的强调色。
- **通用的 `box-shadow`。** 调整阴影色调，使其与背景色相匹配。使用彩色阴影（例如蓝色背景上的深蓝色阴影），而不是低透明度的纯黑色。
- **完全没有纹理的扁平化设计。** 为背景添加细微的噪点、颗粒或微图案。纯扁平矢量会显得冰冷。
- **完全均匀的渐变。** 使用径向渐变、噪点叠加或网格渐变打破均匀感，而不是标准的 45 度线性渐变。
- **光照方向不一致。** 审查所有阴影，确保它们呈现出单一且一致的光源方向。
- **浅色模式页面中随机出现深色区块（或反之）。** 在整体为浅色的页面中，单独出现一个深色背景区块，看起来像复制粘贴造成的意外。要么完整采用深色模式，要么在整个页面中保持一致的背景色调。如果需要对比，请使用同一色板中略深的色调，而不是在奶油色页面中间突然跳到 `#111`。
- **空洞、扁平且缺乏视觉深度的区块。** 仅由纯色背景上的文字组成的区块会显得尚未完成。添加高质量的背景图像（模糊、叠加或遮罩处理）、细微图案或环境渐变。缺少真实素材时，可使用 `https://picsum.photos/seed/{name}/1920/1080` 等可靠的占位图源。尝试在首屏区块、功能区块或 CTA 背后添加背景图像——即使只是一张低透明度的全宽照片，也能增强存在感。

### 布局

- **所有内容都居中且对称。** 使用错位边距、混合宽高比，或在居中内容上方放置左对齐标题，以打破对称。
- **使用三个等宽卡片列作为功能行。** 这是最常见的 AI 布局。替换为双列之字形布局、非对称网格、横向滚动或瀑布流布局。
- **使用 `height: 100vh` 创建全屏区块。** 替换为 `min-height: 100dvh`，防止移动浏览器中的布局跳动（iOS Safari 视口问题）。
- **复杂的 flexbox 百分比计算。** 替换为 CSS Grid，以构建可靠的多列结构。
- **没有 max-width 容器。** 添加容器限制（约 1200-1440px）和自动外边距，避免内容在宽屏上从一端拉伸到另一端。
- **通过 flexbox 强制卡片等高。** 当内容长度不同时，允许高度变化或使用瀑布流布局。
- **所有元素使用统一的 border-radius。** 调整圆角大小：内部元素使用更紧凑的圆角，容器使用更柔和的圆角。
- **没有重叠或深度。** 元素彼此平铺。使用负外边距创造层叠效果和视觉深度。
- **上下内边距对称。** 顶部和底部内边距总是完全相同。根据视觉效果调整——底部内边距通常需要略大一些。
- **仪表盘总是使用左侧边栏。** 尝试顶部导航、浮动命令菜单或可折叠面板。
- **缺少留白。** 将间距增加一倍。让设计拥有呼吸空间。密集布局适合数据仪表盘，不适合营销页面。
- **卡片组中的按钮未底部对齐。** 当卡片内容长度不同时，CTA 会出现在参差不齐的高度。将按钮固定在每张卡片的底部，使其无论上方内容多少，都能形成整齐的水平线。
- **功能列表从不同的垂直位置开始。** 在定价表或对比卡片中，所有列的功能列表都应从相同的 Y 轴位置开始。在列表上方使用一致的间距，或为标题/价格区块设置固定高度。
- **并排元素的垂直节奏不一致。** 并排放置卡片、列或面板时，应对齐所有项目中的共有元素（标题、描述、价格、按钮）。基线错位会让布局显得残缺。
- **数学上对齐，但视觉上不正确。** 数学意义上的居中并不总能让人眼觉得居中。文字旁的图标、圆形中的播放按钮或按钮中的文字，通常需要进行 1-2px 的视觉微调才能显得恰到好处。

### 交互与状态

- **按钮没有悬停状态。** 悬停时添加背景变化、轻微缩放或位移。
- **没有激活/按下反馈。** 按下时添加轻微的 `scale(0.98)` 或 `translateY(1px)`，模拟实体点击效果。
- **过渡瞬间完成，持续时间为零。** 为所有交互元素添加平滑过渡（200-300ms）。
- **缺少焦点环。** 确保键盘导航时显示清晰的焦点指示器。这是无障碍要求，不是可选项。
- **没有加载状态。** 使用与布局形状匹配的骨架屏，替换通用的圆形加载指示器。
- **没有空状态。** 空无一物的仪表盘浪费了引导用户的机会。设计一个完整的“开始使用”视图。
- **没有错误状态。** 为表单添加清晰的行内错误消息。不要使用 `window.alert()`。
- **无效链接。** 按钮链接到 `#`。要么链接到真实目标，要么在视觉上将其禁用。
- **导航中没有当前页面指示。** 为活动导航链接使用不同样式，让用户知道自己当前所在的位置。
- **滚动跳跃。** 点击锚点后会瞬间跳转。添加 `scroll-behavior: smooth`。
- **动画使用 `top`、`left`、`width`、`height`。** 改用 `transform` 和 `opacity`，实现 GPU 加速的平滑动画。

### 内容

- **使用“John Doe”或“Jane Smith”等通用姓名。** 使用多样且听起来真实的姓名。
- **使用 `99.99%`、`50%`、`$100.00` 等虚假的整数数据。** 使用更自然、不规整的数据：`47.2%`、`$99.00`、`+1 (312) 847-1928`。
- **使用“Acme Corp”“Nexus”“SmartFlow”等占位公司名称。** 根据上下文虚构可信的品牌名称。
- **AI 文案陈词滥调。** 绝不要使用“Elevate”“Seamless”“Unleash”“Next-Gen”“Game-changer”“Delve”“Tapestry”或“In the world of...”。使用朴素、具体的语言。
- **成功消息中使用感叹号。** 删除感叹号。保持自信，不要喧闹。
- **使用“Oops!”错误消息。** 直接说明：“Connection failed. Please try again.”
- **使用被动语态。** 使用主动语态：用“We couldn't save your changes”代替“Mistakes were made.”
- **所有博客文章日期都相同。** 随机设置日期，使其看起来真实。
- **多个用户使用同一张头像图片。** 为每个不同的人使用独特的素材。
- **Lorem Ipsum。** 绝不要使用拉丁文占位文本。编写真实的草稿文案。
- **每个标题都使用标题式大小写。** 改用句首字母大写。

### 组件模式

- **通用卡片外观（边框 + 阴影 + 白色背景）。** 移除边框，或只使用背景色，或只使用间距。只有当层级高度能够传达信息层级时，卡片才有存在的必要。
- **总是使用一个填充按钮 + 一个幽灵按钮。** 添加文本链接或第三级样式，减少视觉噪音。
- **药丸形的“New”和“Beta”徽章。** 尝试方形徽章、旗帜或纯文本标签。
- **手风琴式 FAQ 区块。** 使用并排列表、可搜索帮助或行内渐进式披露。
- **带圆点的三卡片轮播式用户评价。** 替换为瀑布流评价墙、嵌入式社交媒体帖子或单条轮换引语。
- **三塔式定价表。** 使用颜色和强调效果突出推荐层级，而不只是增加高度。
- **所有操作都使用模态框。** 对于简单操作，使用行内编辑、侧滑面板或可展开区块代替弹窗。
- **头像一律使用圆形。** 尝试超椭圆或圆角方形，减少千篇一律的感觉。
- **浅色/深色切换始终使用太阳/月亮开关。** 使用下拉菜单、系统偏好检测，或将其整合到设置中。
- **页脚使用四列链接农场。** 简化它。聚焦主要导航路径和法律要求的链接。

### 图标设计

- **只使用 Lucide 或 Feather 图标。** 它们是 AI 的“默认”图标选择。使用 Phosphor、Heroicons 或自定义图标集来体现差异。
- **使用火箭表示“Launch”，使用盾牌表示“Security”。** 用不那么直白的图标（闪电、指纹、火花、保险库）替换陈词滥调式的隐喻。
- **图标之间的描边宽度不一致。** 审查所有图标，并统一为同一种描边粗细。
- **缺少 favicon。** 始终包含品牌化的 favicon。
- **图库式“多元化团队”照片。** 使用真实的团队照片、抓拍照片或统一的插画风格，代替不自然的图库图片。

### 代码质量

- **Div 堆砌。** 使用语义化 HTML：`<nav>`、`<main>`、`<article>`、`<aside>`、`<section>`。
- **行内样式与 CSS 类混用。** 将所有样式移入项目的样式系统。
- **硬编码像素宽度。** 使用相对单位（`%`、`rem`、`em`、`max-width`）实现灵活布局。
- **图像缺少 alt 文本。** 为屏幕阅读器描述图像内容。对于有意义的图像，绝不要使用 `alt=""` 或 `alt="image"`。
- **使用 `9999` 等任意 z-index 值。** 在主题/变量中建立清晰的 z-index 层级。
- **注释掉的废弃代码。** 发布前删除所有调试残留。
- **虚构导入。** 检查每个导入项是否确实存在于 `package.json` 或项目依赖中。
- **缺少 meta 标签。** 添加适当的 `<title>`、`description`、`og:image` 和社交分享 meta 标签。

### 策略性遗漏（AI 通常会忘记的内容）

- **没有法律链接。** 在页脚中添加隐私政策和服务条款链接。
- **没有“返回”导航。** 用户流程中存在死路。每个页面都需要提供返回方式。
- **没有自定义 404 页面。** 设计一个实用且品牌化的“找不到页面”体验。
- **没有表单验证。** 为电子邮件、必填字段和格式检查添加客户端验证。
- **没有“跳至内容”链接。** 这对键盘用户至关重要。添加隐藏的跳转链接。
- **没有 Cookie 同意机制。** 如果所在司法辖区要求，请添加合规的同意横幅。

## 升级技巧

升级项目时，从以下高影响力技巧中选择，用来替换通用模式：

### 字体排印升级

- **可变字体动画。** 在滚动或悬停时对字重或字宽进行插值，让文字充满生命力。
- **从轮廓到填充的过渡。** 文字最初以描边轮廓显示，在滚动进入视口或发生交互时填充颜色。
- **文字遮罩揭示。** 使用大型文字作为窗口，展示其背后的视频或动态图像。

### 布局升级

- **破格网格/非对称设计。** 让元素有意忽略列结构——相互重叠、延伸至屏幕之外，或以经过计算的随机方式错位。
- **最大化留白。** 大胆使用负空间，迫使用户聚焦于单个元素。
- **视差卡片堆叠。** 区块在滚动时保持粘性定位，并在视觉上彼此堆叠。
- **分屏滚动。** 屏幕的两个半区向相反方向滑动。

### 动效升级

- **带惯性的平滑滚动。** 让滚动脱离浏览器默认行为，营造更厚重、更具电影感的体验。
- **错落入场。** 元素以轻微延迟依次出现，结合 Y 轴位移和透明度淡入。绝不要同时挂载所有元素。
- **弹簧物理效果。** 使用基于弹簧的运动替换线性缓动，让所有交互元素呈现自然、有重量感的效果。
- **滚动驱动的揭示效果。** 内容通过扩展遮罩、擦除效果或与滚动进度绑定的 SVG 路径绘制动画进入视图。

### 表面升级

- **真正的玻璃拟态。** 不要止步于 `backdrop-filter: blur`。添加 1px 内边框和细微的内阴影，模拟边缘折射。
- **聚光边框。** 卡片边框在光标下动态亮起。
- **颗粒与噪点叠加层。** 使用固定定位且设置为 pointer-events-none 的细微噪点叠加层，打破数字化的扁平感。
- **彩色、有色调的阴影。** 让阴影带有背景的色相，而不是使用通用的黑色。

## 修复优先级

按照以下顺序应用更改，以最低风险获得最大的视觉提升：

1. **更换字体** — 即时改善最明显，风险最低
2. **清理配色方案** — 移除冲突或饱和度过高的颜色
3. **悬停与激活状态** — 让界面充满活力
4. **布局与间距** — 使用适当的网格、max-width 和一致的内边距
5. **替换通用组件** — 用现代替代方案取代陈词滥调式的模式
6. **添加加载、空白和错误状态** — 让产品呈现完整感
7. **打磨字体层级与间距** — 实现高端质感的最后润色

## 规则

- 使用现有技术栈。不要迁移框架或样式库。
- 不要破坏现有功能。每次更改后都要测试。
- 导入任何新库之前，先检查项目的依赖文件。
- 如果项目使用 Tailwind，请在修改配置前检查版本（v3 与 v4）。
- 如果项目没有框架，请使用原生 CSS。
- 保持更改易于审查且目标明确。优先采用小型、针对性的改进，而不是大规模重写。
