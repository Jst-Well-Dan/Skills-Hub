# tasteskill：反粗制滥造前端技能

> 适用于落地页、作品集和重新设计。不适用于仪表盘、数据表格或多步骤产品 UI。
> 以下每条规则都取决于**具体情境**。没有任何规则会自动触发。先阅读需求说明，再只选取适用的内容。

---

## 0. 需求推断（做任何事之前先读懂情境）

在接触代码或调整参数之前，**先推断用户真正想要什么**。大多数 LLM 设计产出之所以糟糕，是因为模型没有理解情境就直接套用了默认审美。

### 0.A 首先读取这些信号
1. **页面类型** - 落地页（SaaS / 消费产品 / 代理机构 / 活动）、作品集（开发者 / 设计师 / 创意工作室）、重新设计（保留还是彻底改造）、编辑型页面 / 博客。
2. 用户使用的**氛围词** - “极简”“平静”“Linear 风格”“Awwwards”“粗野主义”“高端消费品牌”“Apple 感”“活泼”“严肃 B2B”“编辑感”“代理机构感”“玻璃质感”“暗黑科技”。
3. **参考信号** - 用户提供的 URL、粘贴的截图、提到的产品、竞争品牌。
4. **受众** - B2B 采购评审组、注重设计的消费者，还是快速浏览作品集的招聘人员。应由受众决定审美，而不是你的个人品味。
5. **已有品牌资产** - 标志、颜色、字体、摄影素材。对于重新设计，这些是起始材料，不是可有可无的输入（参见第 11 节）。
6. **隐性约束** - 无障碍优先的受众、公共部门、受监管行业、信任优先的商业、儿童产品。这些约束的优先级**高于**审美偏好。

### 0.B 生成前输出一行“设计解读”
在编写任何代码前，用一行说明：**“我将其理解为：面向 \<audience> 的 \<page kind>，采用 \<vibe> 语言，倾向于 \<design system or aesthetic family>。”**

解读示例：
- *“我将其理解为：面向技术买家的 B2B SaaS 落地页，采用 Linear 风格的极简语言，倾向于 Tailwind 工具类 + Geist + 克制的动效。”*
- *“我将其理解为：面向招聘经理的独立设计师作品集，采用编辑感 / 动态字体语言，倾向于原生 CSS + 滚动驱动动画 + 定制字体。”*
- *“我将其理解为：公共部门服务网站的重新设计，采用信任优先的语言，倾向于 GOV.UK Frontend 或 USWDS。”*

### 0.C 如果需求含糊，只问一个问题，不要猜
只提出**一个**澄清问题，绝不要一次抛出多个问题，并且仅在设计解读确实会产生明显分歧时提问。例如：*“你希望它更接近 Linear 式简洁，还是 Awwwards 式实验感？”*

如果可以根据上下文自信推断，**不要提问**。直接声明设计解读并继续。

### 0.D 反默认纪律
不要默认使用：AI 紫色渐变、暗色网格背景上的居中首屏、三个等宽功能卡片、所有地方都套通用玻璃拟态、随处可见的无限循环微动画、Inter + slate-900。这些都是 LLM 的默认套路。应根据设计解读，有意识地越过这些默认选项。

## 1. 三个旋钮（核心配置）

完成设计解读后，设置三个旋钮。下文所有布局、动效和密度决策都受它们控制。

* **`DESIGN_VARIANCE: 8`** - 1 = 完美对称，10 = 艺术化混沌
* **`MOTION_INTENSITY: 6`** - 1 = 静态，10 = 电影级 / 物理效果
* **`VISUAL_DENSITY: 4`** - 1 = 艺术画廊 / 通透，10 = 驾驶舱 / 数据密集

**基准值：**`8 / 6 / 4`。除非设计解读要求覆盖，否则使用这些值。不要要求用户编辑此文件，覆盖应通过对话完成。

### 1.A 旋钮推断（设计解读 → 旋钮值）
| 信号 | VARIANCE | MOTION | DENSITY |
|---|---|---|---|
| “极简 / 简洁 / 平静 / 编辑感 / Linear 风格” | 5-6 | 3-4 | 2-3 |
| “高端消费品牌 / Apple 感 / 奢华 / 品牌” | 7-8 | 5-7 | 3-4 |
| “活泼 / 狂野 / Dribbble / Awwwards / 实验性 / 代理机构” | 9-10 | 8-10 | 3-4 |
| “落地页 / 作品集 / 营销网站（默认）” | 7-9 | 6-8 | 3-5 |
| “信任优先 / 公共部门 / 受监管 / 无障碍关键” | 3-4 | 2-3 | 4-5 |
| “重新设计 - 保留” | 匹配现有值 | +1 | 匹配现有值 |
| “重新设计 - 彻底改造” | +2 | +2 | 匹配现有值 |

### 1.B 用例预设
| 用例 | VARIANCE | MOTION | DENSITY |
|---|---|---|---|
| 落地页（SaaS，主流） | 7 | 6 | 4 |
| 落地页（代理机构 / 创意） | 9 | 8 | 3 |
| 落地页（高端消费品牌） | 7 | 6 | 3 |
| 作品集（设计师 / 工作室） | 8 | 7 | 3 |
| 作品集（开发者） | 6 | 5 | 4 |
| 编辑型页面 / 博客 | 6 | 4 | 3 |
| 公共部门服务 | 3 | 2 | 5 |
| 重新设计 - 保留 | 匹配 | 匹配值+1 | 匹配 |
| 重新设计 - 彻底改造 | +2 | +2 | 匹配 |

### 1.C 旋钮如何驱动输出
将这些值（或用户覆盖后的值）作为全局变量使用。本文中的交叉引用均指向这些确切的变量名，绝不要发明 `LAYOUT_VARIANCE` 或 `ANIM_LEVEL` 之类的别名。

## 2. 需求 → 设计系统映射

获得设计解读（第 0 节）和旋钮值（第 1 节）后，选择正确的基础。对于已有官方软件包的内容，不要自行编写 CSS。不要假装某种审美趋势是官方设计系统。

### 2.A 何时采用真正的设计系统（使用官方软件包）
| 需求解读为…… | 采用 | 原因 |
|---|---|---|
| Microsoft / 企业 SaaS / 仪表盘 | `@fluentui/react-components` 或 `@fluentui/web-components` | 官方 Fluent UI、Microsoft 令牌、已处理无障碍 |
| Google 风格 UI、Material 风格产品 | `@material/web` + Material 3 令牌 | 官方方案，可通过 Material Theming 设置主题 |
| IBM 风格 B2B / 企业分析 | `@carbon/react` + `@carbon/styles` | 官方 Carbon，成熟的数据密度模式 |
| Shopify 应用界面 | `polaris.js` Web Components / Polaris React | Shopify 管理界面的必需方案 |
| Atlassian / Jira 风格产品 | `@atlaskit/*` + `@atlaskit/tokens` | 官方 Atlassian DS |
| GitHub 风格开发工具 / 社区页面 | `@primer/css` 或 `@primer/react-brand` | 官方 Primer；Brand 变体适用于营销 |
| 英国公共部门服务 | `govuk-frontend` | 法律 / 监管层面的预期 |
| 美国公共部门 / 信任优先 | `uswds` | 同上 |
| 快速交付的本地企业 / 代理机构 MVP | Bootstrap 5.3 | 朴素、快速、有效 |
| 现代、无障碍的 React 基础 | `@radix-ui/themes` | 原语 + 精致主题 |
| 自主管理组件的现代 SaaS | shadcn/ui (`npx shadcn@latest add ...`) | 代码归你所有，易于定制；绝不要按默认状态交付 |
| 基于 Tailwind 的现代 SaaS / AI 营销页面 | Tailwind v4 工具类 + `dark:` 变体 | 独立开发者和小团队构建的默认方案 |

**诚实规则：**如果需求符合上述某个系统，应安装并使用其**官方**软件包。不要手工重建它的 CSS。不要导入某个系统的令牌后又覆盖其中 90%。

**每个项目只使用一个系统。**不要在同一组件树中混用 Fluent React 和 Carbon。不要把 shadcn/ui 组件导入 Material 3 应用。

### 2.B 当需求是一种审美，而不是一个系统时
以下方向**没有单一官方软件包**。使用原生 CSS + Tailwind + 维护良好的组件库构建。在代码注释中如实说明哪些内容只是借鉴灵感，哪些是官方材料。

| 审美 | 诚实的实现方式 |
|---|---|
| 玻璃拟态 / “磨砂玻璃” | `backdrop-filter`、分层边框、高光叠层。为 `prefers-reduced-transparency` 提供纯色填充回退。 |
| Bento（Apple 风格瓷砖网格） | 使用不同单元格尺寸的 CSS Grid。没有任何单一库拥有这种风格。 |
| 粗野主义 | 原生 CSS、等宽字体、原始边框。无专用库。 |
| 编辑感 / 杂志 | 衬线字体、非对称网格、充足留白。无专用库。 |
| 暗黑科技 / 黑客 | 等宽字体 + 霓虹强调色、终端意象。无专用库。 |
| 极光 / 网格渐变 | SVG 或分层径向渐变。无专用库。 |
| 动态字体 | 原生 CSS 动画、滚动驱动动画，劫持式滚动使用 GSAP。无专用库。 |
| **Apple Liquid Glass** | Apple 仅针对 Apple 平台记录了这项技术。**不存在官方 `liquid-glass.css`。**Web 实现是使用 `backdrop-filter` + 分层边框 + 高光构成的近似效果。必须明确标注为近似实现。 |

## 3. 默认架构与约定

除非设计解读选择了真正的设计系统（第 2.A 节），否则使用以下默认方案：

### 3.A 技术栈
* **框架：**React 或 Next.js。默认使用 Server Components (RSC)。
  * **RSC 安全：**全局状态只能在 Client Components 中工作。在 Next.js 中，应使用带有 `"use client"` 的组件包裹 provider。
  * **交互隔离：**任何使用 Motion、滚动监听器或指针物理效果的组件，都必须是隔离的叶子组件，并在顶部添加 `'use client'`。Server Components 只渲染静态布局。
* **样式：****Tailwind v4**（默认）。仅当现有项目要求时才使用 Tailwind v3。
  * 对于 v4：不要在 `postcss.config.js` 中使用 `tailwindcss` 插件。应使用 `@tailwindcss/postcss` 或 Vite 插件。
* **动画：****Motion**（原名 Framer Motion 的库）。从 `motion/react` 导入（`import { motion } from "motion/react"`）。`framer-motion` 软件包仍可作为旧别名工作，新代码优先使用 `motion/react`。
* **字体：**始终使用 `next/font`（Next.js），或通过 `@font-face` + `font-display: swap` 自托管。生产环境中绝不要通过 `<link>` 引用 Google Fonts。

### 3.B 状态
* 隔离 UI 使用局部 `useState` / `useReducer`。
* 仅为避免深层 prop 传递时才使用全局状态，可选 Zustand、Jotai 或 React context。
* **绝不要**用 `useState` 跟踪由用户输入持续驱动的值（鼠标位置、滚动进度、指针物理效果、磁性悬停）。应使用 Motion 的 `useMotionValue` / `useTransform` / `useScroll`。`useState` 会在每次变化时重新渲染 React 树，并在移动端崩溃。

### 3.C 图标
* **允许使用的库（按优先级排序）：**`@phosphor-icons/react`、`hugeicons-react`、`@radix-ui/react-icons`、`@tabler/icons-react`。
* **不推荐：**`lucide-react`。仅当用户明确要求或项目已经依赖它时才可接受。
* **绝不要手工绘制 SVG 图标。**如果缺少某个图形，安装第二个库或使用原语组合，不要从头绘制图标路径。
* **每个项目只使用一个图标系列。**不要在同一组件树中混用 Phosphor 和 Lucide。
* 在全局统一 `strokeWidth`（例如 `1.5` 或 `2.0`）。

### 3.D Emoji 政策
默认不建议在代码、标记和可见文本中使用 Emoji。用图标库中的图形替换符号。**例外：**仅当用户明确要求活泼 / 聊天式 / 原生社交媒体氛围时允许使用 Emoji，即便如此也应少量且有目的地使用。

### 3.E 响应式与布局机制
* 统一断点（`sm 640`、`md 768`、`lg 1024`、`xl 1280`、`2xl 1536`）。
* 使用 `max-w-[1400px] mx-auto` 或 `max-w-7xl` 约束页面布局。
* **视口稳定性：**全高 Hero 区域绝不要使用 `h-screen`。始终使用 `min-h-[100dvh]`，避免移动端（iOS Safari 地址栏）发生布局跳动。
* **网格优先于 Flex 数学计算：**绝不要使用复杂的 flexbox 百分比计算（`w-[calc(33%-1rem)]`）。始终使用 CSS Grid（`grid grid-cols-1 md:grid-cols-3 gap-6`）。

### 3.F 依赖验证（强制）
在导入任何第三方库前，检查 `package.json`。如果缺少该软件包，先输出安装命令。**绝不要**假设某个库已经存在。

## 4. 设计工程指令（偏差纠正）

LLM 默认会产出陈词滥调。应主动覆盖这些默认倾向。每条规则都有根据上下文调整的路径。

### 4.1 字体排印
* **展示文字 / 标题：**默认使用 `text-4xl md:text-6xl tracking-tighter leading-none`。
* **正文 / 段落：**默认使用 `text-base text-gray-600 leading-relaxed max-w-[65ch]`。
* **无衬线字体选择：**
  * **不建议作为默认项：**`Inter`。优先选择 `Geist`、`Outfit`、`Cabinet Grotesk`、`Satoshi` 或适合品牌的衬线字体。
  * **例外：**当用户明确要求中性 / 标准 / Linear 风格，或需求属于公共部门 / 无障碍优先网站时，可以使用 Inter。
* **应了解的搭配：**`Geist` + `Geist Mono`、`Satoshi` + `JetBrains Mono`、`Cabinet Grotesk` + `Inter Tight`、`GT America` + `IBM Plex Mono`。

* **衬线字体纪律（非常不建议作为默认项）：**
  * 对任何项目而言，都**非常不建议将衬线字体作为默认字体**。“它感觉有创意 / 高端 / 编辑感”不是使用衬线字体的理由。智能体默认认为“创意需求 = 衬线字体”，这是生产测试中最常见的 AI 痕迹。
  * **只有明确满足以下任一条件时，才可以使用衬线字体：**
    - 品牌需求明确指定了一种衬线字体，或者
    - 审美体系确实属于编辑 / 奢华 / 出版物 / 手稿 / 传统 / 复古，并且你能够说明为什么这种特定衬线字体适合这个特定品牌
  * 对于其他所有类型（创意代理机构、设计工作室、现代品牌、高端消费品牌、作品集、生活方式），**默认使用无衬线展示字体**（Geist Display、ABC Diatype、Söhne Breit、Cabinet Grotesk Display、Migra Sans、GT Walsheim、Inter Display、PP Neue Montreal）。无衬线展示字体并不“无聊”，它成为默认项的原因与黑色成为时尚界默认色的原因相同。
  * **强调规则（相关）：**需要强调标题中的某个词时（例如动态排版中的“and `spatial` design”），使用**同一字体的斜体或粗体**。不要为了增加视觉趣味，在无衬线标题中突然插入一个衬线词，反之亦然。混用字体系列进行强调显得业余。同一字体系列内使用斜体或粗体才是正确做法。
  * **明确禁止作为默认项：**`Fraunces` 和 `Instrument_Serif`（LLM 最偏爱的两种展示衬线字体）。
  * **如果确实有理由使用衬线字体**（根据上述要求，这种情况很少），从以下字体池轮换选择，不要连续两个项目重复使用同一种衬线字体：PP Editorial New、GT Sectra Display、Cardinal Grotesque、Reckless Neue、Tiempos Headline、Recoleta、Cormorant Garamond、Playfair Display、EB Garamond、IvyPresto、Migra、Editorial Old、Saol Display、Söhne Breit Kursiv、Domaine Display、Canela、Schnyder、Tobias、NB Architekt、ITC Galliard。

* **斜体下伸部留白（强制）：**展示字体使用斜体且单词包含下伸字母（`y g j p q`）时，`leading-[1]` 或 `leading-none` 会裁掉下伸部分。至少使用 `leading-[1.1]`，并在包裹元素上添加 `pb-1` 或 `mb-1` 预留空间。交付前检查展示标题中的每个斜体词。

### 4.2 色彩校准
* 最多使用 1 种强调色。默认饱和度 < 80%。
* **淡紫色规则：**不建议默认采用“AI 紫色 / 蓝色光晕”审美。不要自动添加紫色按钮光晕，不要使用随机霓虹渐变。应使用中性色基础（Zinc / Slate / Stone）搭配单一高对比强调色（Emerald、Electric Blue、Deep Rose、Burnt Orange 等）。
* **例外：**如果品牌或需求明确要求紫色 / 紫罗兰色 / 淡紫色，应充分使用。但要有意识地执行：保持一致的调色板、协调的中性色和克制的渐变。不要做成通用 AI 渐变垃圾。
* **每个项目只使用一套调色板。**同一项目中不要在暖灰和冷灰之间反复切换。
* **颜色一致性锁定（强制）：**页面选定一种强调色后，应在整个页面使用。暖灰色网站不能到第 7 个区段突然出现蓝色 CTA。玫红强调色网站不能在页脚突然出现青绿色状态徽章。选择一种强调色，锁定它，并在交付前检查每个组件。

* **高端消费品牌调色板禁令（强制，第二常见的 AI 痕迹）：**
  * 对于高端消费品牌需求（厨具、健康、手工艺、奢侈品、传统工艺、DTC 家居用品等），LLM 默认倾向于使用**暖米色/奶油色 + 黄铜色/陶土色/牛血色/赭色 + 浓缩咖啡色/墨色深色文字**。具体禁止将以下十六进制色系作为默认背景和强调色：
    - 背景：`#f5f1ea`、`#f7f5f1`、`#fbf8f1`、`#efeae0`、`#ece6db`、`#faf7f1`、`#e8dfcb`（全部属于“暖纸色 / 奶油色 / 粉笔色 / 骨白色”）
    - 强调色：`#b08947`、`#b6553a`、`#9a2436`、`#9c6e2a`、`#bc7c3a`、`#7d5621`（全部属于“黄铜色 / 陶土色 / 牛血色 / 赭色”）
    - 文字：`#1a1714`、`#1a1814`、`#1b1814`（全部属于“浓缩咖啡色 / 暖调近黑色”）
  * **禁止**将这套调色板作为高端消费品牌需求的默认选择。你过去交付的每个高端消费品牌网站都在使用这套完全相同的配色，品牌本身因此变得毫无辨识度。
  * **默认替代方案（轮换使用，不要重复）：**
    - **冷调奢华：**银灰 + 铬色 + 烟灰色（可以联想到 Tesla、没有皮革元素的 Apple Watch Hermes）
    - **森林：**深绿色 + 骨白色 + 琥珀强调色（可以联想到 Filson、Patagonia 高端线）
    - **黑色与棕褐色：**真正的近黑色 + 暖棕褐色，形成鲜明对比，不使用米色
    - **钴蓝 + 奶油色：**高饱和蓝色搭配单一中性色，不使用黄铜色
    - **陶土色 + 板岩色：**暖铁锈色搭配冷灰色，不使用黄铜色
    - **橄榄绿 + 砖红 + 纸白：**柔和橄榄绿搭配砖红强调色
    - **纯单色 + 单一高饱和亮色：**灰白 + 近黑 + 一种明亮强调色（电光蓝、翡翠绿、亮粉色等）
  * **调色板轮换规则：**如果你生成的上一个高端消费品牌项目使用了米色+黄铜色系，这个项目**必须**使用其他色系。不要连续两次交付同一种暖调手工艺配色。
  * **例外：**只有当品牌需求明确指定这些颜色，或品牌身份确实属于复古 / 手工艺 / 暖调工艺，并且你能够说明为什么这套特定配色适合这个特定品牌时，才可以使用米色+黄铜色+浓缩咖啡色调色板。因为“这是厨具需求”就默认采用它是被禁止的。

### 4.3 布局多样化
* **反居中偏差：**当 `DESIGN_VARIANCE > 4` 时，避免居中的 Hero / H1 区域。强制采用“分屏”（50/50）、“内容左对齐 / 素材右对齐”、“非对称留白”或滚动固定结构。
* **例外：**对于编辑型 / 宣言式 / 发布公告类需求，信息本身就是设计，此时可以使用居中 Hero。

### 4.4 材质感、阴影和卡片
* 仅在层级提升能够表达真实信息层级时使用卡片。否则使用 `border-t`、`divide-y` 或留白进行分组。
* 使用阴影时，应根据背景色调为阴影着色。浅色背景上不要使用纯黑色投影。
* 当 `VISUAL_DENSITY > 7` 时，禁止使用通用卡片容器。数据指标应在开放布局中留有呼吸空间。
* **形状一致性锁定（强制）：**为页面选择一种圆角尺度并始终坚持。可选方案：全部直角（半径 0）、全部柔和（半径 12-16px）、全部胶囊形（交互元素使用完整圆角）。只有在记录了明确规则时才允许混合系统（例如“按钮使用完整胶囊形，卡片为 16px，输入框为 8px”），并且必须处处遵守该规则。在方形布局中使用圆形按钮，或在胶囊按钮页面上使用方形卡片，都属于设计错误。

### 4.5 交互式 UI 状态
LLM 默认只实现“静态成功状态”。始终实现完整状态周期：
* **加载：**使用与最终布局形状匹配的骨架加载器。避免通用圆形加载指示器。
* **空状态：**精心组织，并说明如何填充内容。
* **错误状态：**清晰显示，表单使用内联错误，只有瞬时错误才使用上下文 Toast。
* **触觉反馈：**在 `:active` 状态下使用 `-translate-y-[1px]` 或 `scale-[0.98]` 模拟实体按压。
* **按钮对比度检查（强制，无障碍）：**交付任何按钮前，确认按钮文字在按钮背景上清晰可读。白色按钮 + 白色文字、带 `text-white` 标签的 `bg-white` CTA、与页面背景融为一体且没有边框的透明按钮，全部禁止。检查每个 CTA：对比度至少达到 WCAG AA（正文 4.5:1，18px+ 大号文字 3:1）。摄影背景上的幽灵按钮也适用同一规则（使用背景层、遮罩或描边）。
* **CTA 按钮换行禁令（强制）：**桌面端按钮文字必须保持单行。如果“VIEW SELECTED WORK”这样的标签换成 2 行或 3 行，按钮就是坏的。修复方式二选一：缩短标签（主 CTA 最多 3 个单词，最好 1-2 个），或加宽按钮（不要人为限制 CTA 的 `max-width`）。桌面端 CTA 换行属于交付前检查失败。
* **禁止重复 CTA 意图（强制）：**同一页面中出现两个意图相同的 CTA 属于交付前检查失败。相同意图示例：“Get in touch” + “Contact us” + “Let's talk” + “Start a project” + “Start something” + “Reach out”全部表示“联系”意图，应选择**一个**标签并在整个页面（导航、Hero、页脚）统一使用。“Try free” + “Get started” + “Sign up free”（全部表示“注册”意图），以及“View work” + “See selected work” + “Browse projects”（全部表示“浏览作品集”意图）同理。每种意图只使用一个标签。
* **表单对比度检查（强制，无障碍）：**表单输入框、占位文字、焦点环、辅助文字和错误文字，相对于区段背景都必须达到 WCAG AA 对比度。近白色表单中的浅色占位文字、白色页面区段上的白色表单、对比度低于 4.5:1 的灰色表单标签，全部禁止。交付前检查每个表单。

### 4.6 数据与表单模式
* 标签置于输入框上方。辅助文字可选，但应存在于标记中。错误文字置于输入框下方。输入块统一使用 `gap-2`。
* 绝不要用占位文字代替标签。

### 4.7 布局纪律（硬性规则。违反其中任何一条都意味着交付了损坏的作品）

* **Hero 必须完整容纳在初始视口中。**桌面端标题最多 2 行，副文案最多 **20 个单词**且最多 3-4 行，无需滚动即可看到 CTA。如果文案太长：缩小字体尺寸或删减文案。如果无法用 20 个单词的副文案描述价值主张，说明价值主张不清晰，而不是规则过于严格。绝不要让 Hero 溢出，迫使用户滚动寻找 CTA。
* **Hero 字体尺寸纪律。**应同时规划字体尺寸和图片尺寸。如果 Hero 素材较大且标题超过 6 个单词，不要从 `text-7xl/text-8xl` 开始。多数 Hero 合理的默认范围为 `text-4xl md:text-5xl lg:text-6xl`；只有标题为 3-5 个单词时才使用 `text-6xl md:text-7xl`。Hero 标题出现 4 行永远是字体尺寸错误，而不是文案长度错误。
* **Hero 顶部内边距上限（强制）：**桌面端 Hero 顶部内边距最多为 `pt-24`（约 6rem）。超过该值会使 Hero 内容漂浮在视口中部，看起来像布局错误，而非有意留白。如果 Hero 需要更多呼吸空间，应增加字体尺寸或素材尺寸，而不是顶部内边距。
* **Hero 堆叠纪律（最多 4 个文本元素）。**Hero 是一个统一时刻，不是功能列表。允许的文本元素总数最多为 4：
  1. 眉题（小号大写标签）或品牌条，或两者都不使用，只能选择零个或一个
  2. 标题（最多 2 行，见上文）
  3. 副文案（最多 20 个单词，最多 4 行）
  4. CTA（1 个主要 + 最多 1 个次要）
  - **Hero 中禁止：**CTA 下方的小号标语（“Works with GitHub, GitLab, and self-hosted Git”）、信任微型条（“Used by engineering teams at...”）、定价预告（“Free for solo, $10/user for teams”）、功能要点列表、社会证明头像行。所有这些都应移至 Hero 正下方的专用区段。
  - 如果同一个 Hero 中同时有眉题和 CTA 下方标语，应删除标语。如果同时有品牌条和标语，也应删除标语。每个 Hero 最多一个小型文本元素。
* **“Used by” / “Trusted by”标志墙应放在 Hero 下方，绝不能放在其中。**Hero 用于价值主张和主要 CTA。标志墙是紧接其下的独立区段。不要把信任标志塞进 Hero 文案所在的同一个 flex 行。
* **桌面端导航必须单行显示。**如果项目在 `lg`（1024px）下无法放入一行，应缩短标签、删除次要项目或改为汉堡菜单。桌面端两行导航属于损坏的设计。
* **导航高度上限：桌面端最多 80px，默认 64-72px。**不要使用占据视口 15% 的巨大“代理机构”式导航栏。
* **Bento 网格必须有节奏，不能单边重复。**不要堆叠 6 个“左图右文”行。应改变构图：交替使用全宽功能行、非对称瓷砖尺寸和纵向中断。
* **Bento 单元格数量规则（强制）：**Bento 网格的单元格数量必须与内容数量**完全一致**。3 项内容 → 3 个单元格（1+2、2+1 或非对称三联布局）。5 项内容 → 5 个单元格（2+3、3+2、主单元+4 等）。如果网格中间或末尾有空单元格，说明规划有误。重新塑造网格，不要粘贴空白瓷砖。
* **区段布局重复禁令。**某种布局系列用于一个区段后（例如三列图片卡片、全宽引语、文字图片分栏），在页面中最多只能出现一次。“精选委托项目”不能看起来和“我们的服务”一样。包含 8 个区段的落地页必须至少使用 4 种不同的布局系列。
* **之字形交替上限（强制）。**交替使用“左图 + 右文”和“左文 + 右图”的之字形布局很平庸。连续使用这种图文分栏模式最多 2 个区段。第 3 个连续图文分栏属于交付前检查失败。应使用全宽区段、纵向堆叠区段、Bento 网格、跑马灯或其他布局系列打破模式。
* **眉题克制（强制，生产测试中违反次数最多的规则）。**“眉题”是位于区段标题上方、使用小号大写宽字距的标签（例如 `FOUR COLORWAYS`、`SELECTED WORK`、`THE HARDWARE`、`Git-native task management`）。典型 CSS 特征：`text-[11px] uppercase tracking-[0.18em]`、`font-mono text-[10.5px] uppercase tracking-[0.22em]`。每个 AI 构建的网站都会在**每个**区段标题上方添加眉题，产生相同的模板化节奏。硬性规则：
  - **每 3 个区段最多 1 个眉题。**Hero 计为 1 个区段。因此，包含 9 个区段的页面最多只能使用 3 个眉题。
  - 如果区段 A 有眉题，之后 2 个区段不能使用眉题。
  - **交付前检查必须机械执行：**统计所有区段组件中 `uppercase tracking`（或标题上方类似的小型大写等宽标签）的实例。如果数量 > ceil(sectionCount / 3)，输出即为失败。
  - **眉题的替代方案：**直接删除。仅使用标题已经足够。如果需要对区段分类，它在页面中的位置已经完成了分类，不需要额外标签。
* **分栏式标题禁令（强制）。**默认**禁止**使用“左侧大标题 + 右侧小号说明段落”的区段标题模式（左侧 col-span-7/8，右侧 col-span-4/5，并有小号正文悬浮在右栏）。每个区段应只有**一个**聚焦信息。如果确实需要标题和说明段落，应纵向堆叠（标题在上，正文在下，最大宽度 65ch）。只有存在真正的构图理由时才使用分栏式标题模式（例如右栏承载视觉或交互元素，而不只是填充文字）。
* **Bento 背景多样性（强制）。**Bento 和功能网格区段不能是 6 个仅含文字的白底白卡片。任何多单元格网格中至少有 2-3 个单元格需要真正的视觉变化：真实图片、适合品牌的渐变（不是 AI 紫色）、图案、着色背景。只有字体内容的奶油色同色系 Bento 会显得像乏味的 AI 默认产物，即使页面其余部分不错。
* **每个区段都必须明确移动端折叠方式。**对于每个多列布局，都应在同一组件中声明 `< 768px` 时的回退方案。不要假设“它会工作，Tailwind 会处理”。

### 4.8 图片与视觉素材策略

落地页和作品集是**视觉产品**。只有文字和伪截图 div 的页面就是粗制滥造。

**视觉素材优先级：**
1. **首先使用图片生成工具。**如果环境中有任何图片生成工具（`generate_image`、MCP 图片工具、IDE 集成生成工具、OpenAI 图片工具等），就**必须**使用它生成区段专用素材：Hero 摄影、产品图、纹理背景、氛围图。应根据区段生成正确宽高比的素材。不要因为手写 CSS 感觉更快就跳过此步骤。
2. **其次使用真实网络图片。**如果没有生成工具，使用真实摄影来源。可接受的默认选项：
   * 使用 `https://picsum.photos/seed/{descriptive-seed}/{w}/{h}` 作为占位摄影图（seed 应描述区段，例如 `marrow-cookware-kitchen`）
   * 需求中提供的实际图库或品牌 URL
   * 明确允许时使用开放许可来源（通过直接 URL 使用 Unsplash、Pexels）
3. **最后手段：告知用户。**如果两者都不可行，不要用手绘 SVG 插图或基于 div 的“伪截图”填满页面。应留下清晰标记的占位槽（`<!-- TODO: hero product photo, 1600x1200 -->`），并在回复末尾说明：*“此页面需要在以下位置使用真实图片：\[list of placements\]。请生成或提供这些图片。”*

**即使极简网站也需要真实图片。**纯文字页面不是极简主义，而是未完成的作品。即使是编辑感的 Linear 风格网站，也至少需要 2-3 张真实图片（Hero、一张产品/生活方式图片、一张辅助图片）。如果需求很克制，可以生成黑白极简摄影，但不能因为旋钮值较低就完全跳过图片。

**社会证明应使用真实公司标志。**当需求要求“Trusted by / Used by / Customers”标志墙时，不要默认使用纯文字字标（将 `<span>Acme Co</span>` 排成一行）。应使用真实 SVG 标志：
* **来源：Simple Icons**（`https://cdn.simpleicons.org/{slug}/ffffff` 可用于任意颜色，或使用 `simple-icons` npm 软件包）。涵盖大多数知名品牌。
* **替代方案：devicon**，用于技术栈标志（`@svgr/cli` 或 CDN）。
* **品牌名称是虚构的？那么也应虚构一个 SVG 标记。**生成一个与页面风格匹配的简单字母组合图形（圆圈中的一个字母、双字母连字、抽象图形），以内联 `<svg>` 渲染。虚构品牌名称只使用纯文字字标会显得普通。
* **始终**确保标志在浅色和深色模式下均可显示（深色背景使用白色，浅色背景使用黑色，或使用单色主题变量）。
* **仅标志规则（强制）：**标志墙只能包含标志，不要添加其他内容。不要在每个标志下方打印行业 / 分类标签（不要在 `Vercel` 下添加 `hosting`，不要在 `Stripe` 下添加 `payments`，不要在 `Cloudflare` 下添加 `infra`）。标志本身就是可信度，标签没有提供用户尚不知道的信息。可选内容：供屏幕阅读器使用的品牌名称 alt 文本，以及指向品牌网站的链接。仅此而已。

**手绘插图：**
* 来自图标库的 SVG 图标：可以使用（参见第 3.C 节）。
* 手绘装饰性 SVG（定制插图、标志、图形）：**强烈不建议**，绝不能作为默认项。仅在以下情况下可接受：
  - 需求明确要求（“为我绘制一个 SVG 标志”）
  - 它是单一、简单的几何标记（正方形、圆形、使用展示字体的字标）
  - 你对输出质量有信心

**禁止基于 div 的伪截图。**用 `<div>` 矩形、伪任务列表、伪仪表盘、伪终端窗口渲染的“手工产品预览”是一种明显痕迹。如果需要展示产品：
* 如果存在真实截图 URL，使用真实截图
* 通过图片工具生成
* 使用真实组件预览（在页面中运行实际 UI 的迷你版本）
* 或完全跳过预览，改用编辑型摄影

**Hero 需要真实视觉素材。**文字 + 渐变色块不算 Hero，只是占位符。

### 4.9 内容密度

落地页依靠的是**第一印象**，而不是完整阅读。应果断删减。

* **每个区段的默认内容形态：**短标题（≤ 8 个单词）+ 短副段落（≤ 25 个单词）+ 一个视觉素材或一个 CTA。超出这些内容必须由该区段的职责来证明其必要性。
* **禁止数据倾倒区段。**营销页面上的 20 行出版物表格、30 行奖项列表、巨大定价矩阵都属于错误布局。应使用：
  - 前 3-5 个亮点 + “View full list”链接
  - 用跑马灯 / 轮播体现广度
  - 如果数据本身就是产品，应放到完全不同的页面
* **长列表需要不同的 UI 组件，而不是更长的列表。**默认使用带项目符号 / `divide-y` 行的 `<ul>` 是偷懒的选择。如果项目数量 > 5，应改用以下方案之一：
  - 带分组项目的两列分栏
  - 每项包含图片 + 标签的卡片网格
  - 如果项目可以分类，使用标签页 / 手风琴
  - 横向滚动吸附胶囊
  - 对内容广度要求高的列表（客户评价、标志、能力）使用轮播
  - 对“不需要逐项关注的大量内容”使用跑马灯
  带有 10 行且每行下方都有细线的规格表是**最糟糕的默认方案**。应将行分成 2-3 个组并稀疏使用分隔线，或改用每项规格一个卡片的布局。
* **规格表专项规则（Marrow 厨具模式）。**在厨具 / 硬件 / 服装 / 手工商品需求中，每行都有 `border-b` 的长产品规格表是 AI 默认套路，禁止使用。具体替代方案：
  - **两列卡片网格：**每项规格独占一张卡片，包含规格名称、数值（大号展示数字）和一行“为何重要”的说明。桌面端两列排列，移动端单列。
  - **滚动吸附横向胶囊：**每项规格是一个胶囊，用户可以滑动浏览。
  - **分组区块：**将 10 项规格分成 3 个逻辑组（例如“材料”“烹饪”“保修”），每组仅使用**一条**柔和分隔线和一个组标题。
  - **重点与其余内容：**将 3-4 个核心规格以大型展示瓷砖呈现，其余内容折叠在“View full specifications”披露组件下。

* **文案自检（交付前强制执行）：**在宣布任务完成前，重新阅读页面上的每条可见字符串（标题、副标题、眉题、按钮标签、正文、说明文字、alt 文本、页脚文字、错误消息）。标记任何具有以下问题的字符串：
  - **语法错误**（“free on its past”“two plans but one is honest”“to put it on the table”脱离上下文）
  - **指代不清**（前文没有上下文却出现“we plan to stay that way”）
  - **像 AI 幻觉**（可爱但错误的文字游戏、牵强且无法成立的比喻、“elegant nothing”式短语）
  - **像 LLM 刻意显得深思熟虑**（被动攻击式谦逊、伪工匠标签、伪诗意微型元文本）
  重写所有被标记的字符串。如果不确定某句话是否合理，用简单实用的句子替换它。AI 生成的可爱文案比普通文案更糟糕。
* **标记虚假精确数字。**`92%`、`4.1×`、`48k`、`5.8 mm`、`13.4 lb` 等数字必须符合以下任一条件：
  - 来自真实数据（需求说明、品牌指南、公开指标），可以使用
  - 明确标记为模拟数据（`<!-- mock -->`、“example”、“sample data”），可以使用
  - 属于 AI 虚构的规格审美，禁止使用。不要伪造品牌并未声明的工程精度。
* **每个页面只使用一种文案语域。**除非品牌语气明确要求，否则不要在同一构图中混用技术等宽文字（“47 tasks · 0.6 ctx-switches/day”）、编辑型散文和营销短句。

### 4.10 引语与客户评价

* 引语正文**最多 3 行**，绝不能是 6 行。如果原始引语更长，应删减。落地页中的引语是摘要，不是完整评价。
* 对于非常小的字号（例如页脚风格的客户评价），行数上限可以略微放宽。核心原则是“一眼就能读完”。
* **不要在引语文本中使用长破折号**作为设计装饰（长停顿、动态长破折号、长破折号项目符号）。参见第 9.G 节，长破折号已被完全禁止。
* 署名：姓名 + 职位 +（可选）公司。绝不要只写姓名（“- Sarah”）。
* 引号：使用真正的排版引号（“ ”），或完全不使用。不要使用直 ASCII 引号（" "）。

### 4.11 页面主题锁定（浅色 / 深色模式一致性）

页面只有**一个**主题。区段之间不要反转主题。

* 如果页面采用深色模式，所有区段都应采用深色模式。不要在两个深色区段之间夹入一个暖纸色浅色区段，反之亦然。不能让用户在滚动到一半时感觉进入了另一个网站。
* 例外：如果需求明确要求“色块叙事”或“滚动时切换主题”，并且这是有意设计的构图手法（一次完整主题切换并带有强烈过渡，而不是随机交替），则每个页面允许使用一次。
* 默认行为：在页面层级选择浅色、深色或自动（`prefers-color-scheme`）并锁定。允许在同一主题系列中使用不同的区段背景色调（`bg-zinc-950` 接 `bg-zinc-900`）；在 `bg-zinc-950` 页面中间突然切换到 `bg-amber-50` 属于损坏的设计。
* 使用带有内置主题功能的设计系统（Radix Themes、带 `<Theme>` 的 shadcn/ui）时，只在 `layout.tsx` 或页面根节点设置**一次**主题。不要让各个区段自行覆盖。

## 5. 上下文感知的主动性

以下内容是工具，不是默认项。仅在设计解读需要时使用。**它们不会自动触发。**

* **Liquid Glass / 玻璃拟态：**适合高端消费品牌、Apple 邻近风格、奢华品牌或媒体叠层氛围。不适合仪表盘、公共部门或“朴素 B2B”。使用时不要止步于 `backdrop-blur`：添加 1px 内边框（`border-white/10`）和轻微内阴影（`shadow-[inset_0_1px_0_rgba(255,255,255,0.1)]`），模拟物理边缘折射。在 `prefers-reduced-transparency` 下提供纯色填充回退。
* **磁性微物理效果：**当 `MOTION_INTENSITY > 5` 且需求属于高端 / 活泼 / 代理机构风格时使用。必须完全通过 React 渲染周期之外的 Motion `useMotionValue` / `useTransform` 实现。绝不要使用 `useState`。参见第 3.B 节。
* **持续微交互**（脉冲、打字机、漂浮、微光、轮播）：当 `MOTION_INTENSITY > 5` 且该区段确实能从动效中获益时使用（状态指示器、实时信息流、AI 感）。**不是每张卡片都需要无限循环。**如果区段用于提供信息，应保持静止。使用弹簧物理效果（`type: "spring", stiffness: 100, damping: 20`），不要使用线性缓动。
* **“声明了动效，就要展示动效。”**如果 `MOTION_INTENSITY > 4`，页面必须真正运动：至少包括 Hero 入场过渡、关键区段滚动显现和 CTA 悬停物理效果。声称 `MOTION_INTENSITY: 7` 却完全静态的页面是损坏的。相反，如果在现有范围内无法交付可正常工作的动效，应将旋钮降到 3，并交付干净的静态页面。绝不要构建半成品动效并导致故障（被截断的 ScrollTrigger、跳动的入场、缺少清理）。
* **动效必须有动机（强制）。**添加任何动画前，先问：“这个动画传达了什么？”有效答案：层级（将注意力引导到正确内容）、叙事（按符合故事的顺序揭示内容）、反馈（确认用户操作）、状态转换（表明某些内容已改变）。无效答案：“它看起来很酷”。因为可以使用 GSAP 就到处添加 GSAP 是业余做法。每个 ScrollTrigger、每个跑马灯、每个固定区段都需要理由。如果无法用一句话说明理由，应删除该动画。
* **每页最多一个跑马灯（强制）。**横向滚动文字跑马灯（“标志无限滚动”“宣言横向滚动”“动态文字带”）每页最多使用一次。同一页面出现两个或更多跑马灯会显得像偷懒填充。选择一个真正适合跑马灯内容的区段，其余区段使用其他布局。
* **GSAP Sticky-Stack 模式（使用滚动堆叠时）。**“滚动时卡片堆叠”必须是真正的固定堆叠，而不是依次显现的列表。规范代码骨架参见下方第 5.A 节。常见错误：触发器在滚动到一半时才启动，而不是在视口顶部固定。修复方式：使用 `start: "top top"`，不要使用 `start: "top center"` 或 `"top 80%"`。
* **GSAP Horizontal-Pan 模式（使用横向滚动劫持时）。**规范骨架参见下方第 5.B 节。常见错误：动画在区段固定前启动，导致用户看到半张幻灯片。修复方式相同：使用 `start: "top top"`，固定外层容器，并随滚动移动内部轨道。

### 5.A Sticky-Stack - 规范骨架

```tsx
"use client";
import { useRef, useEffect } from "react";
import { gsap } from "gsap";
import { ScrollTrigger } from "gsap/ScrollTrigger";
import { useReducedMotion } from "motion/react";

gsap.registerPlugin(ScrollTrigger);

export function StickyStack({ cards }: { cards: React.ReactNode[] }) {
  const ref = useRef<HTMLDivElement>(null);
  const reduce = useReducedMotion();

  useEffect(() => {
    if (reduce || !ref.current) return;
    const ctx = gsap.context(() => {
      const cardEls = gsap.utils.toArray<HTMLElement>(".stack-card");
      cardEls.forEach((card, i) => {
        if (i === cardEls.length - 1) return;
        ScrollTrigger.create({
          trigger: card,
          start: "top top",                              // pin at viewport top
          endTrigger: cardEls[cardEls.length - 1],
          end: "top top",
          pin: true,
          pinSpacing: false,
        });
        gsap.to(card, {
          scale: 0.92,
          opacity: 0.55,
          ease: "none",
          scrollTrigger: {
            trigger: cardEls[i + 1],
            start: "top bottom",
            end: "top top",
            scrub: true,
          },
        });
      });
    }, ref);
    return () => ctx.revert();
  }, [reduce]);

  return (
    <div ref={ref} className="relative">
      {cards.map((card, i) => (
        <div
          key={i}
          className="stack-card sticky top-0 min-h-[100dvh] flex items-center justify-center"
        >
          {card}
        </div>
      ))}
    </div>
  );
}
```

关键点：`start: "top top"`、`pin: true`，除最后一张卡片外，每张卡片都被固定；缩放/透明度变换由**下一张**卡片的滚动触发器驱动（因此下一张卡片进入时，上一张会缩小）。

### 5.B Horizontal-Pan - 规范骨架

```tsx
"use client";
import { useRef, useEffect } from "react";
import { gsap } from "gsap";
import { ScrollTrigger } from "gsap/ScrollTrigger";
import { useReducedMotion } from "motion/react";

gsap.registerPlugin(ScrollTrigger);

export function HorizontalPan({ children }: { children: React.ReactNode }) {
  const wrap = useRef<HTMLDivElement>(null);
  const track = useRef<HTMLDivElement>(null);
  const reduce = useReducedMotion();

  useEffect(() => {
    if (reduce || !wrap.current || !track.current) return;
    const ctx = gsap.context(() => {
      const distance = track.current!.scrollWidth - window.innerWidth;
      gsap.to(track.current, {
        x: -distance,
        ease: "none",
        scrollTrigger: {
          trigger: wrap.current,
          start: "top top",                              // pin starts when section top hits viewport top
          end: () => `+=${distance}`,                    // scroll distance = track width minus viewport
          pin: true,
          scrub: 1,
          invalidateOnRefresh: true,
        },
      });
    }, wrap);
    return () => ctx.revert();
  }, [reduce]);

  return (
    <section ref={wrap} className="relative overflow-hidden">
      <div ref={track} className="flex h-[100dvh] items-center">
        {children}
      </div>
    </section>
  );
}
```

关键点：`start: "top top"`、`pin: true`、`end: "+=${distance}"`（滚动长度 = 所需横向移动距离）、`scrub: 1`。外层容器被固定，用户纵向滚动时，内部轨道横向滑动。

### 5.C Scroll-Reveal Stagger - 规范骨架（更轻量的替代方案）

对于简单的“元素进入视口时显现”（不固定），优先使用 Motion 的 `whileInView`，不要使用 GSAP。它更轻量，也不需要 ScrollTrigger：

```tsx
"use client";
import { motion, useReducedMotion } from "motion/react";

export function RevealStagger({ items }: { items: string[] }) {
  const reduce = useReducedMotion();
  return (
    <ul className="grid gap-6">
      {items.map((item, i) => (
        <motion.li
          key={item}
          initial={reduce ? false : { opacity: 0, y: 24 }}
          whileInView={{ opacity: 1, y: 0 }}
          viewport={{ once: true, amount: 0.3 }}
          transition={{
            duration: 0.6,
            delay: i * 0.06,
            ease: [0.16, 1, 0.3, 1],
          }}
        >
          {item}
        </motion.li>
      ))}
    </ul>
  );
}
```

适用于：功能列表、客户评价网格、标志墙，以及任何只需要“滚动进入”的内容。GSAP 应留给真正需要固定/擦洗控制的场景。

### 5.D 禁止的动画模式

* 禁止使用 **`window.addEventListener("scroll", ...)`**。它会在每个滚动帧运行，容易卡顿且不进行批处理。应使用 Motion 的 `useScroll()`、GSAP 的 `ScrollTrigger`、IntersectionObserver 或 CSS `scroll-driven animations`（`animation-timeline: view()`）。
* 禁止在 React 状态中使用 `window.scrollY` 自定义计算滚动进度。原因相同：每一帧都会重新渲染。
* 禁止在会修改 React 状态的 `requestAnimationFrame` 循环中执行动画。应改用 Motion 值（`useMotionValue` + `useTransform`）。
* **布局过渡：**对于可见状态变化（重新排列列表、展开模态框、路由间共享元素），使用 Motion 的 `layout` 和 `layoutId` 属性。不要为了“保险”给静态内容包裹 `layout` 属性，这会产生测量开销。
* **交错编排：**对于顺序具有意义的显现时刻，使用 `staggerChildren`（Motion）或 CSS 级联（`animation-delay: calc(var(--index) * 100ms)`）。使用 `staggerChildren` 时，父级（`variants`）和子级必须位于同一个 Client Component 树中。

## 6. 性能与无障碍护栏

### 6.A 硬件加速
* 只为 `transform` 和 `opacity` 添加动画。绝不要为 `top`、`left`、`width`、`height` 添加动画。
* 谨慎使用 `will-change: transform`，仅用于实际会执行动画的元素。

### 6.B 减少动态效果（强制）
* **任何高于 `MOTION_INTENSITY > 3` 的动效都必须遵守 `prefers-reduced-motion`。**这不可协商。
* 在 Motion 中：使用 `useReducedMotion()` 包裹，并降级为静态效果。
* 在 CSS 中：将动画限制在 `@media (prefers-reduced-motion: no-preference)` 内，或在 `@media (prefers-reduced-motion: reduce)` 中提供禁用动画的覆盖块。
* 无限循环、视差、滚动劫持和磁性物理效果在减少动态效果模式下必须变为静态 / 瞬时状态。

### 6.C 深色模式（任何面向消费者的页面都必须支持）
* 从一开始就为**两种模式**进行设计。除非用户明确要求，否则绝不要只交付浅色或深色模式。
* 使用 Tailwind `dark:` 变体或 CSS 变量作为令牌。每个项目只选择一种策略。
* **不要在这里规定具体的深色模式颜色。**颜色由需求决定。两种模式都应保持视觉层级、品牌身份和 WCAG AA 对比度（正文以 AAA 为目标）。
* 遵守 `prefers-color-scheme: dark`。除非品牌坚持使用某一种模式，否则默认跟随系统偏好。

### 6.D Core Web Vitals 目标
* **LCP** < 2.5s。Hero 图片必须使用 `next/image priority` 或预加载。
* **INP** < 200ms。繁重工作移出主线程。
* **CLS** < 0.1。为图片、字体和嵌入内容预留空间。
* 在宣布页面完成前运行 Lighthouse。

### 6.E DOM 成本
* 颗粒 / 噪点滤镜只能应用于固定且带有 `pointer-events-none` 的伪元素（例如 `fixed inset-0 z-[60] pointer-events-none`）。绝不要应用在滚动容器上，持续 GPU 重绘会摧毁移动端 FPS。
* 注意包体积。Motion 并不小。Three.js 很大。对非首屏内容进行延迟加载。

### 6.F Z-Index 克制
绝不要滥用任意 `z-50` 或 `z-10`。只为系统级图层上下文使用 z-index（吸顶导航栏、模态框、叠层、颗粒效果）。在项目常量文件中记录 z-index 尺度。

## 7. 旋钮定义（技术参考）

### DESIGN_VARIANCE（1-10 级）
* **1-3（可预测）：**对称 CSS Grid（12 列、相等 fr 单位）、相同内边距、居中对齐。
* **4-7（错位）：**使用 `margin-top: -2rem` 重叠，不同图片宽高比（4:3 与 16:9 并排），左对齐标题搭配居中数据。
* **8-10（非对称）：**瀑布流布局、使用分数单位的 CSS Grid（`grid-template-columns: 2fr 1fr 1fr`）、大面积空白区域（`padding-left: 20vw`）。
* **移动端覆盖：**对于 4-10 级，`md:` 以上的非对称布局在 `< 768px` 视口下必须折叠为严格单列（`w-full`、`px-4`、`py-8`）。

### MOTION_INTENSITY（1-10 级）
* **1-3（静态）：**无自动动画。只使用 CSS `:hover` 和 `:active` 状态。`prefers-reduced-motion` 本来就是默认模式。
* **4-7（流畅 CSS）：**`transition: all 0.3s cubic-bezier(0.16, 1, 0.3, 1)`。加载入场使用级联 `animation-delay`。重点使用 `transform` 和 `opacity`。
* **8-10（高级编排）：**复杂的滚动触发显现、视差、滚动驱动动画（CSS `animation-timeline` 或 GSAP ScrollTrigger）。使用 Motion hooks。**绝不要使用 `window.addEventListener('scroll')`**，这是硬性禁令，不是“不推荐”。允许的替代方案参见第 5.D 节。

### VISUAL_DENSITY（1-10 级）
* **1-3（艺术画廊）：**大量留白。巨大的区段间距（`py-32` 到 `py-48`）。高端、干净。
* **4-7（日常应用）：**标准 Web 应用间距（`py-16` 到 `py-24`）。
* **8-10（驾驶舱）：**紧凑内边距。不使用卡片框；用 1px 线条分隔数据。强制要求：所有数字使用 `font-mono`。

## 8. 深色模式协议

默认双模式。除非需求是模拟印刷的编辑型页面，否则绝不要假设只需浅色模式。

### 8.A 令牌策略（选择一种并坚持）
* **Tailwind `dark:` 变体**（工具类优先项目的默认方案）：每个颜色工具类都搭配其深色变体（`bg-white dark:bg-zinc-950`、`text-gray-900 dark:text-gray-100`）。
* **CSS 变量**（适用于 shadcn/ui、Radix Themes 或带主题功能的组件库）：定义语义令牌（`--surface`、`--surface-elevated`、`--text-primary`、`--accent`），并在 `[data-theme="dark"]` 或 `@media (prefers-color-scheme: dark)` 下替换值。

### 8.B 不要在这里规定具体颜色
由需求和品牌决定。本技能只强制要求：
* **对比度** - 正文至少达到 WCAG AA，Hero 文案以 AAA 为目标。
* **层级一致** - 浅色模式下有效的视觉层级在深色模式下也必须有效。如果 CTA 在浅色模式下突出，在深色模式下也应突出。
* **品牌忠实度** - 主要品牌色保持可识别。不要为了深色模式而将品牌色去饱和。
* **不要使用纯 `#000000` 或纯 `#ffffff`** - 使用近黑色（zinc-950、暖调近黑灰）和灰白色。纯色值会破坏层次感。

### 8.C 默认模式
除非品牌坚持，否则遵守 `prefers-color-scheme`。如果任何一种模式会削弱关键品牌表达，应添加手动切换开关。

### 8.D 完成前测试两种模式
开发过程中分别在两种模式下打开页面。不要交付只在一种模式下查看过的页面。

## 9. AI 痕迹（禁止模式）

除非需求明确要求，否则避免以下特征。

### 9.A 视觉与 CSS
* 默认**禁止霓虹 / 外发光**。使用内边框或轻微着色阴影。
* **禁止纯黑色（`#000000`）。**使用近黑色、zinc-950 或炭灰色。
* **禁止过度饱和的强调色。**降低饱和度，使其与中性色融合。
* **禁止在大标题中过度使用渐变文字。**
* **禁止自定义鼠标光标。**它已经过时，对无障碍和性能都不友好。

### 9.B 字体排印
* **避免默认使用 Inter。**参见第 4.1 节。存在例外路径。
* **禁止只靠巨大字号叫喊的 H1。**通过字重 + 颜色控制层级，而不是仅靠尺寸。
* **衬线字体约束：**衬线字体用于编辑 / 奢华 / 出版物，不用于仪表盘。

### 9.C 布局与间距
* 使用**数学上完美一致的**内边距和外边距。不要出现留有尴尬间隙的漂浮元素。
* **禁止三个等宽功能卡片。**通用的“三张完全相同卡片横向排列”功能行已被禁止。改用两列之字形、非对称网格、滚动固定或横向滚动方案。

### 9.D 内容与数据（“Jane Doe”效应）
* **禁止通用姓名。**“John Doe”“Sarah Chan”“Jack Su” → 使用有创意、真实且符合地区习惯的姓名。
* **禁止通用头像。**不要使用 SVG“蛋形头像”或 Lucide 用户图标 → 使用可信的照片占位图或具体样式。
* **禁止虚假完美数字。**避免 `99.99%`、`50%`、`1234567`。使用自然、不规整的数据（`47.2%`、`+1 (312) 847-1928`）。
* **禁止粗制滥造的创业品牌名称。**“Acme”“Nexus”“SmartFlow”“Cloudly” → 创造符合上下文、听起来真实的高端名称。
* **禁止空洞动词。**“Elevate”“Seamless”“Unleash”“Next-Gen”“Revolutionize” → 只使用具体动词。

### 9.E 外部资源与组件
* **禁止手绘 SVG 图标。**使用 Phosphor / HugeIcons / Radix / Tabler。只有用户明确要求时才能使用 Lucide。
* 默认**强烈不建议手绘装饰性 SVG**（参见第 4.8 节）。
* **禁止基于 div 的伪截图。**绝不要用 `<div>` 矩形构建伪产品 UI 来模拟截图。使用真实图片、生成图片，或跳过预览。
* **禁止损坏的 Unsplash 链接。**使用 `https://picsum.photos/seed/{descriptive-string}/{w}/{h}`、生成的照片占位图或实际素材。
* **shadcn/ui 定制：**允许使用，但绝不能保持默认状态。根据项目审美定制圆角、颜色、阴影和字体。
* **生产就绪的整洁度：**代码在视觉上整洁、令人印象深刻，并经过细致打磨。

### 9.F 生产测试痕迹（完全禁止）

以下模式来自真实的 LLM 生成落地页测试。它们是模型试图“显得经过设计”时会默认采用的特征。除非需求明确要求某项，否则将其视为硬性禁令。

**Hero 与页面顶部**
* **禁止在 Hero 中使用版本标签。**`V0.6`、`v2.0`、`BETA`、`INVITE-ONLY PREVIEW`、`EARLY ACCESS`、`ALPHA`，禁止作为默认眉题。仅当需求明确涉及产品发布 / 预览状态时才可接受。
* **禁止“Brand · No. 01”式次级眉题。**跳过“Marrow · No. 01 · The 6-quart”这类微型元信息行。

**区段编号与微型标签**
* **禁止区段编号眉题。**`00 / INDEX`、`001 · Capabilities`、`002 · Featured commission`、`06 · how it works`、`05 · The honest table`，全部禁止。眉题应使用直白语言命名主题，而不是编号。
* **禁止在图片或 Bento 瓷砖上使用 `01 / 4` 式分页。**如果用户会数数，就不需要这种标签。
* **禁止“Scroll · 001 Capabilities”式滚动提示。**简单箭头或“Scroll”就够了，不要添加区段编号前缀。
* **禁止将“Index of Work, 2018 - 2026”式范围标签**用作眉题。直接说明该区段是什么。

**分隔符与圆点**
* **中点（`·`）应限量使用。**元信息条中每行最多 1 个。不要把它作为所有内容的默认分隔符（“foo · bar · baz · qux · quux”）。需要一套分隔方式时，优先使用换行、细线或分栏。
* **禁止在每个列表 / 导航 / 徽章中使用装饰性色彩状态点。**默认禁止在“ONE Q4 SLOT OPEN”前、每个导航链接前或每个任务行前添加彩色圆点。只有当圆点表达真实语义状态（服务器状态、可用性标志）且使用克制时才可接受。

**长破折号与字体装饰**
* **禁止将长破折号（`—`）用作设计元素或出现在任何其他位置。**完整且不可协商的禁令参见下方第 9.G 节。标题、眉题、胶囊、正文、引语、署名、说明文字、按钮文字和 alt 文本中都禁止使用长破折号。使用普通连字符（`-`）。
* 默认**禁止使用 `<br>` 强制断行并将部分标题设为斜体**作为“设计手法”。例如“for thirty\<br\>*years.*”式拆分。标题首先应自然易读，只有需求要求时才可以玩技巧。
* **禁止竖向旋转文字**（将“INDEX OF WORK, 2018 - 2026”旋转 90°）。这是代理机构作品集的陈词滥调。仅当需求明确属于代理机构 / Awwwards / 实验性风格，且它确实服务于构图时才使用。
* **禁止用十字准线 / 细线网格进行装饰。**仅为让页面“显得经过设计”而绘制的横竖线已被禁止。只有在它们组织真实内容时才使用。

**伪产品预览**
* **禁止在 Hero 中使用基于 div 的伪产品 UI**（由样式化 div 构建的伪任务列表、伪终端、伪仪表盘）。这是最明显的 LLM 设计痕迹。使用真实截图、生成图片、真实组件预览，或完全不使用。
* **禁止伪版本页脚**（“v0.6.2-rc.1”“last sync 4s ago · main”）出现在伪截图中。它没有价值，只会强烈暴露 AI 痕迹。

**营销文案痕迹**
* **禁止使用“Quietly in use at” / “Quietly trusted by”**作为社会证明标题。使用自然语言：“Trusted by”“Used at”“Customers include”，或者在标志足以说明问题时完全省略标题。
* **禁止使用“From the field” / “Field notes” / “Currently on the bench” / “On our desks” / “Loose plates”式诗意标签**作为引语、博客或侧栏区段标题。它们带有表演式工匠感。使用直接、实用的标签（“Testimonials”“Latest writing”“Now working on”），或省略标签。
* **禁止使用“We respect the French ones”式**假谦逊行业梗正文。既故作可爱又充满 AI 感。
* **禁止在页眉 / 页脚使用天气 / 地区信息条**（“LIS 14:23 · 18°C”），除非需求明确涉及地点 / 跨时区分布式工作室。
* **禁止在眉题下添加微型元信息句子。**诸如*“Each of these is a feature we ship today, not a roadmap promise. The list will stay short on purpose.”*这类放在区段标题下的句子只会增加杂乱。眉题 + 标题 + 正文已经足够。
* **禁止通用步骤标签。**“Stage 1 / Stage 2 / Stage 3”“Step 1 / Step 2 / Step 3”“Phase 01 / Phase 02 / Phase 03”“Pass One / Pass Two / Pass Three”全部禁止。实际步骤内容本身就是标签。如果必须显示进度，直接使用动词-名词（“Install”“Configure”“Ship”），不要写“Stage 1: Install”。

**胶囊、标签和版本戳**
* **禁止在图片上叠加胶囊 / 标签 / 标记。**不要在照片上叠加带有 `Brand · 02`、`PLATE · BRAND`、`Field notes - journal` 等标签的 `<span>`。让图片自行表达，或直接在图片下方（图片外部）添加说明文字。
* **禁止将照片署名作为装饰。**在图库/Picsum 图片下添加 `Field study no. 12 · Ines Caetano`、`Plate 03 · House archive`、`Frame XII · 35mm` 等文字显得矫饰。只有在为真实照片的真实摄影师署名（并获得许可）时才允许使用照片署名。否则应跳过说明文字，或使用一行实用说明（“The 6-quart, in Sage.”）。
* **禁止营销页面使用版本页脚。**`v1.4.2`、`Build 0048`、`last sync 4s ago · main` 等页脚字符串属于 CLI / 开发工具界面，不属于落地页内容。禁止出现在营销 / 落地 / 作品集页面。
* **禁止使用“Reservation 412 of 800”式实时库存计数器**作为装饰。只有当需求明确为限量发售候补名单且使用真实数据时才可使用。

**装饰性文字条**
* **禁止在 Hero 底部使用装饰性文字条。**`BRAND. MOTION. SPATIAL.`、`TYPE / FORM / MOTION`、`DESIGN · BUILD · SHIP`、`ESTD. 2018 · LISBON · BRAND. MOTION. SPATIAL.` 等小号等宽大写文字条横跨 Hero 底部，是代理机构作品集的陈词滥调，默认禁止。只有当文字条包含真实可导航链接（底部吸附导航）或真实状态信息（Cookie 横幅、文档网站构建信息）时才可接受。
* **禁止区段标题右上角漂浮副文案。**这种模式是：区段左侧有巨大标题，而同一区段标题区域的右上角漂浮着一段与其他内容缺乏清晰对齐关系的小号说明文字。这个漂浮段落就是明显痕迹。应将副文案直接放到标题下方，或构建整洁的两列标题（左侧标题，右侧对齐正文），不要使用微型角落段落。

**列表、分隔线和评分**
* **禁止对长列表 / 规格表的每一行同时使用 `border-t` + `border-b`。**二选一（行间下边框或整组上边框），并克制使用。带有 10 行且每行下方都有细线的规格表是最偷懒的布局，第 4.9 节提供了替代 UI 组件。
* **禁止使用带填充背景轨道的评分 / 进度条**作为比较视觉。如果需要显示“X / Y”比较，优先使用数字 + 小图标，或没有背景轨道的微型内联条。大型 `bg-zinc-200` 轨道上叠加局部填充属于仪表盘 UI 杂物，不应出现在落地页上。

**地区、时间和滚动提示**
* **99% 的需求都禁止使用地区 / 城市名称 / 时间 / 天气信息条。**Hero 中的“Lisbon, working with founders”、页脚中的“1200-690 Lisbon, Portugal”、导航中的“Lisbon 14:23 · 18°C”，都是代理机构作品集的装饰性痕迹。仅在以下情况下允许：需求明确描述与时区相关的全球分布式工作室、旅行品牌或现实中的实体场所。页脚中单次出现联系地址没有问题，但氛围化的地区信息条不行。
* **禁止滚动提示。**`Scroll`、`↓ scroll`、`Scroll to explore`、`Scroll to walk through it`、动画鼠标滚轮图标。如果用户还没有滚动，他们正在看 Hero。他们知道如何滚动。视口底部不需要标签。
* **默认零装饰性状态点。**导航项、列表行、徽章、状态标签前的彩色圆点是一种明显痕迹。仅当它传达真实语义状态（实际服务器状态的实时指示器、实时可用性标志），并且每个页面区段最多一个时才可接受。

### 9.G 长破折号禁令（违反次数最多的单一痕迹）

**完全禁止长破折号（`—`）。**它是 LLM 的标志性文风拐杖，也是生产测试中最明显的视觉痕迹。不存在“有限使用”的许可，不存在“自然语言中偶尔出现”的许可，也不存在“正文中可以使用”的许可。完全不允许。

* **标题中禁止。**使用句号或逗号。
* **眉题 / 标签 / 胶囊 / 按钮文字 / 图片说明 / 导航项中禁止。**改用换行、分栏或细线。
* **正文中禁止。**重写句子：用句号拆成两句，或使用逗号、括号、冒号。
* **引语署名中禁止。**使用两侧带空格的普通连字符（` - `），或换行 + 较细字重的姓名。
* **用作分隔符时，也禁止使用短破折号形式（`–`）。**日期范围（`2018-2026`）使用连字符。数字范围（`€40-80k`）使用连字符。

页面中唯一允许的短横线字符是：
* 普通连字符 `-`（用于复合词、范围、标记中的行分隔符）
* 数学中的负号（`-5°C`）

如果输出中任何用户可见位置包含一个 `—` 或 `–`，输出即未通过交付前检查，必须重写。

此规则不可协商。历史上，当要求写成“少量使用”时，智能体总会忽略长破折号限制。因此这里采用二元表述：长破折号数量必须为零。

## 10. 参考词汇（智能体应了解的模式名称）

这是一套词汇，不是一个库。智能体应**了解**这些模式名称，以便讨论它们、在设计中考虑它们，并在设计解读需要时采用它们。**实现和代码草图位于区块库（第 12 节），该库会迭代填充。**

### Hero 范式
* **Asymmetric Split Hero** - 一侧为文字，另一侧为素材，并留有充足空白。
* **Editorial Manifesto Hero** - 大号字体，无素材，接近海报。
* **Video / Media Mask Hero** - 文字作为视频背景上的镂空遮罩。
* **Kinetic-Type Hero** - 动态字体作为主要视觉元素。
* **Curtain-Reveal Hero** - Hero 各部分随滚动像幕布一样展开。
* **Scroll-Pinned Hero** - Hero 保持固定，内容在其后方滚动。

### 导航与菜单
* **Mac OS Dock Magnification** - 边缘导航，图标悬停时流畅缩放。
* **Magnetic Button** - 向光标方向吸附。
* **Gooey Menu** - 子项像黏稠液体一样分离。
* **Dynamic Island** - 用于状态 / 提醒的变形胶囊。
* **Contextual Radial Menu** - 在点击位置展开的圆形菜单。
* **Floating Speed Dial** - FAB 弹出为弧形排列的次要操作。
* **Mega Menu Reveal** - 全屏下拉菜单，内容交错淡入。

### 布局与网格
* **Bento Grid** - 非对称瓷砖分组（Apple Control Center）。
* **Masonry Layout** - 交错网格，无固定行高。
* **Chroma Grid** - 带有轻微动态渐变的边框 / 瓷砖。
* **Split-Screen Scroll** - 两半向相反方向滑动。
* **Sticky-Stack Sections** - 滚动时固定并堆叠的区段。

### 卡片与容器
* **Parallax Tilt Card** - 跟随鼠标坐标的 3D 倾斜。
* **Spotlight Border Card** - 光标经过时边框被照亮。
* **Glassmorphism Panel** - 带内部折射效果的磨砂玻璃。
* **Holographic Foil Card** - 悬停时产生虹彩变色。
* **Tinder Swipe Stack** - 具有物理感、可滑走的卡片堆。
* **Morphing Modal** - 按钮扩展成自身对应的对话框。

### 滚动动画
* **Sticky Scroll Stack** - 卡片固定并产生物理堆叠。
* **Horizontal Scroll Hijack** - 纵向滚动 → 横向平移。
* **Locomotive / Sequence Scroll** - 视频 / 3D 序列与滚动条绑定。
* **Zoom Parallax** - 中央背景图片随滚动缩放。
* **Scroll Progress Path** - SVG 线条随滚动绘制。
* **Liquid Swipe Transition** - 像黏稠液体一样的页面过渡。

### 图库与媒体
* **Dome Gallery** - 3D 全景图库。
* **Coverflow Carousel** - 边缘倾斜的 3D 轮播。
* **Drag-to-Pan Grid** - 无边界可拖动画布。
* **Accordion Image Slider** - 悬停时展开的窄图片条。
* **Hover Image Trail** - 鼠标移动时留下连续弹出的图片轨迹。
* **Glitch Effect Image** - 悬停时产生 RGB 通道偏移。

### 字体与文字
* **Kinetic Marquee** - 随滚动反向移动的无限文字带。
* **Text Mask Reveal** - 巨大文字作为显示视频的透明窗口。
* **Text Scramble Effect** - 加载 / 悬停时产生 Matrix 风格解码效果。
* **Circular Text Path** - 沿旋转圆形路径弯曲的文字。
* **Gradient Stroke Animation** - 带流动渐变的描边文字。
* **Kinetic Typography Grid** - 会避开光标的字母网格。

### 微交互与效果
* **Particle Explosion Button** - CTA 成功后碎裂成粒子。
* **Liquid Pull-to-Refresh** - 像脱落液滴一样的刷新指示器。
* **Skeleton Shimmer** - 在占位内容上移动的反光效果。
* **Directional Hover-Aware Button** - 填充从光标准确所在方向进入。
* **Ripple Click Effect** - 从点击坐标扩散的波纹。
* **Animated SVG Line Drawing** - 矢量线条实时自我绘制。
* **Mesh Gradient Background** - 有机熔岩灯状色块。
* **Lens Blur Depth** - 模糊背景 UI，将注意力集中到前景操作。

### 动画库选择
* **Motion（`motion/react`）** - UI / Bento / 状态变化动效的默认方案。
* **GSAP + ScrollTrigger** - 用于整页滚动叙事和滚动劫持。隔离到专用叶子组件中，并通过 `useEffect` 清理。
* **Three.js / WebGL** - 用于 Canvas 背景和 3D 场景。采用相同的隔离规则。
* **绝不要在同一组件树中混用 GSAP / Three.js 与 Motion。**它们会争夺相同的帧。

## 11. 重新设计协议

本技能同时处理**全新构建和重新设计**。错误判断模式是重新设计产出糟糕的最大原因。

### 11.A 检测模式（第一个操作）
* **全新构建** - 没有现有网站，或已批准彻底改造。使用第 1 节中的旋钮基准值。
* **重新设计 - 保留** - 在不破坏品牌的前提下现代化。先审计，提取品牌令牌，再逐步演进。
* **重新设计 - 彻底改造** - 在现有内容上建立新的视觉语言。视觉上按全新构建处理，保留内容和 IA。

如果含糊，只问**一次**：*“这次重新设计应保留现有品牌，还是在视觉上从零开始？”*

### 11.B 修改前先审计
在提出更改前记录当前状态：
* **品牌令牌** - 主色 / 强调色、字体栈、标志处理、圆角。
* **信息架构** - 页面树、主导航、关键转化路径。
* **内容区块** - 已有哪些内容、哪些确实发挥作用、哪些只是填充。
* **应保留的模式** - 标志性交互、可识别的 Hero、文案语气。
* **应淘汰的模式** - AI 粗制滥造痕迹、损坏的布局、死链接、通用图库图片、性能陷阱。
* **现有网站的旋钮读数** - 推断当前 `DESIGN_VARIANCE` / `MOTION_INTENSITY` / `VISUAL_DENSITY`。这些值是起点，而不是基准值。
* **SEO 基线** - 当前有排名的页面、meta 标题、结构化数据、OG 卡片。**SEO 迁移是重新设计的首要风险。**

### 11.C 保留规则
* 除非用户要求，否则**不要更改信息架构**。保持页面 slug、锚点 ID 和主导航标签稳定，以保护 SEO 和用户操作习惯。
* **应用第 4.2 节前先提取品牌颜色。**已经使用紫色的品牌应继续保持紫色，应用淡紫色规则的例外。
* 除非用户要求重写，否则**保留文案语气**。视觉现代化不等于内容重写。
* **尊重现有无障碍成果。**不要让焦点状态、alt 文本、键盘导航和对比度退步。
* **尊重现有分析事件。**不要重命名下游跟踪所依赖的按钮、表单字段或区段 ID。

### 11.D 现代化手段（按优先顺序）
按顺序应用，满足需求后立即停止：
1. **字体更新** - 单位风险下带来最大的视觉提升。
2. **间距与节奏** - 增加区段内边距，修复垂直节奏。
3. **颜色重新校准** - 降低饱和度，统一中性色，保留品牌强调色。
4. **动效层** - 根据 `MOTION_INTENSITY` 为现有组件添加适当的微交互。
5. **Hero 与关键区段重新构图** - 使用第 10 节词汇重构漏斗顶部。
6. **完整替换区块** - 仅当现有区块无法挽救时使用。

### 11.E 决策树：定向演进还是全面重新设计
* IA、内容和 SEO 状况良好 → **定向演进**（手段 1-4）。约 40% 的风险可获得约 70% 的价值。
* 视觉债务属于结构性问题（损坏的 IA、无设计系统、移动端损坏） → 在严格保留内容的前提下进行**全面重新设计**。
* 品牌本身正在变化 → **全新构建**。

### 11.F 绝不能静默更改的内容
未经用户明确批准，绝不要修改：
* URL 结构 / 路由 slug。
* 主导航标签。
* 表单字段名称或顺序（会破坏分析 + 自动填充）。
* 品牌标志或字标。
* 现有法律 / 同意 / Cookie 文案。

## 附录 C - Apple Liquid Glass：诚实的 Web 近似实现

不要将随机 CSS 代码片段视为官方 Apple Liquid Glass。

### 官方内容是什么
Apple 在 Apple Human Interface Guidelines 和 Developer Documentation 中针对 **Apple 平台**记录了 Liquid Glass。它是一种用于 Apple 平台 UI 的动态材质。Apple 的原生实现属于 Apple 平台 API 和系统组件，**不是公开的 Web CSS 软件包**。

相关官方文档：
- Apple Human Interface Guidelines → Materials
- Apple Developer Documentation → Liquid Glass
- Apple Developer Documentation → Adopting Liquid Glass
- SwiftUI → Material

### 哪些内容不是官方实现
Apple 没有为普通网站提供 `liquid-glass.css`。

Web 近似实现可以使用：
- `backdrop-filter`
- 透明背景
- 分层边框
- 高光叠层
- 渐变
- 动效
- 高对比度回退

但这属于 **Web 玻璃拟态 / 磨砂玻璃近似效果**，不是官方 Apple Liquid Glass。应在注释中如实标注。

### 更安全的 Web 近似实现骨架

```css
.liquid-glass-web-approx {
  position: relative;
  isolation: isolate;
  overflow: hidden;
  border-radius: 999px;
  border: 1px solid rgb(255 255 255 / .32);
  background:
    linear-gradient(135deg, rgb(255 255 255 / .30), rgb(255 255 255 / .08)),
    rgb(255 255 255 / .12);
  backdrop-filter: blur(24px) saturate(180%) contrast(1.05);
  -webkit-backdrop-filter: blur(24px) saturate(180%) contrast(1.05);
  box-shadow:
    inset 0 1px 0 rgb(255 255 255 / .48),
    inset 0 -1px 0 rgb(255 255 255 / .12),
    0 18px 60px rgb(0 0 0 / .18);
}

.liquid-glass-web-approx::before {
  content: "";
  position: absolute;
  inset: 0;
  z-index: -1;
  border-radius: inherit;
  background:
    radial-gradient(circle at 20% 0%, rgb(255 255 255 / .55), transparent 34%),
    linear-gradient(90deg, rgb(255 255 255 / .18), transparent 42%, rgb(255 255 255 / .14));
  pointer-events: none;
}

.liquid-glass-web-approx::after {
  content: "";
  position: absolute;
  inset: 1px;
  border-radius: inherit;
  border: 1px solid rgb(255 255 255 / .14);
  pointer-events: none;
}

@media (prefers-color-scheme: dark) {
  .liquid-glass-web-approx {
    border-color: rgb(255 255 255 / .18);
    background:
      linear-gradient(135deg, rgb(255 255 255 / .16), rgb(255 255 255 / .04)),
      rgb(15 23 42 / .42);
    box-shadow:
      inset 0 1px 0 rgb(255 255 255 / .22),
      0 18px 60px rgb(0 0 0 / .42);
  }
}

@media (prefers-reduced-transparency: reduce) {
  .liquid-glass-web-approx {
    background: rgb(255 255 255 / .96);
    backdrop-filter: none;
    -webkit-backdrop-filter: none;
  }
}
```

**重要：**`prefers-reduced-transparency` 的浏览器支持并不一致，应进行测试。即使没有模糊效果，也必须始终提供足够的对比度。
