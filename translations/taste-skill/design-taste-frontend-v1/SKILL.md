# 高自主性前端技能

## 1. 当前基线配置
* DESIGN_VARIANCE: 8（1=完美对称，10=艺术化混乱）
* MOTION_INTENSITY: 6（1=静态/无运动，10=电影级/魔法物理效果）
* VISUAL_DENSITY: 4（1=艺术画廊/通透，10=飞行员驾驶舱/数据密集）

**AI 指令：** 所有生成任务的标准基线严格设定为这些值（8、6、4）。不要要求用户编辑此文件。除此之外，始终听从用户：根据他们在聊天提示中明确提出的要求，动态调整这些值。将这些基线值（或用户覆盖后的值）作为全局变量，用于驱动第 3 节至第 7 节中的具体逻辑。

## 2. 默认架构与约定
除非用户明确指定其他技术栈，否则请遵守以下结构约束以保持一致性：

* **依赖验证 [强制]：** 在导入任何第三方库（例如 `framer-motion`、`lucide-react`、`zustand`）之前，你必须检查 `package.json`。如果缺少该软件包，你必须先输出安装命令（例如 `npm install package-name`），然后再提供代码。**绝不**假定某个库已经存在。
* **框架与交互性：** React 或 Next.js。默认使用服务器组件（`RSC`）。
    * **RSC 安全性：** 全局状态只能在客户端组件中工作。在 Next.js 中，将 provider 包装在带有 `"use client"` 的组件中。
    * **交互隔离：** 如果第 4 节或第 7 节（动效/液态玻璃）处于启用状态，则必须将具体的交互式 UI 组件提取为独立的叶子组件，并在最顶部添加 `'use client'`。服务器组件只能渲染静态布局。
* **状态管理：** 对独立 UI 使用本地 `useState`/`useReducer`。仅在避免深层属性逐级传递时使用全局状态。
* **样式策略：** 90% 的样式使用 Tailwind CSS（v3/v4）。
    * **TAILWIND 版本锁定：** 首先检查 `package.json`。不要在 v3 项目中使用 v4 语法。
    * **T4 配置防护：** 对于 v4，不要在 `postcss.config.js` 中使用 `tailwindcss` 插件。请使用 `@tailwindcss/postcss` 或 Vite 插件。
* **反表情符号策略 [关键]：** 绝不要在代码、标记、文本内容或替代文本中使用表情符号。请使用高质量图标（Radix、Phosphor）或简洁的 SVG 图元替代符号。禁止使用表情符号。
* **响应式与间距：**
  * 标准化断点（`sm`、`md`、`lg`、`xl`）。
  * 使用 `max-w-[1400px] mx-auto` 或 `max-w-7xl` 约束页面布局。
  * **视口稳定性 [关键]：** 绝不要对全高度 Hero 区域使用 `h-screen`。始终使用 `min-h-[100dvh]`，以防止移动浏览器（iOS Safari）发生灾难性的布局跳动。
  * **使用 Grid 而非 Flex 数学计算：** 绝不要使用复杂的 Flexbox 百分比计算（`w-[calc(33%-1rem)]`）。始终使用 CSS Grid（`grid grid-cols-1 md:grid-cols-3 gap-6`）构建可靠的结构。
* **图标：** 你必须且只能使用 `@phosphor-icons/react` 或 `@radix-ui/react-icons` 作为导入路径（检查已安装的版本）。全局统一 `strokeWidth`（例如，只使用 `1.5` 或 `2.0`）。


## 3. 设计工程指令（偏差纠正）
LLM 在统计上偏向特定的 UI 陈词滥调模式。请主动使用以下工程化规则构建高级界面：

**规则 1：确定性排版**
* **展示文本/标题：** 默认为 `text-4xl md:text-6xl tracking-tighter leading-none`。
    * **反粗制滥造：** 不鼓励为“高级”或“创意”氛围使用 `Inter`。强制使用 `Geist`、`Outfit`、`Cabinet Grotesk` 或 `Satoshi` 塑造独特个性。
    * **技术型 UI 规则：** Dashboard/软件 UI 严禁使用衬线字体。在这些场景中，只能使用高端无衬线字体搭配（`Geist` + `Geist Mono` 或 `Satoshi` + `JetBrains Mono`）。
* **正文/段落：** 默认为 `text-base text-gray-600 leading-relaxed max-w-[65ch]`。

**规则 2：色彩校准**
* **约束：** 最多使用 1 种强调色。饱和度 < 80%。
* **淡紫色禁令：** 严禁“AI 紫色/蓝色”美学。不要使用紫色按钮光晕或霓虹渐变。使用绝对中性的基础色（Zinc/Slate），搭配高对比度的单一强调色（例如 Emerald、Electric Blue 或 Deep Rose）。
* **色彩一致性：** 整个输出坚持使用一套调色板。不要在同一项目中混用暖灰色和冷灰色。

**规则 3：布局多样化**
* **反居中偏差：** 当 `DESIGN_VARIANCE > 4` 时，严禁使用居中的 Hero/H1 区域。强制使用“分屏”（50/50）、“内容左对齐/素材右对齐”或“非对称留白”结构。

**规则 4：材质感、阴影与“反卡片滥用”**
* **Dashboard 强化：** 当 `VISUAL_DENSITY > 7` 时，严禁使用通用卡片容器。请通过 `border-t`、`divide-y` 或纯粹的负空间进行逻辑分组。除非功能上确实需要层级提升（z-index），否则数据指标应保有呼吸感，不应被框在容器中。
* **执行方式：** 仅在层级提升能够传达信息层次时使用卡片。使用阴影时，让阴影带有背景色调。

**规则 5：交互式 UI 状态**
* **强制生成：** LLM 天然倾向于生成“静态”的成功状态。你必须实现完整的交互周期：
  * **加载状态：** 使用与布局尺寸匹配的骨架加载器（避免通用的圆形加载指示器）。
  * **空状态：** 精心构成空状态，并说明如何填充数据。
  * **错误状态：** 提供清晰的行内错误报告（例如表单中的错误）。
  * **触觉反馈：** 在 `:active` 状态下，使用 `-translate-y-[1px]` 或 `scale-[0.98]` 模拟实体按压，以表示操作成功或动作已触发。

**规则 6：数据与表单模式**
* **表单：** 标签必须位于输入框上方。辅助文本是可选的，但应存在于标记中。错误文本位于输入框下方。输入块使用标准的 `gap-2`。

## 4. 创意主动性（反粗制滥造实现）
为积极对抗通用的 AI 设计，请系统性地将以下高端编码概念作为基线：
* **“液态玻璃”折射：** 需要玻璃拟态时，不要止步于 `backdrop-blur`。添加 1px 内边框（`border-white/10`）和细微的内阴影（`shadow-[inset_0_1px_0_rgba(255,255,255,0.1)]`），以模拟物理边缘折射。
* **磁性微物理效果（如果 MOTION_INTENSITY > 5）：** 实现会轻微向鼠标指针靠拢的按钮。**关键：** 绝不要为磁性悬停或连续动画使用 React `useState`。只能使用 Framer Motion 的 `useMotionValue` 和 `useTransform`，并让它们在 React 渲染周期之外运行，以防止移动端性能崩溃。
* **持续微交互：** 当 `MOTION_INTENSITY > 5` 时，在标准组件（头像、状态点、背景）中嵌入连续、无限循环的微动画（脉冲、打字机、漂浮、微光、轮播）。所有交互元素都应用高级弹簧物理效果（`type: "spring", stiffness: 100, damping: 20`），不要使用线性缓动。
* **布局过渡：** 始终使用 Framer Motion 的 `layout` 和 `layoutId` 属性，实现状态变化时平滑的重新排序、尺寸调整和共享元素过渡。
* **交错编排：** 不要让列表或网格瞬间挂载。使用 `staggerChildren`（Framer）或 CSS 级联（`animation-delay: calc(var(--index) * 100ms)`）创建依次展开的瀑布式显现效果。**关键：** 使用 `staggerChildren` 时，父级（`variants`）与子级必须位于同一个客户端组件树中。如果数据是异步获取的，请将数据作为 props 传入一个集中的父级 Motion 包装器。

## 5. 性能防护措施
* **DOM 成本：** 颗粒/噪点滤镜只能应用于固定定位且禁用指针事件的伪元素（例如 `fixed inset-0 z-50 pointer-events-none`），绝不要应用于滚动容器，以防止 GPU 持续重绘和移动端性能下降。
* **硬件加速：** 绝不要为 `top`、`left`、`width` 或 `height` 制作动画。只能通过 `transform` 和 `opacity` 制作动画。
* **Z-Index 克制：** 绝不要在没有要求的情况下滥用任意的 `z-50` 或 `z-10`。仅将 z-index 用于系统性的图层上下文（粘性导航栏、模态框、遮罩层）。

## 6. 技术参考（参数定义）

### DESIGN_VARIANCE（等级 1-10）
* **1-3（可预测）：** Flexbox `justify-center`、严格对称的 12 列网格、相等的内边距。
* **4-7（偏移）：** 使用 `margin-top: -2rem` 重叠效果、不同的图像宽高比（例如 4:3 与 16:9 并列）、在居中对齐的数据上方使用左对齐标题。
* **8-10（非对称）：** 瀑布流布局、使用分数单位的 CSS Grid（例如 `grid-template-columns: 2fr 1fr 1fr`）、大面积空白区域（`padding-left: 20vw`）。
* **移动端覆盖规则：** 对于等级 4-10，任何在 `md:` 以上使用的非对称布局，都必须在 `< 768px` 的视口上积极回退为严格的单列布局（`w-full`、`px-4`、`py-8`），以防止水平滚动和布局破坏。

### MOTION_INTENSITY（等级 1-10）
* **1-3（静态）：** 不使用自动动画。仅使用 CSS `:hover` 和 `:active` 状态。
* **4-7（流畅 CSS）：** 使用 `transition: all 0.3s cubic-bezier(0.16, 1, 0.3, 1)`。使用 `animation-delay` 级联实现加载入场。严格聚焦于 `transform` 和 `opacity`。谨慎使用 `will-change: transform`。
* **8-10（高级编排）：** 复杂的滚动触发显现效果或视差效果。使用 Framer Motion hooks。绝不要使用 `window.addEventListener('scroll')`。

### VISUAL_DENSITY（等级 1-10）
* **1-3（艺术画廊模式）：** 大量留白。巨大的区段间距。一切都显得非常昂贵且简洁。
* **4-7（日常应用模式）：** 标准 Web 应用的常规间距。
* **8-10（驾驶舱模式）：** 极小的内边距。不使用卡片框；仅用 1px 线条分隔数据。一切都非常紧凑。**强制：** 所有数字使用等宽字体（`font-mono`）。

## 7. AI 痕迹（禁止模式）
为确保输出高级且不落俗套，除非用户明确要求，否则你必须严格避免以下常见的 AI 设计特征：

### 视觉与 CSS
* **禁止霓虹/外发光：** 不要使用默认的 `box-shadow` 发光或自动发光效果。使用内边框或细微的带色阴影。
* **禁止纯黑：** 绝不要使用 `#000000`。使用 Off-Black、Zinc-950 或 Charcoal。
* **禁止过饱和强调色：** 降低强调色的饱和度，使其与中性色优雅融合。
* **禁止过度使用渐变文本：** 不要对大型标题使用文字填充渐变。
* **禁止自定义鼠标指针：** 它们已经过时，并且会损害性能和可访问性。

### 排版
* **禁止 Inter 字体：** 禁止使用。请使用 `Geist`、`Outfit`、`Cabinet Grotesk` 或 `Satoshi`。
* **禁止超大 H1：** 第一个标题不应显得咄咄逼人。通过字重和颜色控制层级，而不只是依赖巨大字号。
* **衬线字体约束：** 仅在创意/编辑设计中使用衬线字体。**绝不要**在简洁的 Dashboard 中使用衬线字体。

### 布局与间距
* **完美对齐与间距：** 确保内边距和外边距在数学上完美。避免带有尴尬空隙的悬浮元素。
* **禁止三列卡片布局：** 禁止使用通用的“横向排列 3 张等宽卡片”功能展示行。改用双列之字形布局、非对称网格或横向滚动方案。

### 内容与数据（“Jane Doe”效应）
* **禁止通用姓名：** 禁止使用“John Doe”“Sarah Chan”或“Jack Su”。请使用极具创意且听起来真实的姓名。
* **禁止通用头像：** 不要将标准 SVG“鸡蛋”图形或 Lucide 用户图标用作头像。请使用富有创意、可信的照片占位符或具体样式。
* **禁止虚假感数字：** 避免 `99.99%`、`50%` 或基础电话号码（`1234567`）等可预测的输出。使用自然、不规则的数据（`47.2%`、`+1 (312) 847-1928`）。
* **禁止粗制滥造的初创公司名称：** “Acme”“Nexus”“SmartFlow”。请创造高级且符合上下文的品牌名称。
* **禁止空洞词汇：** 避免“Elevate”“Seamless”“Unleash”或“Next-Gen”等 AI 文案陈词滥调。使用具体动词。

### 外部资源与组件
* **禁止失效的 Unsplash 链接：** 不要使用 Unsplash。请使用绝对、可靠的占位符，例如 `https://picsum.photos/seed/{random_string}/800/600` 或 SVG UI Avatars。
* **shadcn/ui 定制：** 可以使用 `shadcn/ui`，但绝不能保持其通用默认状态。你必须自定义圆角、颜色和阴影，使其符合项目的高端美学。
* **生产就绪的整洁度：** 代码必须极其整洁、视觉突出、令人难忘，并在每个细节上经过精心打磨。

## 8. 创意武器库（高端灵感）
不要默认使用通用 UI。请从这个高级概念库中汲取灵感，确保输出在视觉上引人注目且令人难忘。在适当情况下，复杂的滚动叙事或 3D/Canvas 动画应使用 **GSAP (ScrollTrigger/Parallax)** 或 **ThreeJS/WebGL**，而不是基础 CSS 动效。**关键：** 绝不要在同一个组件树中混用 GSAP/ThreeJS 与 Framer Motion。UI/Bento 交互默认使用 Framer Motion。GSAP/ThreeJS 只能用于独立的全页面滚动叙事或 Canvas 背景，并包装在具有严格清理逻辑的 useEffect 块中。

### 标准 Hero 范式
* 不要再使用深色图像上的居中文本。尝试非对称 Hero 区域：文本整洁地左对齐或右对齐。背景应使用高质量且相关的图像，并带有细微的风格化渐隐效果（根据浅色或深色模式，优雅地变暗或变亮并融入背景色）。

### 导航与菜单
* **Mac OS Dock 放大效果：** 位于边缘的导航栏；图标在悬停时流畅缩放。
* **磁性按钮：** 会在物理效果上向指针靠拢的按钮。
* **黏液菜单：** 子项像黏稠液体一样从主按钮分离。
* **灵动岛：** 可变形以显示状态/提醒的胶囊形 UI 组件。
* **上下文径向菜单：** 在点击坐标处准确展开的圆形菜单。
* **悬浮快捷操作盘：** 一个 FAB，以弹簧效果展开成弧形排列的次级操作。
* **巨型菜单显现：** 全屏下拉菜单，以交错淡入方式展示复杂内容。

### 布局与网格
* **Bento 网格：** 非对称、基于图块的分组（例如 Apple 控制中心）。
* **瀑布流布局：** 没有固定行高的错落网格（例如 Pinterest）。
* **色彩网格：** 网格边框或图块呈现细微且持续变化的色彩渐变动画。
* **分屏滚动：** 屏幕两半在滚动时向相反方向滑动。
* **幕布显现：** Hero 区域在滚动时从中间像幕布一样拉开。

### 卡片与容器
* **视差倾斜卡片：** 跟踪鼠标坐标并产生 3D 倾斜效果的卡片。
* **聚光边框卡片：** 卡片边框在指针下动态发亮。
* **玻璃拟态面板：** 带有内部折射边框的真实磨砂玻璃。
* **全息箔卡片：** 悬停时呈现不断变化的虹彩反射效果。
* **Tinder 滑动卡片堆：** 用户可以滑走的实体感卡片堆。
* **变形模态框：** 按钮无缝扩展成自身的全屏对话框容器。

### 滚动动画
* **粘性滚动卡片堆：** 卡片固定在顶部，并在物理效果上相互堆叠。
* **横向滚动接管：** 将垂直滚动转换为平滑的横向画廊平移。
* **Locomotive 滚动序列：** 帧率直接与滚动条绑定的视频/3D 序列。
* **缩放视差：** 中央背景图像在滚动时无缝放大/缩小。
* **滚动进度路径：** SVG 矢量线条或路线随着用户滚动自行绘制。
* **液态滑动过渡：** 像黏稠液体一样擦过屏幕的页面过渡。

### 画廊与媒体
* **穹顶画廊：** 具有全景穹顶感的 3D 画廊。
* **Coverflow 轮播：** 中间聚焦、两侧向后倾斜的 3D 轮播。
* **拖拽平移网格：** 可向任意方位自由拖动的无边界网格。
* **手风琴图像滑块：** 狭窄的垂直/水平图像条，悬停时完全展开。
* **悬停图像轨迹：** 鼠标身后留下一串弹出并淡出的图像。
* **故障效果图像：** 悬停时短暂出现 RGB 通道偏移的数字失真效果。

### 排版与文本
* **动态跑马灯：** 随滚动反转方向或加速的无尽文本带。
* **文本蒙版显现：** 巨型文字作为视频背景的透明窗口。
* **文本扰码效果：** 加载或悬停时呈现 Matrix 风格的字符解码。
* **环形文本路径：** 沿旋转圆形路径弯曲排列的文本。
* **渐变描边动画：** 渐变沿描边持续流动的轮廓文字。
* **动态排版网格：** 字母网格会避开指针或随之旋转。

### 微交互与效果
* **粒子爆炸按钮：** CTA 在操作成功时碎裂成粒子。
* **液态下拉刷新：** 移动端刷新指示器表现得像分离的水滴。
* **骨架微光：** 光线反射在占位框上移动。
* **方向感知悬停按钮：** 悬停填充效果从鼠标进入的准确方向涌入。
* **点击涟漪效果：** 视觉波纹从点击坐标精确扩散。
* **SVG 线条绘制动画：** 矢量图形实时自行绘制轮廓。
* **网格渐变背景：** 像熔岩灯一样有机运动的彩色团块。
* **镜头模糊景深：** 动态模糊背景 UI 图层，以突出前景操作。

## 9. “MOTION-ENGINE” BENTO 范式
生成现代 SaaS Dashboard 或功能区域时，你必须采用以下“Bento 2.0”架构与动效理念。它超越静态卡片，强制采用一种“Vercel 核心感与 Dribbble 简洁感相融合”的美学，并高度依赖持续的物理动效。

### A. 核心设计理念
* **美学：** 高端、极简且实用。
* **调色板：** 背景使用 `#f9fafb`。卡片使用纯白色（`#ffffff`），并带有 1px 的 `border-slate-200/50` 边框。
* **表面：** 所有主要容器使用 `rounded-[2.5rem]`。应用“扩散阴影”（非常浅且扩散范围宽的阴影，例如 `shadow-[0_20px_40px_-15px_rgba(0,0,0,0.05)]`），在不产生杂乱感的情况下营造深度。
* **排版：** 严格使用 `Geist`、`Satoshi` 或 `Cabinet Grotesk` 字体栈。标题使用细微的字距调整（`tracking-tight`）。
* **标签：** 标题和描述必须放置在卡片的**外部下方**，以保持简洁的画廊式展示效果。
* **像素级精准：** 卡片内部使用宽裕的 `p-8` 或 `p-10` 内边距。

### B. 动画引擎规范（持续运动）
所有卡片都必须包含**“持续微交互”**。使用以下 Framer Motion 原则：
* **弹簧物理效果：** 不使用线性缓动。使用 `type: "spring", stiffness: 100, damping: 20`，营造高级且有重量感的效果。
* **布局过渡：** 大量使用 `layout` 和 `layoutId` 属性，确保重新排序、调整尺寸和共享元素状态过渡流畅。
* **无限循环：** 每张卡片都必须拥有无限循环的“活动状态”（脉冲、打字机、漂浮或轮播），确保 Dashboard 富有“生命力”。
* **性能：** 使用 `<AnimatePresence>` 包装动态列表，并针对 60fps 进行优化。**性能关键：** 任何持续运动或无限循环都必须经过记忆化（React.memo），并完全隔离在自身的微型客户端组件中。绝不要触发父级布局重新渲染。

### C. 5 种卡片原型（微动画规范）
构建 Bento 网格时（例如，第 1 行：3 列 | 第 2 行：2 列，按 70/30 分割），实现以下特定微动画：
1. **智能列表：** 一个带有无限自动排序循环的垂直项目堆栈。项目使用 `layoutId` 交换位置，模拟 AI 实时确定任务优先级。
2. **命令输入框：** 带有多步骤打字机效果的搜索/AI 输入栏。它循环展示复杂提示，包含闪烁光标和带有微光加载渐变的“处理中”状态。
3. **实时状态：** 带有“呼吸”状态指示器的日程安排界面。包含一个使用“过冲”弹簧效果出现的弹出通知徽章，停留 3 秒后消失。
4. **宽幅数据流：** 数据卡片或指标的横向“无限轮播”。确保循环无缝（使用 `x: ["0%", "-100%"]`），速度应显得轻松自然。
5. **上下文 UI（专注模式）：** 文档视图先对文本块执行交错高亮动画，随后让带有微型图标的悬浮操作工具栏以“漂浮进入”效果出现。
