一个模糊的想法出现了——它过于庞大，无法在一次智能体会话中处理完，而且笼罩在迷雾之中：从当前状态到形成计划的路线尚不可见。此技能用于规划这条路线：建立一张地图，然后逐一处理其中的工单，直到通往目标的道路清晰可见。该地图不局限于任何领域——工程工作、课程内容，或任何符合这种形式的事项都适用。

## 地图

地图是一个紧凑的 Markdown 文件，每次寻路工作对应一个文件，与项目一起由 git 跟踪。它是规范性产物——**每次会话都会将整张地图作为上下文加载**，因此必须保持紧凑。

工单执行期间创建的资产应从地图中链接，而不是复制到地图内。

### 结构

每个条目（“工单”）各自占一个章节，并以简短的短横线命名 slug 作为键，
读起来像一个迷你标题（例如 `relational-db`、`auth-strategy`、`cache-layer`）——
足够简洁以保持 token 使用效率，并且在地图内唯一。

```markdown
## relational-db: 关系型还是非关系型数据库？

阻塞于: <slug>, <slug>
状态: open | in-progress | resolved
类型: Research | Prototype | Grilling | Task

### 问题

<question-here>

### 答案

<answer-here>
```

slug 是规范 ID，用于每一条 `Blocked by` 边以及正文中的
引用；冒号后的标题是可选的。当工单 `Blocked by` 列表中的每个工单都为 `resolved` 时，
该工单即为**未阻塞**。会话通过将其工单设置为 `Status: in-progress` 并在开始任何工作前保存地图来
**认领**该工单，以便并发会话跳过它。

每个工单的规模必须控制在一次 100K token 的智能体会话内。

## 工单类型

工单有四种类型：

- **Research**：阅读文档、第三方 API 或知识库等本地资源。创建一份 Markdown 摘要作为资产。当需要当前工作目录之外的知识时使用此类型。
- **Prototype**：通过制作一个廉价、粗糙但具体、可供反馈的产物来提高讨论的具体程度——例如大纲、初稿、桩代码，或通过 /prototype 技能创建的 UI/逻辑代码。将原型创建为资产。当关键问题是“它应该是什么样子”或“它应该如何运行”时使用此类型。
- **Grilling**：与智能体对话。使用 /grilling 和 /domain-modeling 技能。每次只问一个问题。这是默认类型。
- **Task**：在讨论能够继续之前必须完成的实际人工工作——没有需要决定、制作原型或研究的内容。例如将数据从一个位置移到另一个位置、注册第三方服务、配置访问权限。智能体会尽可能自动完成；否则，它会向人类提供一份精确的手动操作清单。工作完成后即为已解决；答案会记录已完成的工作，以及后续工单所依赖的任何结果事实（凭据位置、新 URL、行数）。

## 战争迷雾

地图在前沿之外是_刻意_不完整的——不要绘制尚且看不见的内容。前沿是已知区域边缘那些未阻塞的工单；解决它们以推动前沿向前。逐个工单地驱散战争迷雾，直到通往目标的道路清晰可见，并且不再有工单剩余。

## 调用

分为两个分支。无论哪种方式，**每次会话都以一次[交接](#交接)结束**——每次会话绝不解决超过一个工单。

### 绘制地图

用户以一个模糊的想法调用。

1. 运行一次 `/grilling` 和 `/domain-modeling` 会话，以梳理尚未解决的决策。
2. 编写一张新地图——大部分仍是迷雾，标明前沿，并就地解决可以轻松决定的条目。
3. 交接。绘制地图是一次会话的工作；不要同时解决工单。

### 逐步处理地图

用户使用现有地图的路径调用。工单 slug 是**可选的**——如果没有指定，则由你而不是用户选择下一个决策。

1. 将**整张地图**加载为上下文。
2. 选择工单。如果用户指定了一个，就使用该工单。否则，按文档顺序选择第一个[未阻塞](#结构)且为 `open` 的工单。[认领它](#结构)：在开始任何工作之前，将 `Status: in-progress` 写入并保存。
3. 解决该工单，按需调用技能——包括 `## Notes` 块中指定的任何技能。如有疑问，使用 `/grilling` 和 `/domain-modeling`。
4. 将答案记录在工单正文中，并将 `Status: resolved`。
5. 添加新发现的工单，并设置正确的 `Blocked by` 边。如果已做出的决策使地图的其他部分失效，请更新或删除那些工单。
6. 交接。

用户可能会并行处理未阻塞的工单，因此应预期其他智能体会在各自的会话中编辑地图。

## 交接

每次会话结束时都要清除上下文，并打开一个或多个全新会话。最后提供一个用户可复制粘贴的 **Next steps** 块。分为两种情况：

**仍有开放工单。** 列出当前未阻塞的工单，然后给出两种可复制粘贴的选项：一个用于单会话的纯命令（由你选择下一个工单），以及为每个未阻塞工单提供一条固定工单命令，以便并行运行。每个全新窗口粘贴一行——可以打开其中一个、部分或全部。

> **Next steps** — 3 个工单未阻塞：`auth-strategy`、`cache-layer`、`rate-limits`。
> 清除上下文，然后打开全新会话。
>
> **One session** — 解决下一个未阻塞的工单：
> ```
> Invoke /wayfinder with the map at <path>.
> ```
>
> **Parallel** — 每个窗口粘贴一行，最多可粘贴全部 3 行：
> ```
> Invoke /wayfinder with the map at <path>, ticket auth-strategy.
> Invoke /wayfinder with the map at <path>, ticket cache-layer.
> Invoke /wayfinder with the map at <path>, ticket rate-limits.
> ```

**没有开放工单。** 迷雾已被驱散到足以看清通往目标的道路——地图已经完成。（最初的 grilling 也可能发现根本不存在任何迷雾，在这种情况下，从一开始就没有地图需要绘制。）建议直接实施，或使用 `/to-prd` 来安排跨多个会话的实施工作。

## 备注

这是一个可选块，用于声明**领域**、每次会话都应 `consult` 的任何技能，以及本次工作的自由格式长期偏好。
