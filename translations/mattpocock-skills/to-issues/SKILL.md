# 转为问题

使用垂直切片（示踪弹）将计划拆分为可独立认领的问题。

问题跟踪器和分类标签词汇应已提供给你——如果没有，请运行 `/setup-matt-pocock-skills`。

## 流程

### 1. 收集上下文

基于对话上下文中已有的所有内容开展工作。如果用户传入问题引用（问题编号、URL 或路径）作为参数，请从问题跟踪器中获取它，并阅读其完整正文和评论。

### 2. 探索代码库（可选）

如果你尚未探索代码库，请先进行探索，以了解代码的当前状态。问题标题和描述应使用项目领域术语表中的词汇，并遵循你所涉及区域的 ADR。

寻找对代码进行前置重构的机会，使实现更容易。“先让变更变得容易，再完成这个容易的变更。”

### 3. 起草垂直切片

将计划拆分为**示踪弹**问题。每个问题都是一个贯穿所有集成层的端到端薄垂直切片，而不是某一层的水平切片。

<vertical-slice-rules>

- 每个切片都要交付一条贯穿每一层（schema、API、UI、tests）的狭窄但完整的路径
- 已完成的切片必须能够独立演示或验证
- 任何前置重构都应首先完成

</vertical-slice-rules>

### 4. 向用户提问

以编号列表的形式展示建议的拆分方案。对于每个切片，显示：

- **标题**：简短的描述性名称
- **被阻塞于**：必须先完成哪些其他切片（如有）
- **涵盖的用户故事**：该切片处理哪些用户故事（如果源材料中包含用户故事）

询问用户：

- 这个粒度是否合适？（过粗／过细）
- 依赖关系是否正确？
- 是否应该合并某些切片，或进一步拆分？

持续迭代，直到用户批准该拆分方案。

### 5. 将问题发布到问题跟踪器

对于每个获批的切片，在问题跟踪器上发布一个新问题。使用下面的问题正文模板。这些问题应视为已可供 AFK agents 处理，因此除非另有指示，请使用正确的分类标签发布它们。

按依赖顺序发布问题（阻塞项优先），以便在“被阻塞于”字段中引用真实的问题标识符。

<issue-template>
## 父问题

对问题跟踪器中父问题的引用（如果来源是现有问题；否则省略本节）。

## 要构建的内容

对该垂直切片的简明描述。描述端到端行为，而不是逐层描述实现。

避免指定具体文件路径或代码片段——它们很快就会过时。例外情况：如果原型生成的片段比文字更精确地表达了某项决策（state machine、reducer、schema、type shape），请将其内联在此处，并简要注明它来自原型。仅保留包含关键决策的部分——不是可运行的演示，只保留重要内容。

## 验收标准

- [ ] 标准 1
- [ ] 标准 2
- [ ] 标准 3

## 被阻塞于

- 对阻塞工单的引用（如有）

如果没有阻塞项，则填写“无 - 可以立即开始”。

</issue-template>

不要关闭或修改任何父问题。
