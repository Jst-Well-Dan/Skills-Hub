技能存在的意义，是从随机系统中驯化出确定性。**可预测性**——智能体每次运行时都采用相同的_过程_，而不是产生相同的输出——是根本美德；下文的每一种手段都服务于此。

**粗体术语**在 [`GLOSSARY.md`](GLOSSARY.md) 中定义；请在那里查阅其完整含义。

## 调用

有两种选择，各自承担不同的成本：

- **模型调用型**技能保留一段**描述**，因此智能体可以自主触发它，_并且_其他技能也可以调用它（你仍然也可以输入它的名称）。它会增加**上下文负载**——每一轮中，描述都会占据上下文窗口。实现方式：省略 `disable-model-invocation`，并编写面向模型、包含丰富触发措辞的描述（“当用户想要……、提到……时使用”）。
- **用户调用型**技能会让智能体无法接触到描述：只有你输入它的名称才能调用它——其他技能也无法调用。它的上下文负载为零，但会消耗**认知负载**：必须由_你_充当索引，记住它的存在。实现方式：设置 `disable-model-invocation: true`；此时 `description` 面向人类——只保留一行摘要，去掉触发条件列表。

只有当智能体必须自行调用该技能，或其他技能必须调用它时，才选择模型调用。如果它始终只会被手动触发，就将其设为用户调用型，从而不承担上下文负载。

当用户调用型技能多到超出你的记忆能力时，可以用一个**路由技能**来解决堆积的认知负载：创建一个用户调用型技能，在其中列出其他技能以及何时调用各个技能。

## 编写描述

模型调用型技能的**描述**承担两项工作——说明该技能是什么，并列出应当触发它的**分支**。每个词都会增加**上下文负载**，因此描述比正文更需要严格删减：

- **将技能的引导词前置**——描述正是在这里完成调用工作。
- **每个分支只保留一个触发条件。**仅仅换一种说法来命名同一分支的同义表达属于**重复**——“使用 TDD 构建功能……要求测试优先开发”只是把同一个分支写了两遍。将其合并；只保留真正不同的分支。
- **删掉正文中已有的身份说明。**描述中只保留触发条件，以及任何“当其他技能需要……时”之类的调用条款。

## 信息层级

技能由两类内容构成——**步骤**和**参考资料**——二者可以自由组合：一个技能可以全部由步骤组成、全部由参考资料组成，也可以两者兼有。核心决策是应该使用哪一种，以及每一项内容位于**信息层级**的哪个位置。信息层级是一架按智能体对材料的即时需求程度排列的梯子：

1. **技能内步骤**——`SKILL.md` 中按顺序执行的操作，是首要层级：智能体要做什么，以及按什么顺序做。每个步骤都以一个**完成标准**结束，即告诉智能体工作已经完成的条件。让它_可检查_（智能体能否判断完成与未完成？），并在必要时做到_穷尽_（应写“每个修改过的模型均已纳入”，而不是“生成变更列表”）——模糊的标准会诱发**过早完成**。
2. **技能内参考资料**——`SKILL.md` 中按需查阅的定义、规则或事实。它通常是一组合理的扁平同级内容（例如审查中的每条规则都位于同一层级）——这是良好的安排，而不是坏味道。_本技能全部由参考资料组成。_
3. **外部参考资料**——从 `SKILL.md` 移到单独文件中的参考资料，通过**上下文指针**访问，并且只在指针触发时加载。（其范围涵盖已_披露_的参考资料——例如 `GLOSSARY.md` 这样的同级文件，仍属于技能的一部分——一直到位于技能系统之外、任何技能都可以指向的完全**外部参考资料**。）

严格的完成标准会推动深入的**实地工作**——即智能体在工作中进行的挖掘——无论技能是否包含步骤，因为“应用了每一条规则”对扁平参考资料的约束，与“完成了每一个步骤”对顺序流程的约束相同。

下沉得太少，顶层就会臃肿；下沉得太多，又会把智能体实际需要的材料隐藏起来。如何处理这种张力，就是整个决策的核心。

**渐进式披露**是沿着层级向下移动——把内容从 `SKILL.md` 移到链接文件中——从而让顶层保持清晰易读。实现方式：在技能文件夹中放置一个链接的 `.md` 文件，并根据其内容命名（本技能将完整定义披露到 `GLOSSARY.md`）。有些技能有不止一种用法，每种不同的用法都是一个**分支**——不同的运行会沿技能中的不同路径前进。分支是最清晰的披露判断标准：每个分支都需要的内容内联，只被部分分支访问的内容则放到指针之后。决定智能体何时以及能多可靠地访问材料的，是**上下文指针**的_措辞_，而不是它的目标。

信息层级决定一项内容_向下放多深_，而**共置**决定内容到达该层级后，_哪些东西放在一起_：将一个概念的定义、规则和注意事项放在同一标题下，不要分散各处，这样阅读其中一部分时也会同时看到其相邻内容。

## 何时拆分

**粒度**是指技能划分得有多细，而每次切分都会消耗两种负载之一，因此只有在收益足以抵偿成本时才进行拆分。有两种切分方式：

- **按调用拆分**——当存在一个应当独立触发技能的不同**引导词**，或其他技能必须调用它时，拆出一个**模型调用型**技能。你要为新增且始终加载的**描述**支付**上下文负载**，因此这种独立可达性必须值得付出成本。
- **按顺序拆分**——当一系列**步骤**中尚未执行的后续步骤（某一步的**完成后步骤**）诱使智能体匆忙完成眼前步骤时，将这段步骤拆开（即发生**过早完成**）。让后续步骤暂时不可见，会鼓励智能体在当前任务上做更多**实地工作**。

## 删减

让每项含义都保持一个**单一事实来源**：只设一个权威位置，使行为变更只需修改一处。

检查每一行的**相关性**：它是否仍然与技能所做的事情有关？

然后逐句寻找**无效内容**，而不只是逐行检查：单独对每个句子运行无效内容测试；一旦某个句子未通过测试，就删除整个句子，而不是只删减其中的词语。要果断——大多数测试失败的文字都应该删除，而不是改写。

## 引导词

**引导词**是模型预训练中已经存在、智能体在运行技能时用来思考的精炼概念（例如_课程_、_战争迷雾_、_曳光弹_）。它在文本中反复出现（但并非必须如此——强有力的引导词可能只需出现一次），逐渐形成分布式定义，并通过调用模型已有的先验知识，以最少的 token 锚定一整片行为区域。

它以两种方式服务于可预测性。在正文中，它锚定_执行_：每当该词出现时，智能体都会采用相同的行为。在描述中，它锚定_调用_：当你的提示词、文档和代码中出现同一个词时，智能体会将这种共享语言与技能联系起来，从而更可靠地触发技能。

寻找机会，重构技能以使用引导词。一个在三处完整写出的三元组（**重复**），一段用一句话影射某个概念的描述——每一处都是渴望被**折叠**成一个 token 的文字。例如：

- “快速、确定、低开销” -> _紧凑_——将一个阶段中反复表述的品质——归入一个预训练词汇（一个_紧凑_循环）。
- “一个你信得过的循环” -> _红_——将模糊的关卡转化为二元可观察状态（循环会因为该缺陷变_红_，否则就不会）。

这样可以获得双重收益：token 更少，_并且_为智能体提供一个更锐利的思维挂钩。假设每个技能都携带着可由引导词淘汰的重复表述——去把它们找出来。

## 失败模式

使用以下模式诊断用户在使用技能时可能遇到的问题。

- **过早完成**——在一个步骤真正完成之前就结束它，注意力滑向了_完成这件事_本身。防御措施依次为：先强化完成标准（成本低、影响局部）；只有当标准无法避免地模糊，_并且_你观察到赶工行为时，才通过拆分来隐藏完成后步骤（即按顺序切分）。
- **重复**——同一含义出现在多个位置。它会增加维护成本和 token，并让某项含义在层级中的显著程度被夸大，超过其真实等级。
- **沉积**——由于添加内容让人感觉安全，而删除内容让人感觉有风险，陈旧的层次便不断沉淀。任何缺乏删减纪律的技能，默认都会走向这一结局。
- **蔓延**——一个技能单纯变得过长，即使每一行都仍然有效且独一无二。它会损害可读性和可维护性，并浪费 token。解决方法就是信息层级：通过指针披露**参考资料**，并按**分支**或顺序拆分，使每条路径只携带自身需要的内容。
- **无效内容**——模型默认就会遵守的一行内容，因此你付出了负载，却什么也没有表达。测试方法：相较于默认行为，它是否会改变行为？一个软弱的引导词（当智能体本来就还算认真时说_要认真_）属于无效内容；解决办法是换成更强的词（_不达目的绝不罢休_），而不是换一种技巧。
