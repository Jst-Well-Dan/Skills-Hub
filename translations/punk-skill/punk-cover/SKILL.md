# Punk 封面

## 核心规则

`punk-cover` 是一个封面生成工作流，并不拥有风格。必须从仓库级 `styles/` 库中恰好选择一种可复用风格，然后将该风格原子编译为封面形态。

最终图像提示词不能是“封面指令 + 风格指令”的松散拼接。它必须是一份将所选风格应用于封面格式的、完整融合且专用于封面的提示词。

使用三类输入：

1. `punk-cover` 任务字段：平台、宽高比、标题清晰度、文章摘要、封面传播目标和通用输出约束。
2. 所选风格的 `META.md` 元数据和 `STYLE.md` 可复用视觉风格原子。
3. `references/cover-prompt-blueprint.md`，它定义完整的封面提示词形态。

风格文件定义可复用的视觉语言。封面蓝图定义输出形式。最终提示词必须将二者融合为一份完整的封面生成提示词。

## 资源

- 阅读 `references/style-catalog.md` 以列出或选择封面风格。
- 编写最终提示词前，阅读 `references/cover-prompt-blueprint.md`。
- 对于所选风格，同时阅读：
  - `../../styles/{style-id}/META.md`
  - `../../styles/{style-id}/STYLE.md`
- 仅展示 `META.md` 元数据中的 `outputs` 包含 `cover` 或 `poster` 的风格。
- 除非元数据明确包含 `cover` 或 `poster`，否则不要在 `punk-cover` 菜单中展示照片、头像、人像、宠物专用、拍立得专用或图像重混风格。
- 新的运行中不要读取已弃用的 `references/templates/` 目录。保留该目录仅为兼容旧的外部引用。

## 工作流

1. 分析源材料：
   - 提取核心视觉主体。
   - 如果存在用户提供的完整标题或主题，应予以保留，但不要将文章全文复制到任何输出字段中。
   - 当所选风格包含副标题字段时，起草一个可选副标题。
   - 总结语境、受众、情绪、隐喻和禁用元素。
   - 将长篇源材料转化为精炼的派生字段：标题/主题、1-3 句语境摘要、视觉主体、受众、情绪、隐喻和禁用元素。

2. 生成任何提示词前，确认平台和宽高比：
   - 小红书：`3:4`
   - 微信公众号：`2.35:1`
   - X：`5:2`
   - 自定义：严格保留用户提供的比例。
   - 如果用户仅提供了源内容，询问他们希望发布到哪个平台。此时不要生成提示词。
   - 如果用户提供了自定义比例，则直接使用；除非平台会影响措辞，否则不要再询问平台。
   - 仅当用户已经提供平台、比例，或明确表示让技能自动决定一切时，才跳过此问题。

3. 生成任何提示词前，确认风格：
   - 如果用户指定了目录中的某一种风格，使用该风格。
   - 如果未指定风格，根据内容恰好推荐三种符合条件的目录风格，并分别给出一句理由，然后请用户选择一种或提供自定义风格方向。
   - 除非用户要求查看完整菜单，否则默认不要展示所有符合条件的风格。
   - 仅当用户明确表示让技能自动决定一切时，才自动选择一种风格；不能仅仅因为用户提供了文章就自动选择。

4. 使用以下确认关卡：
   - 当平台/比例或风格缺失时，询问问题后停止。不要填写风格文件、保存提示词文件或生成图像。
   - 对于仅提供文章的输入，首次响应应包含平台问题和三种推荐风格。
   - 如果平台/比例和风格均已知，则无需询问，继续执行。

5. 编译最终图像提示词：
   - 使用 `references/cover-prompt-blueprint.md` 作为 `prompts/cover.md` 的必需结构。
   - 从 `../../styles/{style-id}/STYLE.md` 中读取恰好一个所选风格的视觉原子。
   - 从 `../../styles/{style-id}/META.md` 中读取所选风格的元数据，包括存在时的 `style_anchors`、`cover_shape_adaptation`、`must_preserve` 和 `avoid_when_applying_to_cover`。
   - 提取所选风格不可妥协的视觉锚点：材质、空间逻辑、标题处理、字体排印方式、纹理、色彩系统以及该风格特有的负面约束。
   - 将封面任务字段和风格锚点融合为一份完整的封面提示词。最终提示词应像 `exports/` 中旧版的完整提示词一样，是一份完整的封面生成简报，而不是两个互不相关的提示词片段拼贴。
   - 包含以下封面形态章节：角色/任务、输入字段、内容理解、标题层级、封面构图、风格应用、图文关系、字体排印、色彩/材质/纹理、负面约束和最终标准。
   - 每一个封面决策都必须通过所选风格表达。例如，如果风格是撕纸拼贴，那么标题、主体、辅助文字、背景和隐喻都必须使用撕纸、旧报纸、胶带、颗粒、半色调和纸张层次来实现；不能只制作一个通用封面，再附加一些拼贴风格词汇。
   - 不要将原始 `STYLE.md` 内容作为独立的第二章节附加进去。应重写其风格原子，并使之适配封面蓝图。
   - 不要组合多种风格，也不要添加第二个自定义风格章节。
   - 替换或解析所有显式占位符，例如 `{{主题词}}`、`{{副标题，可留空}}`、`{{画幅比例...}}`、`{{语言...}}`、`{{用途...}}`、`{{补充背景，可留空}}`、`{{情绪倾向...}}`、`{{不想出现的元素，可留空}}` 以及任何其他 `{{...}}` 字段。
   - 如果所需细节没有对应占位符，将其合并到最近的封面章节中，例如 `补充语境`、`风格落地方式` 或 `禁用元素`。
   - 对于长篇文章，标题/主题字段应填写精炼的派生标题或标题层级，而不是文章正文。
   - 提示词中仅放置经过总结的语境；不要将原始文章正文粘贴到最终提示词中。
   - 只有当提示词明确说明字段可留空时，才能将可选字段留空。
   - 不要在最终提示词中输出分析过程。

6. 生成图像前保存文件：
   - 创建 `punk-assets/punk-cover/{slug}/prompts/cover.md`，其中包含完整填写的提示词。
   - 如果图像生成结果为当前运行返回了明确的本地文件路径、可下载 URL 或图像字节，则将该产物保存为 `punk-assets/punk-cover/{slug}/cover.png`。
   - 不要通过扫描宽泛的生成图像目录来推断正确产物，因为这些目录可能包含其他运行产生的无关图像。
   - 如果图像生成工具只返回内联预览，而没有提供当前运行可明确检索的产物，则不要创建虚假的 `cover.png`。

7. 保存提示词后，如果有可用的图像生成工具（例如 `image_gen`），默认生成图像。内联预览生成应视为图像生成成功，但只有当工具明确提供当前运行的产物时，才能将本地 `cover.png` 的保存视为成功。仅当用户明确要求只输出提示词，或当前环境没有图像生成工具时，才跳过图像生成。如果图像生成不可用，则返回提示词文件路径和完整提示词内容。

## 首次响应格式

对于没有平台和风格、仅提供文章的输入，简洁询问：

1. 此封面应面向哪个平台/宽高比？
   - 小红书：`3:4`
   - 微信公众号：`2.35:1`
   - X：`5:2`
   - 自定义：提供比例
2. 推荐风格：
   - `风格 A`：与文章内容相关的理由。
   - `风格 B`：与文章内容相关的理由。
   - `风格 C`：与文章内容相关的理由。

最后请用户选择一个平台和一种风格；如果希望技能自动决定一切，则回复“自动”。

## 风格选择启发式规则

- 使用 `outputs` 元数据包含 `cover` 或 `poster` 的风格。
- 对于战略、产品、AI、创业、行业、咨询或分析类内容，使用商业/报告风格。
- 对于科学、研究、医学、工程或机制密集型内容，使用期刊/概念风格。
- 对于需要更强传播性的社交帖子，使用拼贴、巨型标题、色块、砖块或弥散风格。
- 对于抽象、哲学、批判性或高对比度的编辑主题，使用黑白极简或先锋几何风格。
- 不要推荐元数据标记为仅限头像、仅限人像、仅限宠物、仅限拍立得或仅限图像的风格，除非它们同时声明了 `cover` 或 `poster`。

## 封面提示词蓝图

使用 `references/cover-prompt-blueprint.md` 作为完整的提示词结构。保留下方代码块，仅用于规定必须体现在整合后最终提示词中的任务字段内容。

```text
# punk-cover 封面任务指令

为 {platform} 创建一张且仅一张封面图。宽高比：{ratio}。

仅使用以下派生内容：
- 标题/主题：{title_or_topic}
- 可选副标题：{subtitle}
- 简短语境摘要：{summary}
- 视觉主体：{visual_subject}
- 受众：{audience}
- 情绪：{mood}
- 视觉隐喻：{metaphor}
- 禁用元素：{banned_elements}

主标题必须完整、准确且清晰可读。如果源标题很长，应提取一个简短且具有冲击力的视觉主标题，同时通过较小字号的标题、副标题或语境说明保留完整含义。

对于长篇文章，仅使用标题、摘要、视觉主体、隐喻和补充语境等派生字段。不要将原始文章正文粘贴到图像、提示词、元数据或小字系统中。

封面必须适合传播：第一眼能够识别主题，第二眼能够发现视觉隐喻。图像应呈现出经过精心设计的编辑封面感，而不是通用插图。

避免常见的封面问题：PPT 封面感、课程封面感、通用信息图模板、电商广告、无关装饰、标题拼写错误、缺少标题、标题被裁切至无法辨认，或标题被视觉元素严重遮挡。

仅生成一张最终图像。不要输出说明、备选方案、网格、联系表或多方案构图。
```

## 输出规范

- 最终生成的提示词必须是一份专用于封面且完整融合的提示词，由封面任务字段、`references/cover-prompt-blueprint.md` 和恰好一个所选风格原子编译而成。
- 不要将所选风格的 `STYLE.md` 作为独立的第二章节粘贴进去。应将其风格原子适配到封面蓝图中。
- 最终提示词必须保留所选风格在 `META.md` 和 `STYLE.md` 中不可妥协的锚点。
- 不要将长篇源文本复制到最终提示词中；应使用摘要和提取后的字段。
- 不要在提示词文件中包含风格选择理由。
- 不要组合多种风格。
- 除所选风格的视觉层之外，不要添加第二个自定义风格章节。
- 不要在风格菜单中展示非封面风格。
