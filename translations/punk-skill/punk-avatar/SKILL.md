# Punk 头像

## 核心规则

`punk-avatar` 是一个头像形态工作流，而非风格所有者。从仓库级 `styles/` 库中恰好选择一种可复用风格，然后将该风格原子编译到头像形态中。

最终图像提示词不能只是“头像指令 + 风格指令”的松散拼接。它必须是一个整合后的头像专用提示词，将所选风格应用于个人资料图片、肖像头像、物体头像、宠物头像或头像衍生纪念卡。

使用三类输入：

1. `punk-avatar` 任务字段：主体类型、源图像或文本描述、预期用途、相似度策略、头像构图、宽高比、背景简化、裁剪安全以及通用输出约束。
2. 所选风格的 `META.md` 元数据和 `STYLE.md` 可复用视觉风格原子。
3. `references/avatar-prompt-blueprint.md`，它定义了完整的头像提示词结构。

风格文件定义可复用的视觉语言。头像蓝图定义输出形态。最终提示词必须将二者融合成一个完整的头像生成提示词。

## 资源

- 阅读 `references/style-catalog.md` 以列出或选择头像风格。
- 在编写最终提示词前阅读 `references/avatar-prompt-blueprint.md`。
- 对于所选风格，同时阅读：
  - `../../styles/{style-id}/META.md`
  - `../../styles/{style-id}/STYLE.md`
- `punk-avatar` 菜单中仅展示以下五种风格：
  - `pixel-avatar`
  - `grotesque-soul-sketch`
  - `messy-crayon-pet-portrait`
  - `fashion-sketch-observation`
  - `polaroid-keepsake`
- 不要在 `punk-avatar` 菜单中展示封面/海报风格。
- 运行头像任务时，不要读取 `punk-cover` 的参考资料或模板。

## 工作流

1. 分析源材料：
   - 如果用户提供一张或多张图像，将图像输入视为主要依据。
   - 识别主要主体类型：`person`、`pet`、`object` 或 `unclear`。
   - 只提取头像所需的简洁视觉特征：脸部/头部形状、头发或毛发、眼睛、表情、姿态、标志性色彩、服装、配饰、物体轮廓以及任何必须保留的标记。
   - 将文本作为补充背景信息：名字、性格、预期用途、偏好的背景颜色、需保留的元素以及需避免的元素。
   - 如果没有图像，且用户描述的是虚构头像，则按基于描述的生成方式处理。不要承诺与真实照片相似。

2. 确定宽高比：
   - 在 `punk-avatar` 中，默认比例始终为 `1:1`。
   - 如果用户指定 `3:4`、`4:5`、`16:9` 或任何自定义比例，原样保留用户的比例。
   - 不要使用所选风格元数据中的 `default_ratio` 作为头像默认比例。
   - 对于 `polaroid-keepsake`，在 `punk-avatar` 中默认使用 `1:1`；仅当用户明确要求竖版比例时，才生成竖版拍立得卡片。
   - 用户未提供比例时，不要询问比例。

3. 在生成任何提示词前确认风格：
   - 如果用户指定了一种目录中的风格，则使用该风格。
   - 如果未指定风格，根据主体类型推荐 2-3 种符合条件的风格，并请用户选择一种。
   - 缺少风格时，提问后停止。不要填写风格文件、保存提示词文件或生成图像。
   - 仅当用户明确表示让你自动决定一切时，才自动选择一种风格。

4. 推荐规则：
   - 宠物主体：推荐 `凌乱蜡笔宠物肖像`、`拍立得纪念卡` 和 `怪诞灵魂手绘`；当更具图标感的头像可能合适时，加入 `像素头像`。
   - 人物主体：推荐 `怪诞灵魂手绘`、`时尚速写观察页` 和 `像素头像`。
   - 物体主体或不明确的主体：优先推荐 `像素头像`。
   - 不要为人物推荐 `messy-crayon-pet-portrait`。
   - 除非用户明确要求该风格，否则不要为宠物或物体推荐 `fashion-sketch-observation`。
   - 不要为人物或物体推荐 `polaroid-keepsake`。

5. 使用以下确认门槛：
   - 缺少风格：询问风格选择，然后停止。
   - 缺少比例：静默使用 `1:1`。
   - 风格已知：无需询问，继续执行。
   - 如果风格和主体均已明确到足以继续，则编译提示词。

6. 编译最终图像提示词：
   - 使用 `references/avatar-prompt-blueprint.md` 作为 `prompts/avatar.md` 的必需结构。
   - 从 `../../styles/{style-id}/STYLE.md` 中恰好读取一个所选风格的视觉原子。
   - 从 `../../styles/{style-id}/META.md` 中读取所选风格的元数据。
   - 提取所选风格不可妥协的视觉锚点：主体处理、构图、背景表现、线条或纹理系统、色彩逻辑、排版或手写表现、相似度约束以及负面约束。
   - 将头像任务字段和风格锚点融合成一个完整的头像提示词。最终提示词应像一份完整的头像生成简报，而不是两个互不相关的提示词片段拼接在一起。
   - 包含以下头像形态章节：角色/任务、输入字段、源材料解读、主体身份、相似度策略、头像构图、裁剪安全、背景、风格应用、色彩/材质/纹理、可选文字/名字处理、负面约束以及最终标准。
   - 不要将原始 `STYLE.md` 内容作为独立的第二章节附加进去。应改写其风格原子，并使其适配头像蓝图。
   - 不要组合多种风格，也不要添加第二个自定义风格章节。
   - 替换或解析所选风格文件中的所有显式占位符。
   - 对于基于图像的输入，保留可识别的主体身份，但不要创建照片级真实的复制品，除非所选风格要求真实结构。
   - 对于纯文本虚构头像，说明图像应遵循描述，并避免使用“保留照片相似度”等表述。
   - 不要将封面标题层级、文章摘要、平台传播规则或社交媒体封面构图带入头像提示词。
   - 不要在最终提示词中输出分析内容。

7. 在生成图像前保存文件：
   - 创建 `punk-assets/punk-avatar/{slug}/prompts/avatar.md`，写入完整填写后的提示词。
   - 如果图像生成返回当前运行对应的明确本地文件路径、可下载 URL 或图像字节，则将该产物保存为 `punk-assets/punk-avatar/{slug}/avatar.png`。
   - 不要通过扫描范围宽泛的已生成图像目录来推断正确产物，因为这些目录中可能包含其他运行生成的无关图像。
   - 如果图像生成工具只返回内联预览，而没有当前运行对应的明确可获取产物，则不要创建虚假的 `avatar.png`。

8. 保存提示词后，如果有可用的图像生成工具（例如 `image_gen`），默认生成图像。将内联预览生成视为图像生成成功，但只有当工具明确提供当前运行的产物时，才将本地 `avatar.png` 的保存视为成功。仅当用户明确要求只输出提示词，或当前环境没有图像生成工具时，才跳过图像生成。如果图像生成不可用，返回提示词文件路径和完整提示词内容。

## 首次响应格式

对于未指定风格的输入，简洁询问：

```text
默认画幅：1:1。

请选择一个头像风格：
- `风格 A`：与主体相关的推荐理由。
- `风格 B`：与主体相关的推荐理由。
- `风格 C`：与主体相关的推荐理由。

也可以回复 "auto" 让我自动选择。
```

除非用户明确希望查看比例选项，否则不要询问比例。

## 风格选择启发式规则

- 对人物、宠物、物体、符号化头像、图标式个人资料图片以及不明确的主体使用 `pixel-avatar`。
- 对需要呈现出富有表现力、风趣、速写感和鲜明个性的人物或宠物使用 `grotesque-soul-sketch`。
- `messy-crayon-pet-portrait` 仅用于宠物和宠物肖像头像。
- `fashion-sketch-observation` 仅用于人物，尤其适合时尚、旅行、街拍、电影剧照或编辑风个人肖像。
- `polaroid-keepsake` 仅用于宠物，尤其适合纪念、收藏、带名字的宠物卡片以及头像衍生纪念卡。

## 头像提示词蓝图

使用 `references/avatar-prompt-blueprint.md` 作为完整提示词结构。保留下方代码块，仅用于规定必须体现在整合后最终提示词中的任务字段内容。

```text
# punk-avatar 任务指令

创建一张单独的头像图像。宽高比：{ratio}。

仅使用以下派生主体字段：
- 主体类型：{subject_type}
- 生成模式：{image_based_or_description_based}
- 主体身份：{subject_identity}
- 可识别特征：{recognizable_traits}
- 要包含的名字或文字：{name_or_text}
- 预期用途：{use_case}
- 背景偏好：{background_preference}
- 氛围：{mood}
- 保留：{preserve}
- 避免：{avoid}

对于基于图像的输入，在将主体转化为所选风格的同时，保留其最具辨识度的特征。不要声称能够实现完全一致的生物特征身份或照片级真实复制。

对于基于描述的输入，根据描述创建一个虚构头像。不要写明它会保留照片相似度。

头像必须适合作为个人资料图片：在小尺寸下清晰可辨，主体居中或经过有意取景，轮廓清晰，不裁掉重要面部特征或主体标记，背景简化，并且只输出一个最终结果。

仅生成一张最终图像。不要输出解释、替代方案、网格、联系表或多选项构图。
```

## 输出规范

- 最终生成的提示词必须是一个整合后的头像专用提示词，由头像任务字段、`references/avatar-prompt-blueprint.md` 和恰好一个所选风格原子编译而成。
- 不要将所选风格的 `STYLE.md` 作为独立的第二章节粘贴进去。应将其风格原子适配到头像蓝图中。
- 最终提示词必须保留所选风格在 `META.md` 和 `STYLE.md` 中不可妥协的锚点。
- 不要将无关的用户文本复制到最终提示词中；使用简洁的派生主体字段。
- 不要在提示词文件中包含风格选择理由。
- 不要组合多种风格。
- 不要添加封面/海报标题层级、文章摘要或平台封面规则。
