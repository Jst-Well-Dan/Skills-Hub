【模板: 实验复盘】
【意图】这不是普通数据报告、不是仪表板。目标是回答: "这个实验说明了什么, 我们下一步应该上线、停止、继续跑, 还是重新设计?"

【适合输入】
- A/B 测试、增长实验、定价实验、新用户引导改版、功能灰度、邮件实验
- 可以是 markdown、CSV、表格粘贴或混合记录

【必须输出的结构】
1. 标题区: 实验名称、负责人、日期、实验状态、决策。
2. 假设: 原始假设, 必须改写成可验证句式。
3. 实验设置: 受众、实验版本、持续时间、样本量、主要指标、护栏指标。
4. 结果概览: 主要指标提升幅度、绝对变化量、样本、置信度 / 注意事项。
5. 指标表格: 对照组与实验组, 包含主要指标 + 次要指标 + 护栏指标。
6. 结果解读: 解释结果为什么发生, 区分信号、噪声、未知因素。
7. 决策: 上线 / 迭代 / 延长 / 停止四选一, 并给出理由。
8. 后续实验: 2-4 个下一步实验, 每个包含假设、预期影响、工作量。
9. 数据采集说明: 数据缺口、埋点问题、样本偏差。

【设计要求】
- 产品数据团队风格: 清楚、可信、行动导向。
- 首屏必须有大号决策徽章和主要指标变化量。
- 图表可以用 CSS/SVG/Chart.js; 如果用 Chart.js, canvas 外层必须固定高度。
- 不要把结果包装得过度确定; 小样本或缺少显著性时必须明确注意事项。

【可选风格模板 — 参考 assets/】
根据实验语境选择一种, 不要三种混用:
- `assets/product-readout.html`: 默认风格。浅色产品实验复盘, 适合产品经理 / 增长团队 / 管理层复盘。
- `assets/lab-notebook.html`: 研究实验室笔记本, 适合早期实验、定性 + 定量混合、需要保留注意事项的探索实验。
- `assets/growth-console.html`: 深色增长分析控制台, 适合增长团队、实时指标、漏斗 / 激活 / 转化复盘。

如果用户没有指定风格, 优先使用 `product-readout`; 如果材料强调研究过程和不确定性, 使用 `lab-notebook`; 如果材料强调增长指标、漏斗、实时监控或运营节奏, 使用 `growth-console`。

【内容真实性】
- 只使用用户提供的数据。不要捏造 p-value、confidence、样本量。
- 如果没有统计显著性信息, 用 "方向性结果" / "无定论" / "需要更多数据" 表达。
