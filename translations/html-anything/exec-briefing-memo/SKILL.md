【模板：高管决策简报】
【意图】这不是会议纪要、不是周报、不是 PRD。它的唯一目标是帮助决策者在 3 分钟内理解问题并拍板。

【适合输入】
- 长会议记录、调研材料、战略讨论、销售反馈、产品数据、投资备忘
- 用户可能给很多碎片信息；你要提炼成一个明确的决策框架

【必须输出的结构】
1. 备忘录标题栏：主题、负责人、受众、日期、决策截止日期。
2. 待决策事项：用一句话写清楚需要拍板的问题。
3. 建议：明确建议，不要写“可以考虑”。必须包含置信度。
4. 为何是现在：为什么现在需要决定，不决定的代价是什么。
5. 关键事实：5-7 个事实证据，每条标注来源类型（销售 / 产品 / 财务 / 客户 / 运营）。
6. 权衡表：选项 A / 选项 B / 选项 C，对比收益、成本、风险、可逆性。
7. 风险与缓解措施：3-5 个风险，每个给出缓解动作。
8. 决策路径：批准 / 拒绝 / 要求更多证据三种路径各自的下一步。
9. 后续行动：负责人、截止日期、预期交付物。

【设计要求】
- 像顶级咨询公司的一页式决策备忘录：克制、清楚、密度高。
- 首屏必须直接呈现决策事项 + 建议，不要先铺陈背景。
- 使用强层级：大号结论、紧凑证据卡、对比表、状态标签。
- 不要做成长文章；不要做成演示文稿；不要写空泛的商业黑话。

【可选风格模板 — 参考 assets/】
根据决策场景选择一种，不要三种混用：
- `assets/board-memo.html`：默认风格。浅色高管备忘录，适合 CEO/CFO/CRO、运营、产品决策。
- `assets/decision-command.html`：深色指挥中心，适合紧急决策、风险处置、事故、执行/停止、发布关卡。
- `assets/board-paper.html`：正式董事会文件 / 董事会纸质议案，适合董事会、投资人、合规、预算审批。

如果用户没有指定风格，优先使用 `board-memo`；如果材料强调紧急、风险、行动指挥，使用 `decision-command`；如果材料面向董事会或正式审批，使用 `board-paper`。

【内容真实性】
- 不要捏造数字、客户、预算、日期。
- 如果缺少关键信息，在“证据缺口”中列出，但仍给出基于现有证据的暂定建议。
