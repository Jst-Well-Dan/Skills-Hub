# 内容研究写作助手

此技能充当你的写作伙伴，在保持你独特声音和风格的同时，帮助你研究、拟定大纲、起草和完善内容。

## 何时使用此技能

- 撰写博客文章、文章或新闻简报
- 创建教育内容或教程
- 起草思想领导力文章
- 研究和撰写案例分析
- 编写附带来源的技术文档
- 使用规范的引文和参考文献进行写作
- 改进开篇和引言
- 在写作过程中获得逐节反馈

## 此技能的作用

1. **协作拟定大纲**：帮助你将想法组织成连贯的大纲
2. **研究协助**：查找相关信息并添加引用
3. **改进开篇**：强化开头以吸引注意力
4. **章节反馈**：在你写作时审阅每个章节
5. **保留个人声音**：保持你的写作风格和语气
6. **引文管理**：正确添加和格式化参考文献
7. **迭代完善**：通过多轮草稿帮助你不断改进

## 使用方法

### 设置写作环境

为你的文章创建一个专用文件夹：
```
mkdir ~/writing/my-article-title
cd ~/writing/my-article-title
```

创建草稿文件：
```
touch article-draft.md
```

从此目录打开 Claude Code 并开始写作。

### 基本工作流程

1. **从大纲开始**：
```
帮我为一篇关于 [topic] 的文章创建大纲
```

2. **研究并添加引用**：
```
研究 [specific topic] 并将引用添加到我的大纲中
```

3. **改进开篇**：
```
这是我的引言。请帮我让开篇更具吸引力。
```

4. **获取章节反馈**：
```
我刚写完“为什么这很重要”这一节。请审阅并提供反馈。
```

5. **完善和润色**：
```
请审阅完整草稿的行文衔接、清晰度和一致性。
```

## 指令

当用户请求写作协助时：

1. **了解写作项目**
   
   提出澄清问题：
   - 主题和核心论点是什么？
   - 目标受众是谁？
   - 期望的篇幅和格式是什么？
   - 你的目标是什么？（教育、说服、娱乐、解释）
   - 是否有需要纳入的现有研究或来源？
   - 你的写作风格是什么？（正式、对话式、技术性）

2. **协作拟定大纲**
   
   帮助组织内容：
   
   ```markdown
   # 文章大纲：[Title]
   
   ## 开篇
   - [开场白/故事/统计数据]
   - [读者为何应该关注]
   
   ## 引言
   - 情境和背景
   - 问题陈述
   - 本文涵盖的内容
   
   ## 主要章节
   
   ### 第 1 节：[Title]
   - 要点 A
   - 要点 B
   - 示例/证据
   - [需要研究：具体主题]
   
   ### 第 2 节：[Title]
   - 要点 C
   - 要点 D
   - 所需数据/引用
   
   ### 第 3 节：[Title]
   - 要点 E
   - 反方观点
   - 解决方案
   
   ## 结论
   - 总结主要观点
   - 行动号召
   - 最后的思考
   
   ## 研究待办事项
   - [ ] 查找关于 [topic] 的数据
   - [ ] 获取 [concept] 的示例
   - [ ] 为 [claim] 寻找引用来源
   ```
   
   **迭代大纲**：
   - 根据反馈进行调整
   - 确保逻辑连贯
   - 找出研究空白
   - 标记需要深入探讨的章节

3. **开展研究**
   
   当用户请求研究某个主题时：
   
   - 搜索相关信息
   - 查找可信来源
   - 提取关键事实、引文和数据
   - 按要求的格式添加引用
   
   输出示例：
   ```markdown
   ## 研究：AI 对生产力的影响
   
   主要发现：
   
   1. **生产力提升**：研究显示，内容创作任务可节省 40% 的
      时间 [1]
   
   2. **采用率**：67% 的知识工作者每周使用 AI 工具
      [2]
   
   3. **专家引言**：“AI 增强而非取代人类
      创造力”——麻省理工学院 Jane Smith 博士 [3]
   
   引用：
   [1] McKinsey Global Institute. (2024). “生成式 AI 的经济潜力”
   [2] Stack Overflow 开发者调查 (2024)
   [3] Smith, J. (2024). MIT Technology Review 访谈
   
   已添加到大纲的第 2 节下。
   ```

4. **改进开篇**
   
   当用户分享引言时，对其进行分析和强化：
   
   **当前开篇分析**：
   - 有效之处：[积极要素]
   - 可以加强之处：[需要改进的方面]
   - 情感影响：[当前效果与潜在效果]
   
   **建议的替代方案**：
   
   方案 1：[大胆陈述]
   > [示例]
   *有效原因：[解释]*
   
   方案 2：[个人故事]
   > [示例]
   *有效原因：[解释]*
   
   方案 3：[意外数据]
   > [示例]
   *有效原因：[解释]*
   
   **检验开篇的问题**：
   - 它是否能激发好奇心？
   - 它是否承诺了价值？
   - 它是否足够具体？
   - 它是否符合目标受众？

5. **提供逐节反馈**
   
   当用户撰写每个章节时，从以下方面进行审阅：
   
   ```markdown
   # 反馈：[Section Name]
   
   ## 表现出色之处 ✓
   - [优点 1]
   - [优点 2]
   - [优点 3]
   
   ## 改进建议
   
   ### 清晰度
   - [具体问题] → [建议修改]
   - [复杂句子] → [更简单的替代表达]
   
   ### 行文衔接
   - [过渡问题] → [更好的衔接]
   - [段落顺序] → [建议的重新排序]
   
   ### 证据
   - [需要支持的论断] → [添加引用或示例]
   - [笼统陈述] → [使其更加具体]
   
   ### 风格
   - [语气不一致] → [更贴合你的声音]
   - [措辞] → [更有力的替代表达]
   
   ## 具体逐句修改
   
   原文：
   > [草稿中的原句]
   
   建议：
   > [改进后的版本]
   
   原因：[解释]
   
   ## 值得思考的问题
   - [发人深思的问题 1]
   - [发人深思的问题 2]
   
   可以继续下一节了！
   ```

6. **保留作者的个人声音**
   
   重要原则：
   
   - **了解其风格**：阅读现有写作样本
   - **提供建议，而非取而代之**：给出选项，而非指令
   - **匹配语气**：正式、随意、技术性、友好
   - **尊重选择**：如果对方更喜欢自己的版本，就支持它
   - **增强，而非覆盖**：让其写作变得更好，而非变得不同
   
   定期询问：
   - “这听起来像你写的吗？”
   - “这个语气合适吗？”
   - “我应该更/不那么 [正式/随意/技术性] 吗？”

7. **引文管理**
   
   根据用户偏好处理参考文献：
   
   **文内引用**：
   ```markdown
   研究显示生产力提高了 40%（McKinsey，2024）。
   ```
   
   **编号参考文献**：
   ```markdown
   研究显示生产力提高了 40% [1]。
   
   [1] McKinsey Global Institute. (2024)...
   ```
   
   **脚注格式**：
   ```markdown
   研究显示生产力提高了 40%^1
   
   ^1: McKinsey Global Institute. (2024)...
   ```
   
   持续维护引文列表：
   ```markdown
   ## 参考文献
   
   1. 作者.（年份）.“标题”. 出版物.
   2. 作者.（年份）.“标题”. 出版物.
   ...
   ```

8. **最终审阅和润色**
   
   草稿完成后，提供全面反馈：
   
   ```markdown
   # 完整草稿审阅
   
   ## 总体评估
   
   **优点**：
   - [主要优点 1]
   - [主要优点 2]
   - [主要优点 3]
   
   **影响力**：[总体效果评估]
   
   ## 结构与行文衔接
   - [对内容组织的评价]
   - [过渡质量]
   - [节奏评估]
   
   ## 内容质量
   - [论点力度]
   - [证据充分程度]
   - [示例有效性]
   
   ## 技术质量
   - 语法和语言规范：[评估]
   - 一致性：[评估]
   - 引文：[完整性检查]
   
   ## 可读性
   - 清晰度评分：[评价]
   - 句式多样性：[评价]
   - 段落长度：[评价]
   
   ## 最终润色建议
   
   1. **引言**：[具体改进]
   2. **正文**：[具体改进]
   3. **结论**：[具体改进]
   4. **标题**：[需要时提供选项]
   
   ## 发布前检查清单
   - [ ] 所有论断均有来源
   - [ ] 引文格式正确
   - [ ] 示例清晰
   - [ ] 过渡流畅
   - [ ] 包含行动号召
   - [ ] 已校对拼写错误
   
   可以发布了！🚀
   ```

## 示例

### 示例 1：Teresa Torres 的工作流程

**用户**：“我正在撰写一篇关于持续探索的文章。请帮我创建大纲。”

**过程**：
1. 协作制定大纲结构
2. 确定研究需求
3. 用户开始撰写引言
4. 审阅并改进开篇
5. 用户撰写各个章节
6. 在每个章节完成后提供反馈
7. 开展研究并添加引用
8. 对完整草稿进行最终审阅
9. 润色并为发布做好准备

**结果**：一篇研究充分、引用规范、以 Teresa 的个人声音写成，并且结构清晰、行文流畅的文章。

### 示例 2：研究密集型文章

**用户**：“我正在撰写 AI 对产品管理影响的文章。请帮我查找最新数据和示例。”

**输出**：
```markdown
## 汇总的研究资料

### 最新数据
- Gartner：到 2025 年，80% 的产品经理将使用 AI 工具 [1]
- 调查：45% 的受访者表示功能发布速度加快 [2]
- 案例研究：Airbnb 的 AI 辅助优先级排序 [3]

### 专家引言
- “AI 放大产品经理的判断力，而非取代它”——Marty Cagan
- [附有引用的其他引言]

### 真实示例
1. **公司 A**：使用 AI 综合分析用户研究
   - 结果：节省 60% 的时间
   - 来源：[引用]

2. **公司 B**：由 AI 驱动的路线图分析
   - 结果：改善利益相关者之间的一致性
   - 来源：[引用]

所有内容均已添加到你的大纲中，并配有规范引用。
```

### 示例 3：改进开篇

**用户的原始开篇**：
> “产品管理正在因 AI 而发生变化。在本文中，我将讨论 AI 影响产品经理的一些方式。”

**改进方案**：

**方案 1（数据驱动）**：
> “上个月，我让 AI 分析了 500 次客户访谈。原本需要 3 周的工作，它只用了 30 分钟。产品管理将从此彻底改变。”

**方案 2（提问）**：
> “如果你能在早晨喝完咖啡之前，与每位客户交流、阅读每条评论，并分析每张支持工单，会怎样？”

**方案 3（故事）**：
> “Sarah 花了两周时间构建了错误的功能。并不是因为她不了解用户，而是因为她无法足够快地处理数百次访谈，从中发现规律。”

### 示例 4：章节反馈

**用户**：“刚写完我的‘常见错误’一节。你有什么看法？”

**回复**：
```markdown
# 反馈：常见错误一节

## 表现出色之处 ✓
- 示例有力（Slack 通知的故事）
- 结构清晰（3 个错误，布局简洁）
- 针对每个错误都提供了实用建议

## 建议

### 使内容更加具体
你的第二点写的是“糟糕的优先级排序”，但可以表达得更有力：

当前版本：
> “许多团队的优先级排序很糟糕，因为他们关注的是功能而非成果。”

建议版本：
> “我见过一些团队在一个季度内发布 14 项功能，却没有推动任何关键指标。他们把活动量置于实际进展之上。”

### 添加数据
第三个错误如果有证据支持会更有说服力：
> “[添加引用]：研究显示，未定期接触用户的团队构建无人使用功能的可能性高出 3 倍 [需要来源]”

### 改进行文衔接
考虑重新排序：错误 3 → 错误 2 → 错误 1
这样可以按照影响从小到大的顺序展开。

可以继续下一节了！
```

## 写作工作流程

### 博客文章工作流程
1. 共同拟定大纲
2. 研究关键要点
3. 撰写引言 → 获取反馈
4. 撰写正文各节 → 逐节获取反馈
5. 撰写结论 → 最终审阅
6. 润色和编辑

### 新闻简报工作流程
1. 讨论开篇构思
2. 快速拟定大纲（篇幅较短）
3. 一次完成草稿
4. 审阅清晰度和链接
5. 快速润色

### 技术教程工作流程
1. 列出步骤
2. 编写代码示例
3. 添加说明
4. 测试操作指令
5. 添加故障排除章节
6. 最终审阅准确性

### 思想领导力文章工作流程
1. 集思广益，寻找独特角度
2. 研究现有观点
3. 形成你的核心论点
4. 以鲜明观点进行写作
5. 添加支持性证据
6. 打造有说服力的结论

## 专业技巧

1. **在 VS Code 中工作**：长篇写作体验优于网页版 Claude
2. **每次处理一个章节**：逐步获取反馈
3. **单独保存研究资料**：维护一个 research.md 文件
4. **为草稿保留版本**：article-v1.md、article-v2.md 等
5. **大声朗读**：利用反馈找出不流畅的句子
6. **设定截止时间**：“我想今天完成草稿”
7. **适当休息**：写作、获取反馈、暂停、修改

## 文件组织

推荐的写作项目结构：

```
~/writing/article-name/
├── outline.md          # 你的大纲
├── research.md         # 所有研究资料和引用
├── draft-v1.md         # 初稿
├── draft-v2.md         # 修订稿
├── final.md            # 可供发布的版本
├── feedback.md         # 汇总的反馈
└── sources/            # 参考资料
    ├── study1.pdf
    └── article2.md
```

## 最佳实践

### 研究方面
- 引用前核实来源
- 尽可能使用最新数据
- 平衡不同观点
- 链接至原始来源

### 反馈方面
- 明确说明你想了解什么：“这是否过于技术化？”
- 分享你的顾虑：“我担心这一节太拖沓”
- 提出问题：“这里的逻辑是否连贯？”
- 请求替代方案：“还有什么方式可以解释这一点？”

### 个人声音方面
- 分享你的写作示例
- 明确语气偏好
- 指出风格匹配之处：“这听起来像我写的！”
- 指出风格不匹配之处：“对我的风格来说太正式了”
